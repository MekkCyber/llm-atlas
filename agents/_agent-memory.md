# Agent Memory

*Taxonomy — long-horizon memory systems for conversational and tool-using agents.*

**TL;DR:** Agent memory is how a long-running agent keeps relevant information from earlier turns available at later turns, when the raw history no longer fits in context. The design space splits by **what gets stored** (raw utterances, extracted entities, summaries, parametric state) and **what gets retrieved** (top-$k$ passages, graph walks, no retrieval at all). The simplest end — [raw-rag](raw-rag.md) — turns out to be hard to beat.

**Related taxonomies:** none yet.
**Depth files covered here:** [raw-rag](raw-rag.md)

---

## The problem

An agent that lives across many turns or many tool calls accumulates a conversation / trace too long for the context window. Something must bridge the past to the present. The naive answer — "put all of it in context" — fails on cost and attention-dilution. Everything else is a *lossy compression* of the past, and the open question is **what to drop**.

Compression goes wrong in two directions:

- **Over-compress** (summarize aggressively, extract only entities): coverage drops; downstream LM can't recover.
- **Under-compress** (append everything, cheap retrieval): irrelevant evidence crowds out signal; context budget runs out.

Every memory system is a point on this coverage-vs-density frontier.

---

## The shared pattern

```
    long history ──► WRITER ──► memory store
                                   │
    current turn ──► READER ──► retrieved snippets ──► LM prompt
```

Variants differ in the **writer** (what transformation history undergoes before storage) and the **reader** (how retrieval is done). The writer is where coverage is lost; the reader is where ranking happens.

---

## Variants

| Technique | Writer (store) | Reader (retrieve) | Main tradeoff | When it wins |
| --- | --- | --- | --- | --- |
| [**raw-rag**](raw-rag.md) (Shen et al. 2026) | None — raw utterances append-only | Dense retriever + cross-encoder reranker | Index grows unboundedly | Default baseline; coverage-first tasks |
| **Episodic summarization** — *no depth file yet* | Per-session summary generated by an LM | Retrieve summaries, optionally expand | Loses detail at the summary boundary | Diary-style memory, long gaps between sessions |
| **Entity-graph memory** — *no depth file yet* | Extract entities + relations, store in a graph | Graph walks or path queries | Needs reliable extraction | Tasks where relations between entities dominate |
| **Mutating memory** — *no depth file yet* | LM rewrites existing memory to incorporate new information | Retrieve from current (mutated) state | Mutations are irreversible errors | When memory should reflect "latest truth" (preferences, state) |
| **Parametric memory** ([parametric-memory](../inference/parametric-memory.md)) | Train a predictor that encodes chunks into memory tokens | None — memory lives in hidden states at inference | Needs per-corpus training | Fixed corpora, retrieval latency sensitive |

---

## How to choose

**Default for 2026+:** start with raw-rag and only add compression layers that pass an ablation. The paper that introduced raw-rag found it beats compression-based systems on 6/7 benchmark-model combinations by preserving coverage.

**Prefer episodic or graph memory when:** the task requires reasoning over relations between entities mentioned across many turns, and extraction quality is reliable in the target domain.

**Prefer parametric memory when:** the corpus is fixed, retrieval latency is tight, and you can afford to retrain the memory predictor on corpus changes.

**Avoid mutating memory unless:** you have a mechanism to detect and roll back mutation errors — bad rewrites compound.

## Adjacent but distinct

- **KV-cache compression** — attacks the long-context cost of a *single* forward pass, not the cross-session memory problem. Composable with any entry here.
- **Fine-tuning** — permanently incorporates knowledge into weights. Different operation (training-time, not inference-time), and the knowledge is amortized across all users rather than per-conversation.
- **RAG over external documents** — same mechanisms as agent memory but the corpus is external knowledge, not conversation history. Memory stores *earlier state of this agent's own conversation*.
