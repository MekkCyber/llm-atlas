# Agent memory (state-centric)
*Depth — one specific technique, grounded in its source paper(s).*

**TL;DR:** Fact-centric agent memory ("Alice's birthday is March 14") can't tell you whether a fact is still valid, how it relates to other facts, or when to invoke it for a given request. State-centric memory augments persistent facts with *Relational States* (how facts relate and age over time) and a per-request *Reasoning State* generated by an RL-trained policy. Introduced in EvoMemState (2611.03743).

**Prereqs:** [grpo](../post-training/grpo.md)
**Related:** [rlvr](../post-training/rlvr.md)

## What it is

A memory architecture for personal agents with three layers:
- **Persistent Facts** — the usual extracted claims about the user (plain key-value or triple store).
- **Relational States** — per-fact and pairwise metadata: validity window, scope, conflicts-with, supersedes, depends-on, confidence over time.
- **Reasoning State** — a request-conditional view that specifies which facts to invoke, in what role (evidence vs. constraint vs. background), and at what priority.

The Reasoning State is generated at query time by a *policy* $\pi_\phi$ trained with RL on memory-use trajectories.

## How it works

Three-stage pipeline:

1. **Ontology-Guided Memory State Induction.** From a conversation stream, extract persistent facts (standard IE) and build the Relational State graph — explicit edges for validity ("expires on", "supersedes"), scope ("applies when", "only in context"), and relation to other facts.

2. **RL-Based State Evolution.** Train $\pi_\phi$ with RL:
   - Observation: user request + relevant subgraph of facts + relational edges.
   - Action: emit a Reasoning State (which facts to use, their roles, their priorities).
   - Reward: downstream response quality against a held-out reference (correctness + memory-grounding).
   
   The policy internalizes patterns like "if request is a reminder, prioritize time-bound facts," "if facts conflict, prefer the more recent and flag the conflict."

3. **State-Aware Reasoning.** The reasoner LLM takes (facts + Relational States + Reasoning State) and generates the response.

## Why it matters

- **Memory becomes graph-aware, not bag-aware.** Conflict detection, validity, and precedence are first-class.
- **Usage-side RL.** The *how-to-use-memory* step is trainable, not a hand-written heuristic — the system improves with experience.
- **Compatible with existing stores.** Persistent Facts can be sourced from any fact-extraction pipeline; the novel contribution is the state overlay.

Reported gains: consistent improvements over existing memory systems on long-term dialogue and memory-use benchmarks in both retrieval completeness and memory-grounded response accuracy.

## Gotchas & tricks

- **Reward design is the hard part.** Pure correctness rewards don't teach the policy to use *relational* information — need rewards that penalize invoking stale facts.
- The Relational State graph grows super-linearly with facts; needs pruning rules (confidence decay, scope expiry) to stay tractable.
- Conflicts between facts are detected at induction time *and* at reasoning time — detecting them once isn't enough because new facts can retroactively conflict with old ones.
