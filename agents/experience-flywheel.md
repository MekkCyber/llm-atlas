# Experience Flywheel
*Depth — a system that manufactures executable, verifiable agent tasks at scale by jointly scaling intents, environments, and verifiers.*

**TL;DR:** Agent-training data is bottlenecked not by model rollouts but by the **supply of executable, verifiable tasks** that models can roll out against. An Experience Flywheel (NorthCUA, 2026) solves this by scaling three things in lockstep: **intents** (enumerated from the environment's own capabilities), **environments** (built or reconstructed to host those intents), and **verifiers** (co-evolved with the task so completion is machinely checkable). The Flywheel's output is a growing library of tasks with known initial states and checkable end states — the raw material for SFT and RL.

## What it is

Agent-training experience has three parts:
- **A task** — a natural-language goal.
- **An environment** — a sandbox (OS, browser, app) where the task runs.
- **A verifier** — a check on the final (or intermediate) state that says "done" or "not done."

Hand-written tasks don't scale, and tasks without verifiers can't be used for RL. The Flywheel generates all three *together* so that every produced task is executable (environment exists, is reachable) and checkable (verifier has been authored and tested).

## How it works

Three coupled "scaling" axes, each a production pipeline:

1. **Scaling Intents.**
   - Rather than asking humans "what would users do," enumerate the *capabilities* of the installed software: menu items, keyboard shortcuts, API endpoints, file types, URLs reachable from the local browser state.
   - Combine capabilities into intents using small LLMs: "open X, modify Y, save as Z," "search for X on site Y and compare with Z."
   - The resulting intent set covers what the environment *supports* — a much larger surface than hand-curated task lists.

2. **Scaling Environments.**
   - For OS intents, prepare workspace snapshots with required files, installed apps, and starting state.
   - For web intents, reconstruct the target website as a **replayable mirror** — a fixed snapshot the agent can interact with the same way it would the live site, with no risk of real-world side effects or network flakiness.
   - Mirror construction uses crawling plus local hosting; stateful sites may need request replay or a stubbed backend.

3. **Scaling Verifiers.**
   - Co-author the verifier at the same time as the task. For file-modification tasks: a diff/check script. For retrieval tasks: a regex or semantic-match on the final rendered text. For workflow tasks: a state-equality check at the end of the sequence.
   - The verifier is executed against *known-good* reference trajectories (either hand-made or generated by a frontier model) before the task enters the pool, so false negatives don't pollute training.

Grounding data (how UI elements map to pixels / DOM) is a parallel pipeline: OmniParser-style screen parsing, plus documentation retrieval for specialized apps where the visuals aren't self-explanatory.

## Why it matters

- **Scales the real bottleneck.** The scarce resource isn't compute for rollouts — it's tasks with verifiable outcomes. The Flywheel decouples task supply from human authoring.
- **Keeps training data in-distribution with the environment.** Enumerating capabilities ensures tasks are about things the environment *can actually do*, so trajectories don't fail for reasons unrelated to the agent.
- **Composable.** The same Flywheel produces tasks for mid-training (broad capability exposure), SFT (long complete workflows), and RL (narrow, outcome-varying tasks).
- **Pattern-level transferable.** The three-axis decomposition (intents × environments × verifiers) applies to any agent domain — coding, scientific workflows, data analysis.

## Gotchas & tricks

- **Verifier coverage gap.** A task whose verifier is weak will generate noise during RL. Spot-check verifiers against negative examples (plausibly wrong trajectories that should fail).
- **Capability-space blowup.** The combinatorial intent surface grows fast; filter for intents a judge thinks are plausibly user-like, or you drown in "double-click the top-left corner then press Escape."
- **Replay-mirror drift.** Web mirrors are snapshots; sites that were mirrored months ago may not match the live site's layout. Regenerate periodically.
- **Reference trajectories still needed.** A task with a verifier but no known-good trajectory can't be filtered for false negatives. Allocate frontier-model budget to generate references for new tasks.
