# GUI Agent RL (Mock-Env Online Training)
*Depth — training GUI agents online in auto-synthesized mock apps.*

**TL;DR:** Real GUIs are stateful, slow, and hard to reset — bad fit for online RL. MAI-Gym's recipe is to auto-synthesize *resettable mock apps* with verified tasks, run online RL across 20K parallel environments, and transfer to real mobile/desktop/web GUIs. Reported: 48.1% success on a real train-ticket phone app after training only on a mock version (vs. 28.8% without mock training).

## What it is

A sim-to-real approach for GUI agents. The "sim" is a bank of mock apps generated by an LLM pipeline — small, resettable, instrumented to verify task success. The "real" is production mobile/desktop/web GUIs the agent sees after training.

## How it works

1. **Mock-app synthesis.** For each target app or domain, generate a mock implementation (HTML/JS or similar) with a verifier that checks whether a task's intended end-state is reached. Scale to 2K+ apps.
2. **Parallel rollouts.** Spin up ~20K parallel environments (mock apps + browsers / emulators). Rollouts are cheap because reset is cheap.
3. **Online RL.** Use a critic-free policy-gradient method (GRPO-family) with the verifier as reward.
4. **Cross-env mixing.** Train the agent across mobile, desktop, and web mocks simultaneously so the policy generalizes to interface types, not just one layout.
5. Deploy on real apps; the mock-trained policy transfers via the shared action vocabulary (click/scroll/type) and visual tokenizer.

## Why it matters

Classical GUI RL stalled because real apps are slow and non-resettable; demos used recorded trajectories (offline). Mock synthesis + online RL puts GUI agents back on the standard RLVR train. The real-app transfer number is the one to watch — if mock-only policies keep generalizing, the data problem is largely synthetic.

## Gotchas & tricks

- Mock apps must be faithful enough that policies learn transferable skills, not mock-specific tricks (shortcut buttons, impossible states). The synthesis pipeline is the critical design surface.
- 20K parallel environments is a systems problem — rollout infrastructure, not RL math, is often the bottleneck.
- Verifier gaming is possible: an LLM-generated verifier can be too lax; keep a held-out human-verified subset to catch drift.
