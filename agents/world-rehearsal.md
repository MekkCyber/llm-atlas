# World Rehearsal

*Depth — jointly train an LLM agent as both actor and environment inside a single autoregressive rollout, so RL no longer needs an executable environment.*

**TL;DR:** Agentic RL is bottlenecked by *environments*: real ones cost engineering, simulators drift from reality, and every new domain needs its own harness. World rehearsal (introduced by EnvACE, 2026) sidesteps this by letting the policy play both roles inside one rollout: emit a tool call, then predict the environment's response to it, then continue conditioned on the rehearsed response. Both roles are jointly optimized against the same task-success reward. The trained policy carries an internalized world model that supports test-time "private rehearsal" before real execution.

## What it is

A single-rollout interleaving of **acting** and **rehearsing** during RL:

```
[user query]
 ↳ ACT     : tool_call_1
 ↳ REHEARSE: <predicted response_1>
 ↳ ACT     : tool_call_2
 ↳ REHEARSE: <predicted response_2>
 ...
 ↳ final answer
```

Both `ACT` tokens and `REHEARSE` tokens are generated by the same policy in the same forward pass and both receive gradient from the outcome reward. There is *no* call to a real environment during training.

At inference the policy can either (a) execute for real without any rehearsal, or (b) "privately rehearse" the next action before committing — a test-time compute lever that costs generation tokens but no external calls.

---

## How it works

1. **Rollout schema.** Fix a delimiter convention that separates action turns from response turns. The generator produces both.
2. **Reward.** Task-success reward `R ∈ {0,1}` at end of rollout. Standard GRPO/PPO surrogate. The reward is broadcast (via the policy loss) to *all* tokens in the rollout — both action and rehearsed-response tokens.
3. **What the policy learns.** Two coupled skills: (a) picking useful tool calls, and (b) predicting the environment response those calls induce. Because both are optimized end-to-end against the same reward, response prediction is shaped toward "responses that lead to a correct final answer if I trust them," which coincides with real environment behavior when trajectories are correct.
4. **Test-time private rehearsal.** After training, at inference the policy can generate a candidate action, rehearse its response, and only if the rehearsal looks bad revise the action before committing. Modest budget → meaningful additional wins on the same benchmarks.

## Why it matters

- **Unblocks scale.** Environment count is the current ceiling on agentic RL. World rehearsal turns environment quantity into a modeling capacity problem inside the LLM.
- **Removes simulator drift.** No external simulator means no simulator-vs-real gap for the RL to overfit to.
- **Test-time lever.** Private rehearsal is a per-request compute knob that trades tokens for reliability without extra tool calls — attractive when tools are rate-limited, expensive, or side-effecting.
- **Composable with credit assignment.** The scheme leaves the policy loss shape intact, so schemes like recursive credit assignment or GRPO variants drop in.

## Gotchas & tricks

- **Rehearsal collapse.** If the rehearsed response tokens have too much freedom, the policy can hallucinate a response confirming any action, and reward flows through anyway. Anchor the rehearsal — e.g., seed it with a small held-out set of real environment traces early in training, or add a KL toward a rehearsal-specific reference model.
- **Only works on environments the LLM can plausibly model.** Great for tool-augmented QA (BFCL, τ²-Bench, VitaBench, FinMCP-Bench). Weaker for environments with hidden physical dynamics or genuinely unknown state.
- **Trajectory length blows up.** A rollout now interleaves both roles, roughly doubling sequence length. Budget context accordingly; the paper reports the trade is worth it.
- **Private-rehearsal budget saturates.** Test-time gains from rehearsing before executing plateau after a moderate budget — don't spend unbounded rehearsal compute at inference.
