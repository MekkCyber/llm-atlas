# Case Study: Qwen-Audio-3.1-ASR

*Alibaba's audio-language model family extended beyond pure ASR into speaker-diarized transcription and general audio understanding (captioning, temporal grounding, sound event detection, audio QA, audio reasoning). The interesting story is not architectural novelty — it's a six-stage training pipeline (encoder SSL → audio-LLM pretrain → cooldown → SFT → GRPO → multi-teacher on-policy distillation) that lets one model lineage span async-file / streaming / interactive / non-streaming deployment and five task surfaces (ASR, SD, AU, hotwords, polishing).*

## What this is

**Qwen-Audio-3.1-ASR**, released October 2026 by Alibaba / Qwen Team. arXiv 2610.28711. A family of audio-language models whose core is a Mixture-of-Experts LLM decoder initialized from Qwen3 and an audio encoder operating at 12.5 Hz. The family covers 30 languages and 16 Chinese dialects.

The paper's core claim: one model lineage covers the full audio-task surface — transcription (ASR), speaker-diarized transcription (SD), and general audio understanding (AU) — plus the operational variants required for production (async file, low-latency streaming, interactive voice, non-streaming). The recipe rests on four pillars:

1. **Encoder pretraining via BEST-RQ SSL** on unlabeled speech, then supervised AED pseudo-labeling (Paraformer-V2, Whisper-large-v3, SenseVoice).
2. **Audio-LLM pretraining** on ~20M hours of ASR-heavy data with the MoE decoder, interleaved text-audio data, frozen encoder.
3. **Comprehensive post-training**: SFT with LoRA → GRPO (via **FunVerl**, an async RL framework) → **MOPD** (multi-teacher on-policy distillation with task-routed teachers and k3 reverse-KL).
4. **Instruction-controlled task multiplexing**: historical-context conditioning, hierarchical hotword customization (P0 critical / P1 soft), native transcription polishing.

Unlike Qwen2.5 which is a dense + MoE text model family, Qwen-Audio-3.1-ASR is a *task-multiplexed* audio family — same backbone, different variant for different latency/task profiles.

## Architecture at a glance

```
Three core blocks:
  Audio encoder  → Audio adapter → LLM decoder (MoE, init from Qwen3)
  Auxiliary CTC branch → preliminary hypotheses for hotwords and context

Encoder:
  - Operates at 12.5 Hz output frame rate
  - Non-streaming variant: bidirectional attention
  - Some Transformer layers initialized from a Qwen3 LLM
  - Pretrained via BEST-RQ SSL on unlabeled speech, then supervised AED

Decoder:
  - MoE backbone initialized from Qwen's LLM
  - No vision components (text + audio only)

Variants (Table 1 in the report):
  Flash-Filetrans   async file ASR + context + hotwords
  Flash-Streaming   real-time ASR + context + hotwords
  Flash-Message     interactive voice ASR + context + hotwords + polishing
  Flash             non-streaming ASR + speaker diarization
  Next              non-streaming ASR + SD + general audio understanding
```

**Exact parameter counts are not disclosed** — the report uses only the "Flash" / "Next" names.

### Speaker-diarized ASR output format

Structured output: `[SPK|start-end]text`. Speaker labels are recording-local (consistent across turns within one audio); times are in seconds; overlapping intervals are allowed. Timestamps are quantized to an **80 ms grid** matching the encoder frame rate — the paper reports faster convergence and better DER/cpWER vs. 1 ms targets. Speaker-ID tokens are **10× weighted** in the SFT cross-entropy loss.

## Training pipeline (six stages)

### Stage 1: Encoder pretraining
- **BEST-RQ self-supervised learning** on unlabeled speech.
- **Supervised AED** on labeled Chinese and English. Pseudo-labels generated by Paraformer-V2, Whisper-large-v3, and SenseVoice ensembles.

### Stage 2: Audio-LLM pretraining
- **~20M hours** of training data, mostly ASR with interleaved text-audio.
- **Encoder frozen**, adapter and decoder trained.

### Stage 3: Cooldown
- **~1M hours** of higher-quality data.
- Language and dialect **rebalancing**.
- WER-based filtering: samples with WER > 0.3 against a VibeVoice reference are removed.

### Stage 4: SFT
- **LoRA on the LLM**; encoder and adapter updated with full gradients.
- Data streams:
  - Multilingual / dialect / code-switching speech.
  - **CosyVoice3 TTS augmentation** for domain-entity coverage.
  - Native transcription polishing targets.
  - Historical-context conditioning (dialogue-level consistency).
  - **Hierarchical hotwords**: P0 (critical, strict adherence) vs. P1 (soft bias).

### Stage 5: RL via GRPO
- Trained within **FunVerl**, an asynchronous RL framework built on verl: Megatron for training, vLLM for rollouts.
- Reward composition:
  - Accuracy: `1 - WER`.
  - Keyword precision and recall.
  - **Hotword reward**: P0/P1 with asymmetric weighting (P0 heavier).
  - Context reward (consistency across history).
  - Hallucination suppression.
- For SD, rewards combine **DER, cpWER, and tcpWER** (time-constrained cpWER).

### Stage 6: Multi-teacher on-policy distillation (MOPD)
- **k3 reverse-KL** distillation objective.
- **Task-routed teachers**: separate teachers for ASR, SD, AU, and text/dialogue (Qwen3.5 for text).
- On-policy: distilled against the student's own rollouts, not static teacher outputs.
- Covered in [multi-teacher-on-policy-distillation.md](./../post-training/multi-teacher-on-policy-distillation.md).

## Key results (reported)

**ASR (benchmarks)**: AISHELL-1, AISHELL-2, FLEURS, LibriSpeech, WeNetSpeech, GigaSpeechBench, Common Voice 15, KeSpeech, WSYue.

- **GigaSpeechBench** (7 East/Southeast Asian languages) macro error: **15.09%** (Next) vs. 22.50% (Qwen-Audio-3.0-ASR).
- **Internal dialect ASR** (16 Chinese dialects) macro CER: **10.38%** (Next).

**Speaker-diarized ASR**: AISHELL-4, AliMeeting-test, MLC-SLM, MagicData-RAMC.

- **AliMeeting-test** cpWER: **12.04%** (Next) vs. 15.78% (Qwen-Audio-3.1-ASR non-Next). SD eval used ~4-minute chunks.

**Audio understanding**: MMAU, MMSU, CochlScene, Nonspeech7k, MELD, NSynth, DiDiSpeech.

- **MMAU** 81.60%, **MMSU** 82.24% (Next).

**Temporal grounding**: Clotho-Moment, DESED.

- **Clotho-Moment** 82.20% mIoU; **DESED** 66.60% mIoU.

**Streaming latency**: Message ASR first-character latency **100 ms** vs. 570 ms for Doubao Streaming ASR 2.0 (self-reported, 10 concurrent streams).

## Why this report matters

- **Audio catches up.** A single instruction-controlled audio foundation model that covers diarization *and* captioning *and* temporal grounding *and* audio QA has not previously been released at this scope by any lab.
- **MoE decoder + Qwen3 init.** The paper is the first external evidence of an MoE Qwen-family model used as an audio-LLM decoder. Vision components are not reused — this is a focused audio stack.
- **Operational variants.** The streaming/non-streaming/interactive variants show up as separate training targets, not post-hoc adapters. The report is explicit that each variant is trained for its deployment profile.
- **FunVerl + MOPD.** The RL and distillation stages are two independently reusable ideas (async RL on verl/Megatron/vLLM; task-routed multi-teacher on-policy distillation) that likely transfer beyond audio.
