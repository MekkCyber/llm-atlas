## 1. Code2LoRA

**Authors:** Liliana Hotsko, Yinxi Li, Yuntian Deng, Pengyu Nie — *University of Waterloo*
**Links:** [arXiv:2606.06492](https://arxiv.org/abs/2606.06492) · [HF](https://huggingface.co/papers/2606.06492) · [AlphaXiv](https://www.alphaxiv.org/abs/2606.06492)
**Topics:** `LoRA`, `fine-tuning`, `code`

### TL;DR

A hypernetwork generates a *repository-specific* LoRA adapter from a code repo (or a stream of code diffs), so the model "knows" the repo at inference time without dragging long retrieved context through every call. Two modes: Static (one adapter per snapshot) and Evo (a GRU updates the adapter's latent state per commit).

### Key idea

Replace either RAG (long input tokens) or per-repo fine-tuning (training cost) with a learned mapping `repo → LoRA weights`. The hypernetwork sees repo contents (Static) or a GRU hidden state that absorbs each diff (Evo) and emits low-rank update matrices. Inference cost equals the base model — zero extra tokens.

### Main finding

On RepoPeftBench (604 Python repos): Static reaches 63.8% cross-repo / 66.2% in-repo exact match, matching a per-repo LoRA upper bound. Evo reaches 60.3% cross-repo, **+5.2 pp** over a single shared LoRA on the evolution track (87K commit-derived test tasks).

### Why it matters

Hypernetwork-generated adapters revive a long-dormant idea (HyperNetworks, 2017) at a moment when **(a)** every coding agent eats long retrieved context, and **(b)** repos evolve faster than per-repo fine-tunes can land. If this generalizes beyond code (docs, customer KBs, per-tenant deployments), it's a serious alternative to RAG.

## 2. RL Elicits Contextual Translation

**Authors:** Hanxu Hu, Zdeněk Šnajdr, Pinzhen Chen, Jannis Vamvas, Rico Sennrich — *U. Zurich / ETH Zurich / Queen's U. Belfast*
**Links:** [arXiv:2606.06428](https://arxiv.org/abs/2606.06428) · [HF](https://huggingface.co/papers/2606.06428) · [AlphaXiv](https://www.alphaxiv.org/abs/2606.06428)
**Topics:** `RL`, `RLVR`, `in-context learning`

### TL;DR

Outcome-based RL (RLVR with a chrF reward) on prompts that contain *linguistic context* (grammar snippets, parallel pairs) teaches the model the meta-skill of *using* in-context language information. Result: stronger zero-shot transfer to fully unseen languages than ICL or SFT.

### Key idea

Frame unseen-language translation not as "memorize this language" but as "learn to extract grammar from context." Use chrF (a cheap surface metric) as a verifiable reward and roll out under prompts that include grammar / parallel-sentence context. The RL signal pushes the policy to actually condition on the provided linguistic material.

### Main finding

RL-trained models out-translate ICL and SFT baselines on completely unseen languages. Authors argue this is the first demonstration that outcome-based RL extends beyond math/code into a meta-skill (using in-context grammar) — chrF is enough of a signal, no human preferences required.

### Why it matters

Widens the RLVR thesis: any task with a cheap *outcome* signal — not just math correctness — can train a *meta-skill*, not just point capability. If chrF works for translation, BLEU/ROUGE-like signals could plausibly train context-conditional behaviors in other domains.

## 3. Complexity-Balanced Diffusion Splitting

**Authors:** (incl. Noam Issachar) — *Affiliations not shown*
**Links:** [arXiv:2606.06477](https://arxiv.org/abs/2606.06477) · [HF](https://huggingface.co/papers/2606.06477) · [AlphaXiv](https://www.alphaxiv.org/abs/2606.06477)
**Topics:** `diffusion`, `efficient-inference`

### TL;DR

Replace the monolithic diffusion backbone with multiple specialized sub-networks, each owning a slice of the noise-to-data timeline. Slice boundaries are chosen so each slice carries equal *approximation burden* (de Boor's equidistribution principle), so capacity is spent where the score field is hardest to fit.

### Key idea

A function-approximation-theory take on multi-stage / multi-expert diffusion: don't split timesteps uniformly, split so each segment's *integrated complexity* matches. Then assign capacity per segment proportionally. The whole timeline becomes a piecewise-specialist generator.

### Main finding

Abstract emphasizes the framework + theoretical grounding; concrete numbers depend on the full paper. The framing — "uniform capacity is provably wasteful on diffusion timelines" — is the key takeaway.

### Why it matters

Multi-expert / multi-stage diffusion has been a folklore trick (eDiff-I, MoE-DiT). CBS gives it a *principled* knob: capacity allocation by approximation difficulty. If the equidistribution criterion holds up empirically, it's a drop-in design rule for the whole DiT/video-DiT lineage.

## 4. LoomVideo

**Authors:** Jianzong Wu, Hao Lian, Jiongfan Yang, Dachao Hao, Ye Tian, Yunhai Tong, …, Hao Jiang — *Peking U. / Alibaba*
**Links:** [arXiv:2606.06042](https://arxiv.org/abs/2606.06042) · [HF](https://huggingface.co/papers/2606.06042) · [AlphaXiv](https://www.alphaxiv.org/abs/2606.06042)
**Topics:** `diffusion`, `video`, `multimodal`

### TL;DR

A 5B-parameter unified video generation+editing model that swaps the text encoder for an MLLM, injects MLLM features into the DiT via "Deepstack," and — crucially — does video editing by **adding** the clean source-video latent to the noised target latent (Scale-and-Add) instead of concatenating tokens. Token concat doubles seq length on DiTs (4× compute via self-attention); Scale-and-Add is zero-overhead.

### Key idea

Two architectural moves: **(1)** MLLM-as-text-encoder with Deepstack multi-layer feature injection into DiT; **(2)** Scale-and-Add conditioning — `noised_target + α · clean_source` — replaces token concatenation for editing, and a Negative Temporal RoPE handles multiple reference frames.

### Main finding

5B LoomVideo matches or beats 13B+ unified video models on standard benchmarks while running **≥5.41× faster** at inference. Especially strong on e-commerce / fashion generation. The Scale-and-Add trick is the unlock.

### Why it matters

A clean recipe for "smaller unified video model that doesn't pay the concatenation tax." If Scale-and-Add holds up across diffusion editing more broadly, it changes the cost curve for video DiTs — concat conditioning has been the default since SDEdit.

### Knowledge graph integration

## 5. PropMe

**Authors:** Gianluca Barmina, Peter Schneider-Kamp, Lukas Galke — *U. Southern Denmark*
**Links:** [arXiv:2606.06286](https://arxiv.org/abs/2606.06286) · [HF](https://huggingface.co/papers/2606.06286) · [AlphaXiv](https://www.alphaxiv.org/abs/2606.06286)
**Topics:** `safety`, `memorization`, `eval`

### TL;DR

Most memorization eval is *capability*: "can the model be forced to spit out training data?" PropMe adds *propensity*: "does it do so under ordinary use?" The gap matters because legal/policy claims about memorization should plausibly track propensity, not just worst-case extraction.

### Key idea

Contrast adversarial prefix-completion attacks (capability) against non-adversarial natural prompts (propensity) over the same suspected training strings, on the same models. Report both; the disagreement is the real signal.

### Main finding

Across evaluated LLMs: yes, training data can be extracted under adversarial prefixing — but verbatim leakage under non-adversarial use is rare. The capability/propensity gap is large and model-dependent.

### Why it matters

Reframes the memorization conversation: a model that *can* leak isn't the same as a model that *will* leak in deployment. Better aligned with real privacy/copyright threat models, and a more legible measurement axis for releases.

## 6. OPRD

**Authors:** Shenzhi Yang, Guangcheng Zhu, Bowen Song, Haobo Wang, Mingxuan Xia, Xing Zheng, Yingfan Ma, Zhongqi Chen, Weiqiang Wang, Gang Chen — *Zhejiang U. / Ant Group*
**Links:** [arXiv:2606.06021](https://arxiv.org/abs/2606.06021) · [HF](https://huggingface.co/papers/2606.06021) · [AlphaXiv](https://www.alphaxiv.org/abs/2606.06021)
**Topics:** `distillation`, `post-training`, `RL`

### TL;DR

On-policy distillation usually matches student-teacher log-probs at the LM-head output. OPRD argues that's wasteful: late in training, sampling variance dominates, and the LM head compresses information. Instead, match teacher and student **hidden states** at selected layers on the same on-policy rollouts.

### Key idea

Take the on-policy rollouts the student is already producing, run the teacher in parallel, and minimize a representation-matching loss between teacher and student hidden states at chosen layers. Bypassing the LM head removes head-induced variance and exposes structural signal that token-prob KL throws away.

### Main finding

On three math benchmarks: closes the student-teacher gap relative to output-space on-policy distillation while training **1.44× faster** and using **54% less memory**. Theoretical claim: zero sampling variance from the supervision side.

### Why it matters

On-policy distillation is the workhorse of modern reasoning post-training (DeepSeek-R1 family, Qwen, etc.). Moving the supervision from output to representations is a structural improvement, not just a tweak — and the memory win comes for free because you don't materialize per-token log-prob matrices.

## 7. NF-CoT (Latent Reasoning with Normalizing Flows)

**Authors:** Xiangjun Fu, Suhao Yu, Yao Tang, Haoqiang Kang, Lianhui Qin, Yizhe Zhang, Jiatao Gu — *U. Pennsylvania / UC San Diego / Meta*
**Links:** [arXiv:2606.06447](https://arxiv.org/abs/2606.06447) · [HF](https://huggingface.co/papers/2606.06447) · [AlphaXiv](https://www.alphaxiv.org/abs/2606.06447)
**Topics:** `reasoning`, `latent-CoT`, `efficient-inference`

### TL;DR

Latent CoT methods usually give up niceties of autoregressive LMs: KV cache, tractable likelihoods, left-to-right sampling. NF-CoT runs a TARFlow-style normalizing flow *inside* the LM backbone, so continuous "thought" positions get exact likelihoods, KV-cache decoding, and policy-gradient compatibility — alongside regular text tokens emitted by the standard LM head.

### Key idea

Add a second output head — a normalizing flow ("NF head") — that emits continuous latent thoughts at designated positions. Text positions still use the LM head. Both heads share the same causal stream and KV cache. Latent thoughts are distilled from explicit CoT, so the flow's target distribution is grounded.

### Main finding

On code-generation benchmarks: pass-rate improvements over both explicit-CoT and prior latent-reasoning baselines, with substantially **lower intermediate-reasoning cost** (fewer / cheaper thought tokens).

### Why it matters

The latent-CoT line (Coconut and successors) keeps stumbling on "you lose properties X, Y, Z." NF-CoT is the first credible answer that preserves all four (left-to-right gen, sampling, KV cache, tractable likelihood). If exact likelihoods on latent thoughts hold up, it opens the door to clean policy-gradient training in latent reasoning space.

## 8. The Shape of Addition

**Authors:** (Anonymous in HF extract; CN academic sponsorship: NSFC, 111 Center) — *Affiliations not shown on HF page*
**Links:** [arXiv:2606.03645](https://arxiv.org/abs/2606.03645) · [HF](https://huggingface.co/papers/2606.03645) · [AlphaXiv](https://www.alphaxiv.org/abs/2606.03645)
**Topics:** `interp`, `probing`, `reasoning`

### TL;DR

Probes the residual stream during multi-operand addition and finds an *Iso-Raw-Sum Trajectory* (IRST): representations split into semantic-digit anchors plus continuous "carry fibers." Arithmetic errors are geometric *slippages* — carries get pushed across quantization thresholds by neural noise. The framing yields a geometric consistency check that detects/corrects errors at inference.

### Key idea

Treat carry as a *continuous latent potential* moving along a 1D fiber, with each digit position acting as a quantization boundary. Errors happen when noise nudges the potential past a threshold. Lightweight linear probes can read off this potential — and disentangle hallucination from truth on the same activation vector ("probe versatility").

### Main finding

The geometric model predicts arithmetic-error structure and supports a consistency-check method that detects and corrects failed additions at inference time. Concrete probe / correction numbers from the abstract are qualitative; the framing itself is the contribution.

### Why it matters

Best recent example of *mechanistic* explanation for the famous "LLMs can't do arithmetic" symptom — and it's actionable: a probe-based inference-time corrector. Bridges interpretability and capability work.

## 9. ADR (Combinatorial Synthesis for Code RLVR)

**Authors:** Jiasheng Zheng, Boxi Cao, Boxi Yu, Yuzhong Zhang, Jialun Cao, Yaojie Lu, Hongyu Lin, Xianpei Han, Le Sun — *CAS / U. Limerick / CUHK-SZ / HKUST*
**Links:** [arXiv:2605.31058](https://arxiv.org/abs/2605.31058) · [HF](https://huggingface.co/papers/2605.31058) · [AlphaXiv](https://www.alphaxiv.org/abs/2605.31058)
**Topics:** `RLVR`, `data`, `code`

### TL;DR

Code RLVR runs out of *hard* verifiable tasks. ADR generates new ones by **decomposing** existing tasks into atomic elements (functions, constraints, test specs) and **recombining** them under controlled rules. Outputs are guaranteed-verifiable, more diverse, and *truly novel* compared to heuristic seed expansion.

### Key idea

Two stages: (1) Atomic Decomposition — break tasks into reusable atoms; (2) Controlled Recombination — assemble atoms under combinatorial constraints that preserve verifiability. The constraints govern difficulty and novelty.

### Main finding

ADR-synthesized tasks beat baseline seed-expansion synthesis on originality, difficulty, diversity, and test quality. Downstream: consistent code-ability gains across algorithmic programming, tool use, and data-science domains under RLVR training.

### Why it matters

RLVR's bottleneck is increasingly *data*, not *algorithm*. ADR is a principled answer to "how do you scale the prompt distribution for code RLVR past the long tail of curated seeds?" Plausibly extensible to math RLVR with the right atom set.

## 10. Experience Internalization

**Authors:** Jingwen Chen, Wenkai Yang, Shengda Fan, …, Yankai Lin — *Renmin U. / Beihang / Meituan*
**Links:** [arXiv:2606.04703](https://arxiv.org/abs/2606.04703) · [HF](https://huggingface.co/papers/2606.04703) · [AlphaXiv](https://www.alphaxiv.org/abs/2606.04703)
**Topics:** `agents`, `fine-tuning`, `distillation`

### TL;DR

"Self-evolving" LLM agents that internalize past experience into weights *collapse* after a few iterations, not compound. Paper isolates three design axes that determine stability: experience granularity (principle > instance), injection pattern (step-wise > global), regime (off-policy context-distillation from a teacher > on-policy).

### Key idea

Treat experience internalization as a recurring SFT step and ablate the three axes carefully. Findings: abstract *principles* survive multi-iteration training; *instances* contaminate; per-step injection aligns updates with intermediate decision states (matters for long-horizon tools); on-policy student-trajectory training reinforces flawed states.

### Main finding

The recommended recipe (principle-level + step-wise + off-policy context-distillation) yields stable multi-iteration improvement where the obvious recipe collapses. Code and data at `RUCBM/ExpInternalization`.

### Why it matters

Most "self-improving agent" pipelines silently degrade past iteration 2–3; this paper says *why* and gives a working recipe. Important for any RAG-then-distill or replay-buffer-driven agent training loop.

## 11. DataCOPE

**Authors:** Kangqi Song, Shengwei Tang, Shuofei Qiao, Lei Liang, Huajun Chen, Shumin Deng — *Affiliations not shown*
**Links:** [arXiv:2606.06416](https://arxiv.org/abs/2606.06416) · [HF](https://huggingface.co/papers/2606.06416) · [AlphaXiv](https://www.alphaxiv.org/abs/2606.06416)
**Topics:** `agents`, `eval`, `self-improvement`

### TL;DR

Unsupervised skill discovery for data-analysis agents: an agent explores, an unsupervised *verifier* (adaptive checklist for reports, self-consistency for QA) scores trajectories, and a skill manager contrastively distills the high-quality ones into reusable procedural skills injected at inference.

### Key idea

No labels, no ground truth. The verifier is task-shape-specific (checklist for open-ended reports, answer-agreement for closed QA) and produces relative-quality signals. Skill manager extracts contrasts between high- and low-verifier trajectories and stores them as inference-time skills.

### Main finding

Across two settings (Deep Data Research reports, DABStep reasoning) and four model backbones: **+9.71% (report)** and **+32.30% (reasoning)** mean improvement over baselines.

### Why it matters

Inference-time skill libraries are the lightweight alternative to weight-updating self-improvement. DataCOPE's contribution is the *verifier design* — and it shows that for data analysis specifically, you can bootstrap from pure exploration. Likely transferable to other "open-ended report + closed-form check" task families.

## 12. CLEAR / The Shadow Price of Reasoning

**Authors:** Speed Zhu, Jianwei Cai, Guang Chen, Ximing Huang, Wiggin Zhou, Mingyang Sun — *Affiliations not shown*
**Links:** [arXiv:2606.03092](https://arxiv.org/abs/2606.03092) · [HF](https://huggingface.co/papers/2606.03092) · [AlphaXiv](https://www.alphaxiv.org/abs/2606.03092)
**Topics:** `efficient-inference`, `reasoning`, `eval`

### TL;DR

Frame inference-time scaling under a *global* compute budget as a constrained-optimization problem. Per-query utility is modeled with a shifted-surge function. The optimal allocation has a closed-form shadow-price: marginal utility equalizes across queries. Translates into CLEAR — abandon hopeless queries, reallocate to ones near their emergence threshold.

### Key idea

Apply Lagrangian duality to inference budget allocation. The global shadow price tells you which queries to keep spending tokens on and which to drop. *Rational abandonment* is the key operational move — symmetric to "knowing when to stop" in test-time compute work, but derived from utility theory not heuristics.

### Main finding

In compute-scarce regimes, CLEAR's Pareto frontier (tokens vs. mean accuracy) dominates uniform allocation by up to **3×** on global accuracy. Holds across multiple reasoning task streams.

### Why it matters

Test-time scaling research mostly tunes per-query knobs (CoT length, samples). CLEAR is *global* — you spend on the queries that benefit most, drop ones below the threshold. As inference becomes the cost driver, "where to allocate the next 1000 tokens?" gets a principled answer.

## 13. ArcANE

**Authors:** Woojung Song, Nalim Kim, Sangjun Song, Chaewon Heo, Jongwon Lim, Yohan Jo — *Seoul National University*
**Links:** [arXiv:2606.05553](https://arxiv.org/abs/2606.05553) · [HF](https://huggingface.co/papers/2606.05553) · [AlphaXiv](https://www.alphaxiv.org/abs/2606.05553)
**Topics:** `agents`, `eval`

### TL;DR

Role-play eval has been static (does the character recall facts?). ArcANE asks the right question: do role-play agents *evolve psychologically along the right arc*? Auto-built benchmark over 17 novels, 80 characters. Conditioning on the character's arc beats every other context strategy.

### Key idea

Operationalize "staying in character" as alignment with a *psychological trajectory*, not factual consistency. Build the benchmark by extracting character arcs from novel text automatically; score model behavior against arc-aligned reference responses.

### Main finding

Across all tested models, arc-conditioned context outperforms persona prompts, summary context, etc. The static-recall version of the benchmark misses this entirely.

### Why it matters

A correct *measurement* shift, not a new method. Future role-play training will likely target arc fidelity directly, which changes data design.

**Topics:** `agents`, `eval`, `reasoning`

### TL;DR

Agents typically only act on the explicit user request and miss hidden, coexisting problems in the context. TIDE proposes *iterative discovery* (each round conditions on what's already been found, extending coverage) plus *thought templates* (reusable schemas distilled from solved cases that say what signals to attend to).

### Key idea

Two complementary tricks: rounds-with-memory to escape the salience anchor that single-pass prediction falls into, plus templates that act as recognizers for problem classes. Each round picks up a small batch of new candidates grounded in supporting evidence.

### Main finding

On personal-workspace and software-repo settings, across four backbones, TIDE beats single-shot and parallel multi-agent baselines on coverage, identification, and resolution.

### Why it matters

The default "do exactly what the user asked" mode is bad agent design when most real workflows have multiple latent issues. TIDE is a clean recipe for *proactive* agents — and "schemas of past solved cases as prompts" is a generalizable trick.

## 15. AdaPlanBench

**Authors:** Jiayu Liu, Cheng Qian, Zhenhailong Wang, …, Heng Ji — *UIUC*
**Links:** [arXiv:2606.05622](https://arxiv.org/abs/2606.05622) · [HF](https://huggingface.co/papers/2606.05622) · [AlphaXiv](https://www.alphaxiv.org/abs/2606.05622)
**Topics:** `agents`, `eval`, `planning`

### TL;DR

Benchmark for *adaptive* planning: agents face household tasks with hidden world and user constraints revealed only when violated, forcing iterative re-planning. Best of 10 leading models: **67.75%** accuracy. Degrades sharply as constraints stack; user constraints hurt the most.

### Key idea

Hide constraints behind environment feedback. Agents must infer + track them while re-planning. 307 base tasks each augmented with a dual-constraint pipeline (world + user). Multi-turn interactive protocol.

### Main finding

A leading model ceiling of 67.75% (best result), with failures concentrated in physical-grounding errors under user-constraint accumulation.

### Why it matters

Most planning benchmarks pre-state all constraints — that's not how real users interact. AdaPlanBench measures *plan-revision-under-disclosure*, which is the more honest task. A natural target for RL fine-tuning of planning agents.
