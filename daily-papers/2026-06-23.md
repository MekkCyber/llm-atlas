## 1. PlanBench-XL: Evaluating Long-Horizon Planning of LLM Tool-Use Agents in Large-Scale Tool Ecosystems {#1-planbench-xl}

**Authors:** Jiayu Liu, Qihan Lin, Cheng Qian, Rui Wang, Emre Can Acikgoz, Xiaocheng Yang, Jiateng Liu, Zhenhailong Wang, Xiusi Chen, Heng Ji, Dilek Hakkani-Tür — *University of Illinois Urbana-Champaign*
**Links:** [arXiv:2606.22388](https://arxiv.org/abs/2606.22388) · [HF](https://huggingface.co/papers/2606.22388) · [AlphaXiv](https://www.alphaxiv.org/abs/2606.22388)
**Topics:** `agents`, `eval`, `tool-use`

### TL;DR

A 327-task / 1,665-tool interactive benchmark for tool-use agents under *retrieval-limited* tool visibility — agents have to iteratively retrieve tools, invoke them to surface intermediate evidence, and chain that into more retrieval. Frontier agents fall off a cliff (GPT-5.4: 51.9% → 11.4%) once blocking gets severe, exposing how brittle current "long-horizon" planning is when the tool catalogue is too large to fit in the prompt.

### Key idea

Decouple tool *visibility* from tool *availability*: the agent never sees all 1,665 tools at once and must use successful sub-results as queries that bring the next useful tool into the visible set. Tasks then probe whether the policy can plan under partial-information retrieval rather than top-k selection from a static schema list.

### Main finding

Best frontier system (GPT-5.4 + harness) reaches 51.90% in the unblocked retail setting but collapses to 11.36% under severe blocking; smaller open-weight agents degrade earlier and more sharply. Failures localize to *adaptive re-planning* — agents commit to invalid tool chains and don't recover.

### Why it matters

Most agent benchmarks fix the tool catalogue or give the agent full visibility. PlanBench-XL is one of the first to stress-test the loop that real production agents actually run: dynamic discovery + multi-hop planning over a catalogue that doesn't fit in context.

## 2. OpenRath: Session-Centered Runtime State for Agent Systems {#2-openrath}

**Authors:** Fukang Wen, Zhijie Wang, Ruilin Xu — *Tsinghua University*
**Links:** [arXiv:2606.19409](https://arxiv.org/abs/2606.19409) · [HF](https://huggingface.co/papers/2606.19409) · [AlphaXiv](https://www.alphaxiv.org/abs/2606.19409)
**Topics:** `agents`, `systems`

### TL;DR

OpenRath reframes agent infrastructure around a first-class `Session` object that carries lineage, tool evidence, sandbox metadata, and usage records — instead of letting that state hide in implicit side channels (env vars, scratch files, framework-specific caches). The pitch is that "hidden runtime state" is what makes agents non-reproducible, non-auditable, and hard to compose.

### Key idea

A *session-centered* runtime: every tool call, every sub-agent, every sandbox write is parented to a Session, which holds the full causal lineage. The Session is the unit of replay, attribution, and resource accounting.

### Main finding

The paper is more system / framework than benchmark — the main argument is qualitative: making the runtime state explicit yields better reproducibility, easier auditing, and cleaner multi-agent composition. Examples demonstrate replay and lineage queries across tool chains.

### Why it matters

Agent frameworks have been ad-hoc about state: each one invents its own thread-local "context" object and they don't interoperate. A standard session abstraction is the kind of plumbing that makes safety auditing, cost attribution, and multi-agent orchestration tractable.

## 3. DataClaw₀: Agentic Tailoring Multimodal Data from Raw Streams {#3-dataclaw0}

**Authors:** Xiangyang Luo, Zhiheng Ma, Yihong Gong — *XJTU / UCAS / SUAT / Tsinghua*
**Links:** [arXiv:2606.21337](https://arxiv.org/abs/2606.21337) · [HF](https://huggingface.co/papers/2606.21337) · [AlphaXiv](https://www.alphaxiv.org/abs/2606.21337)
**Topics:** `data`, `multimodal`, `RL`

### TL;DR

DataClaw₀ is a 9B agentic data-refinement model: instead of passively annotating data, the agent actively *tailors* raw multimodal streams to the downstream training task. Trained with SFT followed by GRPO and validated on video gen, VQA, and GUI navigation downstreams.

### Key idea

Treat data preparation as a *policy* problem: the agent's reward signal comes from how well the refined dataset trains a downstream model, and the policy is shaped with GRPO to favor refinements that unlock task-specific structure (procedural logic, action grounding) hidden in the raw stream.

### Main finding

DataClaw₀-9B + the agentic pipeline improves downstream task models across video-gen, VQA, and GUI-navigation benchmarks vs. passive annotation baselines (DataClaw₀-val is introduced for direct evaluation of refinement quality).

### Why it matters

Multimodal post-training is increasingly bottlenecked by data quality, not compute. Moving the data pipeline from "tag everything once" to "shape the data for the target task" reframes data curation as RL-trained behaviour.

## 4. EnterpriseClawBench: Benchmarking Agents from Real Workplace Sessions {#4-enterpriseclawbench}

**Authors:** Weizhi Wang, Che Jiang, Kai Tian, Zhenzhao Yuan, Junlin Yang, Dianqiao Lei, Kaiyan Zhang — *Horizon Research, Frontis.AI*
**Links:** [arXiv:2606.23654](https://arxiv.org/abs/2606.23654) · [HF](https://huggingface.co/papers/2606.23654) · [AlphaXiv](https://www.alphaxiv.org/abs/2606.23654)
**Topics:** `agents`, `eval`

### TL;DR

852 reproducible tasks reconstructed from real workplace agent sessions (proprietary data — only the construction & eval protocol is released). Each task carries fixtures, rewritten prompts, role/skill labels, hard rules, and semantic rubrics. Even the best harness/model pair (Codex + GPT-5.5) only hits 0.663 on the 120-task Lite subset.

### Key idea

Don't trust synthetic benchmarks for enterprise agents — mine actual session archives and reify them into tasks with the artifacts the agent originally produced. Evaluation reports a *vector* (artifact delivery, visual quality, cost, runtime, skill-transfer) rather than collapsing to a single score.

### Main finding

The 0.663 ceiling under careful auditing shows that even frontier agents on real enterprise work miss a third of tasks. Choice of *harness* (scaffolding) is shown to matter as much as choice of *model*.

### Why it matters

A pattern: as agents move into production, eval protocols have to match. The "release a corpus" model is dead for proprietary data — the contribution is the eval methodology and the reusable scaffolding.

## 5. Grouped Query Experts: Mixture-of-Experts on GQA Self-Attention {#5-gqe} <a name="5-gqe"></a>

**Authors:** Not disclosed on HF page
**Links:** [arXiv:2606.20945](https://arxiv.org/abs/2606.20945) · [HF](https://huggingface.co/papers/2606.20945) · [AlphaXiv](https://www.alphaxiv.org/abs/2606.20945)
**Topics:** `MoE`, `architectures`, `efficient-inference`

### TL;DR

GQE puts a router inside a GQA layer: within each query group, only `k` of the query-head experts fire per token; KV heads stay dense. The result is a *sparse attention* layer that keeps the entire KV-cache footprint of GQA while activating only a fraction of query-head compute.

### Key idea

A token-conditional sparse query head. The router picks which query-head experts run, the dense KV heads stay shared — so cache size is unchanged but query-side FLOPs drop. This is MoE applied at the head granularity inside an attention block, rather than the usual MoE on the MLP.

### Main finding

At 250M params and 30B-token budget, GQE matches the all-active GQA baseline in downstream accuracy while activating only half the routed query-head experts per token — half the query-side attention compute for free.

### Why it matters

Attention cost dominates at long context. Putting MoE on the *attention* side (and on the right side of it — query-only, KV dense) preserves the KV-cache savings of GQA while unlocking the activation-sparsity savings of MoE.

## 6. KaLM-Reranker-V1: Fast but Not Late Interaction for Compressed Document Reranking {#6-kalm-reranker}

**Authors:** Xinping Zhao, Jiaxin Xu, Ziqi Dai, Xin Zhang, Shouzheng Huang, Danyu Tang, Xinshuo Hu, Meishan Zhang, Baotian Hu, Min Zhang — *HIT Shenzhen / Shenzhen Loop Area Institute*
**Links:** [arXiv:2606.22807](https://arxiv.org/abs/2606.22807) · [HF](https://huggingface.co/papers/2606.22807) · [AlphaXiv](https://www.alphaxiv.org/abs/2606.22807)
**Topics:** `retrieval`, `efficient-inference`

### TL;DR

A reranker that decouples query and passage computation (so passages can be pre-encoded once and cached) without paying the expressivity tax of late-interaction models. Encoder pre-encodes passages with *Matryoshka pooling*; decoder handles system prompt, user instruction, and query; cross-attention does the relevance step.

### Key idea

"Fast but not late" (FBNL): not full joint encoding (too expensive at serve time) and not pure dual-encoder late interaction (too weak). The trick is encoder/decoder asymmetry with cross-attention as the cheap join, plus Matryoshka pooling so the cached passage embedding can be truncated per latency budget.

### Main finding

Decouples passage cost from query cost while staying competitive on quality. The Matryoshka design means one stored embedding serves multiple precision/latency tiers.

### Why it matters

Reranker quality vs. serving cost is the central pain in retrieval pipelines. FBNL is a third operating point on that tradeoff curve — important because RAG and agentic retrieval are pushing rerankers into the hot path.

## 7. World Action Models: A Survey {#7-world-action-models}

**Authors:** Shihua Zhang, Yue Liao, Qi Li, Zhenxiong Tan, Shizun Wang, Shuicheng Yan, Xinchao Wang — *National University of Singapore*
**Links:** [arXiv:2606.20781](https://arxiv.org/abs/2606.20781) · [HF](https://huggingface.co/papers/2606.20781) · [AlphaXiv](https://www.alphaxiv.org/abs/2606.20781)
**Topics:** `multimodal`, `agents`, `world-models`

### TL;DR

A survey that draws hard boundaries between "world model", "video generation model", "action-grounded video world model", "VLA", and "World Action Model" (WAM). Organizes WAMs along two axes: what they have to generate (rendered futures, latent futures, no future at all), and four design dimensions — predictive substrate, backbone, action coupling, deployment regime.

### Key idea

WAMs are not "video generators with an action head" — they're predictive-action methods whose design choice trades representational richness against compute, memory, latency, and action-label cost. The field is shifting toward generating *less* of the future while preserving what control needs.

### Main finding

A taxonomy and unified vocabulary; identifies interactability, causality, persistence, physical plausibility, and generalization as the cross-cutting evaluation axes.

### Why it matters

WAMs sit between foundation models and embodied control. Without shared terminology, this area was fragmenting into "video-gen with extra steps" and "VLA with extra steps" — a clean survey unblocks comparison.

## 8. EvoEmbedding: Evolvable Representations for Long-Context Retrieval and Agentic Memory {#8-evoembedding}

**Authors:** Not disclosed on HF page
**Links:** [arXiv:2606.21649](https://arxiv.org/abs/2606.21649) · [HF](https://huggingface.co/papers/2606.21649) · [AlphaXiv](https://www.alphaxiv.org/abs/2606.21649)
**Topics:** `agents`, `retrieval`

### TL;DR

Static embeddings encode each segment in isolation. EvoEmbedding carries a continuously-updated latent memory across a stream of segments and emits embeddings that are conditioned on both the raw content and the running memory — so the *same query* retrieves different things as the context evolves.

### Key idea

A recurrent/stateful embedding model: process inputs sequentially, maintain a latent memory, jointly embed `(content, memory)`. The embedding is then a *snapshot* of the agent's memory at the point of indexing rather than a context-free representation.

### Main finding

Retrieval quality on long-context / agentic-memory benchmarks improves when the embedding tracks evolving state, vs. static-embedding baselines that have to re-embed on every update.

### Why it matters

Agentic memory is the bottleneck for long-running agents — static embeddings can't reflect "what the agent knows now." Evolvable embeddings give the storage layer a temporal axis without paying the cost of re-embedding.

## 9. Deeper is Not Always Better: Mitigating the Alignment Tax via Confident Layer Decoding {#9-confident-layer-decoding}

**Authors:** Xuanming Zhang, Sining Zhoubian, Yuxuan Chen, Tianyi Tang, An Yang, Sean Du, Chujie Zheng, Fei Huang, Dayiheng Liu, Gao Huang, Jingren Zhou — *Qwen Team (Alibaba) / Tsinghua / NTU*
**Links:** [arXiv:2606.21906](https://arxiv.org/abs/2606.21906) · [HF](https://huggingface.co/papers/2606.21906) · [AlphaXiv](https://www.alphaxiv.org/abs/2606.21906)
**Topics:** `efficient-inference`, `safety`, `reasoning`

### TL;DR

Identifies a recurring *Guess–Refine–Perturb* dynamic across LLM layers: early layers form coarse guesses, middle layers refine reasoning-relevant semantics, *final* layers perturb predictions toward alignment-preferred tokens — costing reasoning quality. Confident Decoding dynamically picks a near-final layer via entropy-guided backward search; training-free, <2% latency, no extra memory.

### Key idea

Treat layer selection as an optimal-stopping problem: walk backward from the final layer, accept the first layer whose logit distribution is "confidently refined" (entropy criterion). Under bounded projection noise and dominant late-stage alignment perturbation, the rule provably bounds loss vs. the oracle layer.

### Main finding

Consistent gains on GPQA-Diamond, Omni-MATH, and HLE across dense and MoE LLMs, with no training, <2% latency overhead, zero memory overhead. Works at inference time on already-aligned models.

### Why it matters

The "alignment tax" on reasoning is well-known but usually addressed at train time (e.g., constitutional fine-tuning trade-offs). This says: the tax lives in the *final* layers, and you can skip past it at decode time — a free reasoning boost on any aligned model.

## 10. HydraHead: From Head-Level Functional Heterogeneity to Specialized Attention Hybridization {#10-hydrahead}

**Authors:** Not disclosed on HF page
**Links:** [arXiv:2606.20097](https://arxiv.org/abs/2606.20097) · [HF](https://huggingface.co/papers/2606.20097) · [AlphaXiv](https://www.alphaxiv.org/abs/2606.20097)
**Topics:** `architectures`, `efficient-inference`, `long-context`

### TL;DR

Different attention heads do different jobs — retrieval-critical heads need full attention, the rest can run linear attention. HydraHead uses interpretability-based head identification to assign each head to its right attention kernel, getting long-context capability on just 15B training tokens.

### Key idea

Hybrid attention at the *head* level, not the layer level. Use probing/interpretability to identify which heads matter for long-range retrieval (the "needle" heads), keep them on full attention, and downgrade the rest to linear attention. The result is an attention layer that's mostly cheap with a small fully-attended core.

### Main finding

Approaches Qwen3.5-2B performance on long-context benchmarks with only 15B training tokens; >69% improvement on NIAH at 512k context vs. uniformly-applied linear attention.

### Why it matters

Hybrid attention has so far been layer-granularity (some layers full, some linear). Going head-granularity is finer-grained, and the per-head decision can be made by *evidence from the model itself* (probes) rather than ablation guesswork.

## 11. SkillHarness: Harnessing Safe Skills for Computer-Use Agents {#11-skillharness}

**Authors:** Not disclosed on HF page
**Links:** [arXiv:2606.20636](https://arxiv.org/abs/2606.20636) · [HF](https://huggingface.co/papers/2606.20636) · [AlphaXiv](https://www.alphaxiv.org/abs/2606.20636)
**Topics:** `agents`, `safety`, `computer-use`

### TL;DR

Existing computer-use agents that "learn skills from successful trajectories" assume a static, safe environment. SkillHarness adds a *skill boundary* abstraction that filters unsafe skill candidates using multi-source supervision, and replaces unconditional skill reuse with context-conditional *selective* activation.

### Key idea

Reframe skill learning as a safety-constrained interaction process. The skill boundary identifies which skills are safe to internalize, using signals from interaction outcomes, environment state, and supervision. At runtime, tasks are decomposed and only the *safe subset* of skills is activated for the current context.

### Main finding

57.1% reduction in unsafe-skill rate vs. prior skill-learning baselines and improved execution stability under dynamic environment changes (pop-ups, prompt-injection attempts).

### Why it matters

Skill-learning frameworks for CUAs are getting popular and almost all of them assume benign environments. As CUAs ship into real browsers and OS shells, the literature has to bake safety into the skill-acquisition loop, not bolt it on after.

## 12. TAPO: Learning from Your Own Mistakes via Micro-Reflective Trajectories {#12-tapo}

**Authors:** Zhilin Huang, Hang Gao, Ziqiang Dong, Yuan Chen, Yifeng Luo, Chujun Qin, Jingyi Wang, Yang Yang, Guanjun Jiang — *Qwen (Alibaba) / Tsinghua / PKU*
**Links:** [arXiv:2606.18844](https://arxiv.org/abs/2606.18844) · [HF](https://huggingface.co/papers/2606.18844) · [AlphaXiv](https://www.alphaxiv.org/abs/2606.18844)
**Topics:** `RL`, `reasoning`, `post-training`

### TL;DR

Trajectory-Augmented Policy Optimization (TAPO) sits on top of GRPO. During training, the model samples both correct and incorrect rollouts for the same prompt; TAPO builds *micro-reflective* trajectories that keep the wrong prefix, insert a natural-language diagnosis, and graft on a corrected continuation from a sibling rollout. Adds difficulty-aware candidate selection and decoupled advantage to keep gradients clean.

### Key idea

Replace implicit KL-style distillation ("imitate the right distribution") with *explicit* reflective trajectories ("here's where you went wrong and how to fix it"). The diagnosis-and-correct trajectory stays on-policy because it's anchored in the model's own prefix.

### Main finding

Consistent improvements over GRPO at the same training step count on AIME 2024, AIME 2025, and HMMT 2025 — both first-pass accuracy and error-correction effectiveness improve.

### Why it matters

GRPO and other RL post-training methods waste signal: they only use the *outcome* of a rollout, not the structure of *where it went wrong*. TAPO turns that error structure into trajectory-level supervision without leaving the on-policy regime.

## 13. VESFlow: Safe Few-Step Generation via Velocity Editing {#13-vesflow}

**Authors:** Yujin Choi, Jaehong Yoon — *NTU Singapore / UNIST*
**Links:** [arXiv:2606.23267](https://arxiv.org/abs/2606.23267) · [HF](https://huggingface.co/papers/2606.23267) · [AlphaXiv](https://www.alphaxiv.org/abs/2606.23267)
**Topics:** `diffusion`, `flow-matching`, `safety`

### TL;DR

Existing diffusion-safety methods (trajectory steering, CLIP-embedding manipulation) break under few-step flow matching (e.g., MeanFlow). VESFlow is a training-free safety filter that edits the *velocity field* directly via a Bayesian decomposition of the safe-conditional posterior, while leaving the conditioning prompt untouched. A risk-score gate skips editing on benign prompts.

### Key idea

Flow-matching models learn the marginal/mean velocity; that velocity *is* the steerable knob. Decompose the safe-conditional posterior, edit the velocity to push trajectories toward safe outputs (VESFlow+) and explicitly away from unsafe ones, with a risk-score router so benign generations stay un-perturbed.

### Main finding

On 4-step MeanFlow: NudeNet attack-success rate drops to 6.3% on Ring-A-Bell and 6.8% on MMA-Diffusion, while quality on benign prompts is preserved.

### Why it matters

The flow-matching / few-step generation wave was leaving a safety hole: every existing T2I safety method assumed many iterative denoising steps. VESFlow proves you can steer at the velocity-field level instead — the right abstraction for the new generation paradigm.
