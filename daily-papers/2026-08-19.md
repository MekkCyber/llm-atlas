## 1. Demystifying Agent Skills

**Authors:** Zhiyuan Jiang, Fangrui Huang, Hanwen Xing, Xander Wu, Yipeng Gao, Rui Cao, Mengdi Wang, Shilong Liu, Yijiang Li — *UC San Diego / Princeton*
**Links:** [arXiv:2608.14036](https://arxiv.org/abs/2608.14036) · [HF](https://huggingface.co/papers/2608.14036) · [AlphaXiv](https://www.alphaxiv.org/abs/2608.14036)
**Topics:** `agents`, `eval`

### TL;DR

A controlled study of *why* prompt-packaged "skills" (Claude-style skill libraries) actually help LLM agents. Runs 8,135 trials across benchmarks, harnesses and LLMs, isolates the effect of representation, outcome annotation, retrieval, and cross-framework robustness, then hand-codes 240 trajectory pairs into a taxonomy of 12 skill-use modes. Skills mostly work by anchoring execution to a stable procedure — not by injecting missing knowledge.

### Key idea

Treat "skills" as a *composition of three moving parts* (retrieval, representation, adaptation) and run matched-trajectory ablations that hold two constant while varying the third. This lets the authors separate "the skill helped because it was correctly retrieved" from "the skill helped because its execution scaffold stabilized the agent". They then open-code 240 trajectories to build a **twelve-mode taxonomy** of how skills interact with agent behaviour.

### Main finding

- **Procedural anchoring dominates.** 65.7% of successful skill uses fit the "noisy trajectory → procedural anchor" pattern; only 4.5% inject explicit missing knowledge.
- **Skills beat Workflow Memory by 6.06 points** in matched comparisons.
- **Retrieval collapses at scale.** As the skill pool grows 5 → 100, actual-use precision falls from 29.6% to 3.3%.
- Exact ground-truth invocation is neither sufficient nor necessary — confusable distractors hurt offline identification but leave downstream success stable.

### Why it matters

Every self-evolving-agent framework (SkillWeaver, Voyager-descendants, Claude Skills) treats "grow the skill library" as the goal. This paper says the marginal skill only helps if it can be *found* and if it *anchors* an existing shaky procedure — otherwise it's dead weight or actively harmful. Retrieval, not authorship, is the ceiling.

## 2. Agentic ESOpt

**Authors:** Zhi Zheng, Rongsheng Chen, Yunpeng Ba, Zhenkun Wang, Yee Whye Teh, Wee Sun Lee — *NUS / Oxford / SUSTech*
**Links:** [arXiv:2608.17310](https://arxiv.org/abs/2608.17310) · [HF](https://huggingface.co/papers/2608.17310) · [AlphaXiv](https://www.alphaxiv.org/abs/2608.17310)
**Topics:** `agents`, `RL`, `evolution-strategies`

### TL;DR

Replaces backprop-based RL post-training for long-horizon LLM agents with **evolution strategies (ES)**: sample parameter perturbations, evaluate at rollout time, apply a reward-weighted mean update. Because ES only needs inference-level GPU memory (no gradients, no activations), it scales to full-parameter fine-tuning of large models on modest hardware.

### Key idea

Reframe long-horizon agentic optimisation as **trajectory-level parameter attribution**: instead of back-propagating a per-token loss through a huge rollout, perturb the whole parameter vector, run the whole trajectory, and weight the perturbation by its return. Adds two twists that make ES competitive on LLMs: (1) online reward-weighted updates (rather than a batch-mean like OpenAI-ES), and (2) a **cosine-decayed perturbation scale** so the schedule mimics RL's early-exploration / late-exploitation curve.

### Main finding

- Full-parameter optimisation of **Qwen-3.5-27B** on WebArena-Lite beats the no-skill baseline by **+6.69** points using only inference-scale memory.
- In test-time automatic heuristic design, ES co-evolves prompts and parameters and wins in **28 of 36** settings vs matched RL.
- Advantage over agentic RL grows with horizon length, matching the theoretical claim that ES's credit-assignment is horizon-agnostic.

### Why it matters

If ES really is competitive at LLM scale, it undermines the assumption that big-model RL requires DeepSpeed-scale GPU fleets. It also opens a natural bridge to **prompt-space evolution** (skill libraries, DSPy, TextGrad), because both live in the same black-box optimisation regime. Expect frameworks like verl and Agent Lightning to grow ES backends.

## 3. FreeToken

**Authors:** Shuo Yang, Xiaoze Fan, Melissa Pan, Haocheng Xi, Zhe Wang, Shanlin Sun, Kurt Keutzer, Song Han, Matei Zaharia, Chenfeng Xu, Ion Stoica — *UC Berkeley / MIT / NVIDIA*
**Links:** [arXiv:2608.16157](https://arxiv.org/abs/2608.16157) · [HF](https://huggingface.co/papers/2608.16157) · [AlphaXiv](https://www.alphaxiv.org/abs/2608.16157)
**Topics:** `efficient-inference`, `MoE`, `agents`

### TL;DR

An edge-native MoE serving stack that treats a personal machine (laptop → workstation) as a heterogeneous inference platform, and *continuously* remaps expert residency, CPU–GPU execution, and KV state as the workload changes. No fixed offloading policy — decisions adapt to which experts a coding/tool-using agent actually hits next.

### Key idea

Two observations reshape MoE serving away from datacenter assumptions:
1. **Agent workloads shift execution patterns turn-by-turn** (a code agent might oscillate between long-context reads and short bursts of tool calls).
2. **Edge hardware is heterogeneous** — laptop GPU + integrated GPU + big CPU + bandwidth-limited PCIe.
FreeToken co-designs the whole stack (layout, expert residency, prefill/decode split, agentic KV reuse) around a **runtime scheduler** that measures effective bandwidth each step and re-plans.

### Main finding

- Runs a **35B MoE on an 8GB laptop GPU**, a **284B MoE on a gaming desktop**, and the **753B GLM-5.2 on a single workstation GPU**.
- Supports 20+ open MoE models and real code/tool agents end-to-end.

### Why it matters

The gap between "open weights" and "runnable on my machine" is the largest friction in local AI. FreeToken pushes frontier-scale MoEs onto consumer hardware without touching the model, expanding the addressable deployment surface for open-weight frontier models substantially.

## 4. ASI-Bench

**Authors:** Junwei Zhou, Zhen Sun, Binyu Li, Jiangyu Zhou, Yuexi Pan, et al. (43 authors) — *large multi-institution consortium*
**Links:** [arXiv:2608.17271](https://arxiv.org/abs/2608.17271) · [HF](https://huggingface.co/papers/2608.17271) · [AlphaXiv](https://www.alphaxiv.org/abs/2608.17271)
**Topics:** `eval`, `agents`, `reasoning`

### TL;DR

A 60-task, 11-domain benchmark for open-ended scientific research where the amount of human scaffolding is *itself* a variable. Each task is graded at multiple guidance levels, from "you're given the method" down to "you must choose the method". Tests when agents stop being tool-users and start being investigators.

### Key idea

Rather than a static leaderboard, ASI-Bench sweeps a **guidance axis** per task: full method → partial method → no method. This yields a "guidance-sensitivity curve" for each system, so you can distinguish an agent that solves problems only when told how from one that self-directs.

### Main finding

Frontier systems scored **50.91** with full guidance and dropped to **26.62** at the no-guidance end — a nearly 50% relative collapse when the agent has to pick methods itself.

### Why it matters

Most "AI scientist" evals conflate execution and initiative. Splitting them is essential for making claims about *research capability* rather than *research assistance*. Expect follow-up systems (co-scientist, deep-research) to report guidance curves.

### Knowledge graph integration

**Suggested new pages:**
- `evaluation/asi-bench.md` *(depth)* — 60-task, 11-domain, guidance-swept research benchmark.

## 5. AVA-Encoder

**Authors:** Chuyue Li, Jinpeng Yu, Haozhe Wang, Tian Xueyun, Zhijing Zhang, Bingnan Li, Shuqi Gu, Kan Ren, Jiaming Liu, Ruihua Huang — *Qwen / Alibaba / ShanghaiTech / HKUST*
**Links:** [arXiv:2608.12313](https://arxiv.org/abs/2608.12313) · [HF](https://huggingface.co/papers/2608.12313) · [AlphaXiv](https://www.alphaxiv.org/abs/2608.12313)
**Topics:** `multimodal`, `agents`, `video`

### TL;DR

Turns videos into an **agent-readable knowledge graph** (typed nodes for scenes/objects, typed edges for relations, links back to source frames/audio) and trains a decoder to reconstruct the video from that graph. Optimised with textual-gradient descent: an outer loop tunes the policy that writes the graph, an optional inner loop tunes the representation.

### Key idea

Video → graph is a lossy compressor, but one whose lossiness is *understood* by an agent. Textual-gradient optimisation (à la TextGrad / DSPy) drives the graph-writing policy by measuring reconstruction quality of the graph → video decoder. Because both loops read the same asset-linked graph, prompt tuning and representation tuning share a native currency.

### Main finding

- **+20.7 percentage points** over the strongest video-encoder baseline on the reconstruction benchmark.
- Pseudo-trained policy beats human-tuned prompts while using **74.3% fewer tokens**.
- Ships a reconstruction benchmark and film knowledge-graph datasets.

### Why it matters

Long-video understanding is bottlenecked by token cost; graph-first video representations let agents *reason* over long clips without pushing every frame through a VLM. If reconstruction quality really can be a training signal for video graph writers, this becomes a general recipe for agent-native modality encoders (audio, docs, code).

### Knowledge graph integration

**Suggested new pages:**
- `multimodal/agent-native-video-encoder.md` *(depth)* — graph-first video representation with textual-gradient optimisation.

## 6. V-RAE

**Authors:** Minghui Guo, Shengqiong Wu, Hao Fei — *National University of Singapore*
**Links:** [arXiv:2608.13556](https://arxiv.org/abs/2608.13556) · [HF](https://huggingface.co/papers/2608.13556) · [AlphaXiv](https://www.alphaxiv.org/abs/2608.13556)
**Topics:** `diffusion`, `video`, `multimodal`

### TL;DR

A video autoencoder that builds its latent space on **frozen vision-foundation-model features** (not pixels), pools temporally, and decodes back to motion. The claim: reconstruction-optimal video latents are *not* generation-optimal; semantic-first latents converge 6× faster and match SoTA gFVD.

### Key idea

Split reconstruction from generation. Freeze a semantic encoder (SigLIP-style), add a lightweight temporal-pooling module that squeezes redundant frames while preserving semantic structure, and train a decoder to reconstruct continuous motion from the compressed features. The autoencoder is optimised primarily for the *generative* downstream, not for pixel fidelity.

### Main finding

- **2.13 rFVD on K600** — beats all evaluated large pretrained video VAEs.
- Best variant: **gFVD 117.86 on UCF101** and **19.16 on K600** under matched settings; **6× faster convergence** than pixel-VAE baselines.
- Introduces **tFVD** (temporal-coherence FVD) — correlates with downstream generation better than plain rFVD.

### Why it matters

Latent-video-diffusion has been stuck on VAE latents optimised for the wrong metric. Building latents on frozen foundation-model features may become the default for video generation, analogously to how DINO/SigLIP-based latents are eating pixel-VAE latents in image generation.

### Knowledge graph integration

**Suggested new pages:**

## 7. Agent Lightning v1.0

**Authors:** Zhiyuan He, Siwei Zhang, Zhiwen Zhou, Yuqing Yang, Yu Kang, Yuge Zhang, Luna K. Qiu, Tin Yan Tsui, Jiahang Xu, Chong Luo — *Microsoft / USTC*
**Links:** [arXiv:2608.17528](https://arxiv.org/abs/2608.17528) · [HF](https://huggingface.co/papers/2608.17528) · [AlphaXiv](https://www.alphaxiv.org/abs/2608.17528)
**Topics:** `agents`, `RL`, `systems`

### TL;DR

A ~3,500-LOC framework for **harnessed agentic RL** — where the deploy-time harness (Claude Code, OpenHands, OpenCode) owns the environment loop and the trainer sees only LLM request/response pairs through an endpoint proxy. Codifies the retokenisation / sample-merging / advantage / loss-normalisation choices that this decoupling forces.

### Key idea

The **LLM endpoint proxy** is the coupling seam. The harness runs unmodified and thinks it's calling a normal chat completion endpoint; behind the proxy, the trainer captures token-level request/response pairs, stitches them into trajectories, re-tokenises where necessary, and computes RL loss. Any harness works if it speaks the endpoint protocol. This is the paradigm shift the paper names **harnessed agentic RL** — a first-class framework family (verl Uni-Agent, AReaL 2.0, slime, Polar) rather than a one-off wrapper.

### Main finding

- Trains **Qwen3.5-9B** on SWE-bench Verified from **41.8% → 56.4%** (+14.6 abs) using only 6K training examples.
- Reproducible coding-agent RL pipeline released end-to-end.

### Why it matters

Coding-agent evaluation has become a dominant benchmark family, but training an agent that plays well inside a real harness has been ad-hoc. A framework that decouples harness from trainer via a proxy lets researchers reuse deployment infrastructure directly for post-training, dramatically shortening the sim-to-real loop.

## 8. Dynamic Multi-Byte Prediction

**Authors:** Abraham Toluwase Owodunni, Chibuzor Okocha, Christan Grant, Tomasz Limisiewicz, Sachin Kumar — *Ohio State University / University of Oklahoma / ETH Zurich*
**Links:** [arXiv:2608.15454](https://arxiv.org/abs/2608.15454) · [HF](https://huggingface.co/papers/2608.15454) · [AlphaXiv](https://www.alphaxiv.org/abs/2608.15454)
**Topics:** `efficient-inference`, `tokenization`

### TL;DR

Byte-level hierarchical LMs (Byte-Latent-Transformer / MegaByte-style) generate one byte at a time — a throughput cliff. This paper generalises **multi-token prediction (MTP)** to bytes with a **variable-length prediction window aligned to the hierarchical LM's latent segments**, plus a new attention mask that keeps causality intact. No extra parameters.

### Key idea

MTP with a fixed $k$ doesn't map to byte-level models because segment boundaries are dynamic. **Dynamic MBP** aligns the prediction window to the *latent segment* the hierarchical encoder just produced — so the model predicts a whole segment's bytes in parallel when the segment is short, fewer when long. A tailored causal mask keeps each predicted byte from seeing later bytes in the same segment.

### Main finding

Pareto-optimal trade-off between throughput and quality on QA, instruction following, summarisation, and MT — matches next-byte quality with substantially higher tokens/sec.

### Why it matters

Byte-level LMs remove tokeniser lock-in but have been throughput-bottlenecked. Dynamic MBP closes the gap without adding parameters, keeping byte-level models a live alternative to subword tokenisation for multilingual / code / robust-to-noise regimes.

## 9. MoE-ViE

**Authors:** Bonan Zhang, Shiyu Dong, Quan Hung Tran, Katharina Gschwind, Shuqi Yang, Sijia Chen, Adel Ahmadyan, Seungwhan Moon, Lu Zhang, Ahmed Kirmani, Babak Damavandi, Anuj Kumar — *Meta*
**Links:** [arXiv:2608.17402](https://arxiv.org/abs/2608.17402) · [HF](https://huggingface.co/papers/2608.17402) · [AlphaXiv](https://www.alphaxiv.org/abs/2608.17402)
**Topics:** `multimodal`, `MoE`, `efficient-inference`

### TL;DR

Systematic study of Mixture-of-Experts for **vision encoders** in VLMs. Fine-grained expert topologies (many small experts, high top-k) beat both dense and standard MoE. Adds an aux-loss-free balancing variant, a custom MoE kernel to cut latency, and a frame-level distillation + freezing trick to add video without losing image knowledge.

### Key idea

Vision encoders were dense-scaled; this paper ports **fine-grained MoE + aux-loss-free balancing** (DeepSeek-style) into a CLIP/SigLIP-shaped image/video encoder, tunes the topology (expert count, granularity, top-k) for vision-specific activation patterns, and adds a **frozen-image / trainable-temporal** distillation pipeline so video training doesn't degrade the image priors.

### Main finding

- Largest MoE-ViE matches a SoTA dense encoder that is **1.7× larger** at **76% of its latency**.
- When plugged into a VLM, MoE-ViE beats all compared encoders on image and video benchmarks, including ones with **5× more activated parameters**.
- Code released at `github.com/facebookresearch/moe_vie`.

### Why it matters

The MoE recipe that transformed LLM scaling finally lands cleanly in vision encoders. This upsets the "just use SigLIP" default for VLMs and suggests VLMs will start shipping with MoE encoders as well as MoE LLMs.

## 10. Harness the Memory

**Authors:** Wei-Chieh Huang, Weizhi Zhang, Yuchen Wu, Yankai Chen, Eric Hanchen Jiang, Wooseong Yang, Yiwei Yang, Henry Peng Zou, Hanrong Zhang, Ying Nian Wu, Haolun Wu, Kai-Wei Chang, Philip S. Yu, Xue Liu, Aylin Caliskan — *UIUC / UCLA / U-Washington / McGill*
**Links:** [arXiv:2608.15008](https://arxiv.org/abs/2608.15008) · [HF](https://huggingface.co/papers/2608.15008) · [AlphaXiv](https://www.alphaxiv.org/abs/2608.15008)
**Topics:** `agents`, `eval`, `memory`

### TL;DR

A controlled evaluation of **memory substrates** for long-horizon agents: dense/sparse indices, text records, structural stores, hierarchical stores, refinement-based memories, parametric updates, and activation-compatible context. 26 metrics, 3 backbones, 4 benchmark suites, one harness. No substrate dominates; the right substrate depends on the operating regime.

### Key idea

Treat "memory" as a *routing* decision, not an architectural choice. Fix the harness, vary the substrate, measure both quality and efficiency in a common frame. The paper's central experimental design choice is to **pin the agent scaffold** so any variance is attributable to the substrate.

### Main finding

- **No single dominant substrate.** Broad retrieval helps long-context QA; excessive retrieval *hurts* sequential decision-making by shifting attention off action-critical context.
- **Scalability shifts the winner.** Substrates that win at moderate history become brittle or costly at long horizons.
- Motivates **substrate routing** as a first-class agent-memory design element.

### Why it matters

The agent-memory literature had converged on RAG variants; this paper shows that's the wrong default for decision-making tasks and gives the first apples-to-apples map of when each substrate wins. Framework designers should expose substrate as a per-regime knob.

### Knowledge graph integration

**Suggested new pages:**

## 11. LEGO-RL

**Authors:** Yiming Du, Yuxin Jiang, Tao Yuan, Jianbo Dai, Shaowei Wang, Jierun Chen, Chaofan Tao, Xianzhi Yu, Lifeng Shang, Kam-Fai Wong, Xiaohui Li, Haoli Bai — *CUHK / Huawei Noah's Ark Lab*
**Links:** [arXiv:2608.17393](https://arxiv.org/abs/2608.17393) · [HF](https://huggingface.co/papers/2608.17393) · [AlphaXiv](https://www.alphaxiv.org/abs/2608.17393)
**Topics:** `agents`, `RL`, `systems`

### TL;DR

A **harness-native RL** framework for coding agents that leaves the harness's control flow untouched. Three pillars: (1) in-process LLM proxying for token-level trainer/rollout alignment, (2) scalable sandbox orchestration with image caching and reward-hacking defences, (3) integrated plugin + live UI for training observability.

### Key idea

Rather than build a "clean" RL environment that mimics a coding harness, wrap the real one via an **in-process LLM proxy** that captures raw generation streams. The trainer recomputes log-probs from the exact bytes the harness produced, so tokenisation quirks / compaction / re-serialisation can't decouple rollout from update — measured train-inference correlation stays above 0.99. Sandbox orchestration pre-caches Docker layers and stages defences against reward hacking (e.g. test tampering, filesystem inspection).

### Main finding

Training Qwen3.5-35B-A3B with **GSPO** across three coding harnesses on SWE-bench Verified:
- **OpenHands SDK:** 64.0 → **70.4**
- **Claude Code:** 62.4 → **68.2**
- **OpenCode:** 57.2 → **66.6**
Rollout/training log-prob correlation **> 0.99** throughout.

### Why it matters

Complement to Agent Lightning (paper #7): where AL provides a lightweight paradigm, LEGO-RL solves the plumbing that breaks when you scale to real harnesses (compaction, sandbox scale, reward hacking). Together they define the operating envelope for harnessed agentic RL.

## 12. Energy-Guided Flow Matching

**Authors:** Haoyang Tong, Yu He, Fang Li, Lichen Ma, Jingling Fu, Dong Chen, Zhen Chen, Junshi Huang, Jie Cao — *JD.com / independent*
**Links:** [arXiv:2608.05811](https://arxiv.org/abs/2608.05811) · [HF](https://huggingface.co/papers/2608.05811) · [AlphaXiv](https://www.alphaxiv.org/abs/2608.05811)
**Topics:** `diffusion`, `flow-matching`

### TL;DR

Standard flow matching interpolates between noise and a **fixed clean image**, leaving coarse-to-fine spectral evolution implicit. EG-FM replaces the fixed endpoint with a **heat-kernel-filtered target that evolves from low- to high-frequency**, scheduled per-image by an energy metric. Backbone and data are untouched.

### Key idea

Move the *endpoint*, not the sampler. At each training step the target is a smoothed version of the clean image whose blur strength depends on both the flow-time and an image-specific energy signal. This makes the velocity field explicitly re-target toward finer detail late in the trajectory — a coarse-to-fine curriculum baked into the loss.

### Main finding

- **ImageNet 256² class-conditional:** FID **1.55 @ 200 epochs**, **1.45 @ 600 epochs**.
- **ImageNet 512²:** FID **1.58** after only 40 high-res adaptation epochs.
- **Text-to-image transfer:** GenEval **0.85**, DPG-Bench **83.9**.

### Why it matters

Pixel-space generative models want the frequency curriculum that latent diffusion gets "for free" from VAE compression. EG-FM shows you can inject that curriculum via the endpoint schedule without changing the network — a drop-in improvement for any flow-matching pipeline.

**Suggested new pages:**

## 13. HarnessRisk

**Authors:** Yajing Bai, Jinhao Duan, Jie Peng, Xianfeng Wu, Sijia Liu, Song Wang, Tianlong Chen — *UNC / MSU / U-Delaware*
**Links:** [arXiv:2608.17597](https://arxiv.org/abs/2608.17597) · [HF](https://huggingface.co/papers/2608.17597) · [AlphaXiv](https://www.alphaxiv.org/abs/2608.17597)
**Topics:** `safety`, `agents`, `eval`

### TL;DR

A lifecycle-oriented safety benchmark for **agent harnesses**: 128 sandboxed cases across six operational phases (Configuration, Capability Extension, Runtime, State Persistence, Action Control, Incident Recovery), each pairing a benign user goal with an adversarial instruction in an untrusted workflow artifact. Attack success ranges **12.6%–80.9%** while utility stays 75–98%.

### Key idea

Existing agent-safety benchmarks measure single attacks (prompt injection, tool misuse). HarnessRisk measures the **phase in the harness lifecycle** in which the failure occurs, exposing that different harnesses fail at different points — most notably **Harness Configuration** (setting security-sensitive parameters through otherwise authorised flows) is the most vulnerable phase across all three harnesses tested.

### Main finding

- Attack success **12.6% → 80.9%** depending on model+harness combo.
- Utility remains 75–98% under attack — attackers rarely need to break the agent to breach it.
- **Detection ≠ safety**: some configurations flag risks in >90% of runs yet still succumb at high rates.

### Why it matters

As agents move from demos into deployment, the *harness* is a bigger attack surface than the model. HarnessRisk names the phases where safety work needs to concentrate and provides a comparable benchmark for harness hardening — a category that didn't have one.

## 14. Abra

**Authors:** Kyle Chickering, Wei-An Lin, Swayam Bhanded, Dan Saunders, Akshat Tripathi, Jiaming Song, Shyamal Buch, Xinchen Yan — *Adobe / Stanford*
**Links:** [arXiv:2608.17286](https://arxiv.org/abs/2608.17286) · [HF](https://huggingface.co/papers/2608.17286) · [AlphaXiv](https://www.alphaxiv.org/abs/2608.17286)
**Topics:** `diffusion`, `scaling-laws`, `flow-matching`

### TL;DR

A Chinchilla-style scaling-law study for **text-to-image diffusion (flow-matching transformer)**, sweeping $10^{19}$–$10^{22}$ FLOPs. Result: diffusion scales *as predictably* as LLMs, but the compute-optimal ratio is very different — **~200 image tokens per parameter, ~10× the Chinchilla LLM ratio**. Diffusion is robust to overtraining; err toward more data, not more parameters.

### Key idea

Build a controlled DiT-family (Abra) whose only free parameters are width/depth/data and run a systematic sweep three orders of magnitude in compute. Fit both loss and downstream generative quality against parameter/token allocation. Show that not just loss but **optimal CFG, representation quality, and even training-curve *shape* collapse onto a universal form** given the compute budget.

### Main finding

- Compute-optimal ratio: **~200 tokens/parameter** (vs 20 for LLMs).
- Diffusion tolerates massive overtraining without quality loss.
- Optimal CFG, representation quality, and training-curve shape are all *predictable* from the compute allocation.

### Why it matters

Reallocates the field's implicit belief that image models should be scaled parameter-first. If the Chinchilla-for-diffusion ratio really is 10× data-heavier, every open-weight image-model release should ship at a very different aspect ratio than they currently do — with predictable quality wins.

## 15. MathForm

**Authors:** Lushi Pu, Weiming Zhang, Xinheng Xie, Zixuan Fu, Bingxiang He, Hengyu Zhao, Hongya Lyu, Xin Li, Jie Zhou, Yudong Wang — *Tsinghua / Alibaba*
**Links:** [arXiv:2608.14221](https://arxiv.org/abs/2608.14221) · [HF](https://huggingface.co/papers/2608.14221) · [AlphaXiv](https://www.alphaxiv.org/abs/2608.14221)
**Topics:** `reasoning`, `agents`, `data`

### TL;DR

Mathematical autoformalisation (NL → Lean 4) framework with two moves: (1) a **retrieval planner** that surfaces relevant Mathlib definitions before generation, and (2) **verification-guided iterative refinement** using Lean compiler diagnostics + semantic consistency feedback. Yields **FormalVerse**, a 367K-example verified Lean 4 dataset, then trains an **8B model** that beats specialised 32B autoformalisers.

### Key idea

Separate *library grounding* (retrieval) from *translation* (generation), and close the loop with the *actual compiler*. The retrieval planner assembles a working library subset; the generator translates; Lean checks; failures feed back for refinement. Verification-derived training data is high-signal because it's certified — every accepted example is provably syntactically valid and semantically consistent.

### Main finding

- **FormalVerse:** ~367K verified NL→Lean 4 examples.
- **MathForm-8B:** Pass@8 **88.06%** Syntax Check, **72.37%** Consistency Check on average across 6 benchmarks — beats multiple 32B specialised autoformalisers.
- **FATE-H / FATE-X:** CC pass **63% / 37%**, best-in-class on the hardest subsets.

### Why it matters

Formal-math datasets are the current bottleneck for RL-verified reasoning. A verification-in-the-loop pipeline that scales to 367K certified examples changes the ceiling for tools like DeepSeek-Prover, Lean Copilot, and any RLVR pipeline using Lean as the verifier.
