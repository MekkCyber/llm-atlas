## 1. ScienceIDE

**Authors:** Hejia Geng, Zesen Huang, Haoyang Li, Wenbin Li, Koutian Wu, et al. — *Multi-institution consortium (~45 authors)*
**Links:** [arXiv:2609.19134](https://arxiv.org/abs/2609.19134) · [HF](https://huggingface.co/papers/2609.19134) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.19134)
**Topics:** `agents`, `RL`, `data`

### TL;DR

An infrastructure paper that turns real scientific code repositories into gym-style environments where agents can be trained with RL. Scientific code encodes decades of domain knowledge but has fragmented toolchains and specialized correctness criteria — ScienceIDE wraps this so agents get *executable* experience against real research code rather than synthetic tasks. Ships with a trained model family.

### Key idea

Reframe the "hard to gather scientific agent training data" problem as an *environment* problem, not a demonstration problem. Instead of collecting scientific trajectories, wrap existing scientific codebases in a common IDE-shaped interface with implicit-convention adapters and domain-specific verifiers, so RL rollouts against real code become the training signal.

### Main finding

Produces a trained model family evaluated on scientific-agent benchmarks. Numbers not fully quoted in abstract; the primary claim is that agents trained *inside* scientific environments beat agents trained on abstracted or synthetic scientific tasks.

### Why it matters

If the pattern holds, "scientific reasoning" becomes bottlenecked by environment engineering, not by exotic training tricks. Same recipe that made coding agents work (SWE-bench-style repo environments) applied to research code — turns the world's open-source science into free reward signal.

## 2. SP³O — Value Flattening in PPO

**Authors:** Yizhuo Li, Jianhao Yan, Yun Luo, Zhi Wang, Futing Wang, Rong-Xi Tan, Kanghui Tian, Ganqu Cui, Ning Ding, Peilin Zhao, Yafu Li, Yu Cheng — *CUHK / Tencent / Shanghai AI Lab*
**Links:** [arXiv:2609.18708](https://arxiv.org/abs/2609.18708) · [HF](https://huggingface.co/papers/2609.18708) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.18708)
**Topics:** `RL`, `post-training`, `PPO`

### TL;DR

Identifies **Value Flattening**: in PPO for LLMs, ground-truth values estimated from multiple Monte Carlo continuations vary sharply across intermediate response states, yet the trained critic's predictions stay comparatively flat. Attributes this to an implicit variance penalty in the critic loss plus redundant gradient signal from temporally correlated states. Proposes **SP³O** (Sparse PPO): supervise the value loss on only a few well-separated states per response — three is enough — and the critic learns to track the true value curve.

### Key idea

The dense per-token critic loss in PPO is not benign: temporally adjacent states have highly correlated gradients that average toward the mean, producing a smoothed critic. Sparsifying the value supervision to a handful of anchor states per response breaks the correlation and restores fidelity, without changing the policy loss.

### Main finding

On Qwen3-Base at multiple sizes, supervising the critic on only ~3 states per rollout closes the flattening gap and improves downstream policy performance across evaluation suites. Reproduced in a controlled FrozenLake environment where the effect scales with state-space size.

### Why it matters

PPO-for-LLMs is under sustained attack from value-free methods (GRPO, DPO), largely because the critic is seen as expensive and unreliable. This paper says the critic isn't broken — it's over-supervised. A near-free fix (sample 3 states per rollout instead of all of them) restores PPO's advantage-estimation quality and, potentially, its edge in reward-model RL where GRPO's return-baseline doesn't fit.

## 3. XConf — Experiential Confidence Estimation

**Authors:** Caiqi Zhang, Xiaochen Zhu, Chengzu Li, Yulong Chen, Dharshan Kumaran, Nigel Collier — *University of Cambridge*
**Links:** [arXiv:2609.17708](https://arxiv.org/abs/2609.17708) · [HF](https://huggingface.co/papers/2609.17708) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.17708)
**Topics:** `reasoning`, `eval`, `agents`

### TL;DR

Existing confidence estimators read only the *current* inference — introspection, token probabilities, or resampling. XConf estimates confidence by consulting the model's *own past graded episodes*: a memory of (task, reflection, stated confidence, outcome, lesson). At inference, a Recall stage retrieves similar past episodes with similar stated confidence and reads their historical success rate; a Reflect stage shows the model this record and asks for a track-record-informed confidence.

### Key idea

Calibration as *retrieval over the model's own history*, not introspection over the current forward pass. The estimator is format-general (no logit access, no weight updates) and costs only one extra generation vs many-sample self-consistency.

### Main finding

Across 9 benchmarks × 4 models × 3 families: matches or beats 10-sample self-consistency AUROC on 23/24 comparisons with much lower ECE, at 1/10 the generation cost. In agent selective prediction, abstaining on the least-confident 10% raises delivered success rate by up to 8.7 points.

### Why it matters

Self-consistency has been the cheap-and-strong baseline for calibrated LLM outputs since 2022. If a single-generation, memory-based approach dominates it at agent scale, the calibration story for deployed agents changes: memory of the model's past deployment behavior becomes a first-class alignment artifact, not just a helpful log.

## 4. ProgramDistill

**Authors:** Jeonghye Kim, Minseon Kim, Young Jin Kim, Matheus Pereira, Marc-Alexandre Côté, Alessandro Sordoni, Xingdi Yuan, Zhengyan Shi — *Microsoft / MSR Montréal*
**Links:** [arXiv:2609.18805](https://arxiv.org/abs/2609.18805) · [HF](https://huggingface.co/papers/2609.18805) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.18805)
**Topics:** `eval`, `agents`, `data`

### TL;DR

Coding-agent benchmarks normally give agents an issue or spec; ProgramDistill instead gives agents a *working reference application* and asks them to infer and reimplement its behavior into an incomplete copy. Their pipeline (mine-craft-patch) discovers 1,975 replay-verified behaviors across 26 apps and constructs 4,063 tasks without human annotation.

### Key idea

Factorize an application into *replayable behaviors* at multiple granularities, each with a gold patch. This yields a controlled difficulty knob (restoration depth): remove 1 vs 8 features and measure how completion falls.

### Main finding

On 9 frontier coding agents: GPT-6 Astra and Claude Opus 5 hit 49.2% / 28.8% on full-application reconstruction; success drops from 100% → 64.0% (Astra) and 96% → 32% (Opus 5) as restoration depth increases from 1 to 8.

### Why it matters

SWE-bench-style benchmarks have saturated at the "resolve an issue" granularity. ProgramDistill introduces a scalable, human-labeled-free way to generate coding tasks with controllable depth — a natural basis for curriculum RL post-training (the paper explicitly notes this).

## 5. Agora

**Authors:** Yifan Zhang, Yunheng Zou, Shaokun Zhang, Jian Hu, Hao Zhang, Binfeng Xu, Jan Kautz, Yi Dong — *NVIDIA + collab*
**Links:** [arXiv:2609.18094](https://arxiv.org/abs/2609.18094) · [HF](https://huggingface.co/papers/2609.18094) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.18094)
**Topics:** `agents`, `systems`, `data`

### TL;DR

A shared-memory protocol for autonomous research agents: every claim (result, insight, hypothesis, verification, report) is an immutable Git commit with parent edges naming what it builds on. A derived index exposes the frontier, neglected branches, and per-claim verification status; a diversity-aware selection rule prevents mode collapse onto one "leader". Demonstrated on a 12-day run: 13 LM workers, no assigned tasks, no central planner, weight-transfer problem.

### Key idea

Reuse Git — content-addressed, append-only, diff-native — as the substrate for multi-agent research memory. Each agent's outputs are commits; the graph *is* the coordination signal. Verification and reproducibility fall out of "check out and rerun the commit".

### Main finding

The 13-worker swarm published 1,703 contributions and drove eval from 3.39 → 1.899 bits per byte on a weight-transfer task (init a frozen 119.6M attention-SSM hybrid from 141 pretrained donors, no training data, no gradients), closing 62% of the gap to a trained GPT-2 124M. Winning recipe: compress donor next-token stats into embedding + output head, add sparse edits to attention/FFN/SSM blocks. 165 independent reproductions posted, none failed.

### Why it matters

Multi-agent research systems have been idea-rich but coordination-poor — most reduce to N independent single-agents that redo each other's work. Agora is the first system to demonstrate a substrate where marginal agents produce marginal *new* discoveries at scale, with an audit trail cheap enough to reproduce every claim.

## 6. ActionPiece

**Authors:** Shijie Lian, Bin Yu, Zhaolong Shen, Xiaopeng Lin, Yichao Du, Zhirui Zhang, Laurence T. Yang, Kai Chen — *HUST / HKUST-GZ*
**Links:** [arXiv:2609.18487](https://arxiv.org/abs/2609.18487) · [HF](https://huggingface.co/papers/2609.18487) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.18487)
**Topics:** `multimodal`, `VLA`, `tokenization`

### TL;DR

VLA action tokenizers are typically judged by pointwise MSE, but low MSE is compatible with *relational collapse*: similar actions all round to one codeword and the context-dependent adjustments a policy needs get erased. ActionPiece introduces **Physical Rank Consistency (PRC)**: does the tokenizer preserve near/far distance rankings between actions after reconstruction? Adds a supervision term that enforces PRC in both the encoder and the quantized codebook.

### Key idea

Action tokenizer fidelity is *relational*, not pointwise. Add rank-preservation objectives on encoder distances and on codeword assignment distributions, alongside standard reconstruction, so nearby physical actions stay nearby in token space.

### Main finding

Under fixed Qwen3-VL-4B policy training: 94.8% on LIBERO, 68.8% on unseen LIBERO-Plus, 71.9% on SimplerEnv, 51.5% across VLA-Arena L0–L2. Ablations confirm PRC and policy success rise together.

### Why it matters

Points at a class of *silent* failures in the VLA stack: an action tokenizer can look great on MSE and be quietly destroying the fine-grained motor control the policy is trying to learn. Rank-based fidelity should join reconstruction as a standard tokenizer diagnostic.

## 7. VC-Attention

**Authors:** Xingyang Li, Dongyun Zou, Shining Zhang, Jiacheng Chen, Haocheng Xi, Lvmin Zhang, Jun-Yan Zhu, Song Han, Zhekai Zhang, Yujun Lin, Muyang Li — *MIT / NVIDIA / CMU*
**Links:** [arXiv:2609.15810](https://arxiv.org/abs/2609.15810) · [HF](https://huggingface.co/papers/2609.15810) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.15810)
**Topics:** `quantization`, `efficient-inference`, `attention`

### TL;DR

Training-free low-bit attention for Diffusion Transformers. Two contributions: (1) **V-Smooth** — value outliers, unlike Q/K outliers, follow no fixed channel or spatiotemporal structure. Reorder value tokens by lightweight online clustering so a hardware block quantizes well together; quantize only the residual after subtracting the block mean and restore the mean from the row sum already maintained by online softmax. (2) **ExpCast-FP8** — the FP32 exponential between the two low-bit matmuls in softmax attention becomes the longest pipeline stage; ExpCast maps log-domain scores directly to E4M3 probability codes with one fused multiply-add.

### Key idea

Address the two bottlenecks of low-bit attention separately: outliers in V (V-Smooth) and the FP32 exponential in softmax (ExpCast). Both are training-free and preserve mathematical correctness up to quantization noise.

### Main finding

Applied to Wan2.2, LongCat-Video, HunyuanVideo-1.5, MiniMax-H3. Kernel speedup over BF16 FlashAttention-4: 1.46–1.59× on Blackwell/Hopper datacenter GPUs, 2.3–3.6× on RTX PRO 6000 / RTX 5090. End-to-end clip generation: 1.13–1.19× (datacenter) and 1.36–1.70× (workstation). Fidelity beats prior low-bit baselines.

### Why it matters

FP8/FP4 attention is the last frontier for DiT serving cost. Prior work smoothed Q/K but left V outliers as the accuracy floor; the softmax exponential quietly became the compute floor now that Tensor Cores accelerate the matmuls. VC-Attention removes both, and does it training-free — meaning it drops into existing diffusion serving stacks.

## 9. SpectralShift

**Authors:** Zian Liu, Yiwen Hu, Zican Dong, Tian Xie, Wayne Xin Zhao, Yucheng Ding, Ran Tao, Bryan Dai — *RUC (Renmin U. of China)*
**Links:** [arXiv:2609.14320](https://arxiv.org/abs/2609.14320) · [HF](https://huggingface.co/papers/2609.14320) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.14320)
**Topics:** `architectures`, `long-context`, `SSM`

### TL;DR

Long-context extension of linear-attention models (Gated DeltaNet) needs to modify the layers themselves — spectral properties of the state-transition matrix decide what dependency lengths the layer can reach. Two conditions govern retrieval: a broad enough *slow* spectral band matching target dependency length, and preservation of *fast-decaying* modes for state clearing / context switching. SpectralShift reparameterizes the α-projection initialization and adds a per-α learning-rate scaling.

### Key idea

Linear-attention context extension is fundamentally spectral, not just data-scaling. Fix the decay-eigenvalue distribution at init (shift the slow band toward the target length) and treat α-projections as a distinct optimization group.

### Main finding

On Gated DeltaNet with continual pretraining, SpectralShift consistently improves long-context capabilities over standard extension. Specific benchmark numbers not in the summary excerpt.

### Why it matters

Linear-attention layers are increasingly used in hybrid stacks (Mamba/DeltaNet + attention) as a cheap long-context path. This paper says naive continued pretraining underuses them; a targeted spectral fix at init is a near-free win. The framing — spectrum of the transition matrix as the governing quantity — will likely generalize to other SSM/linear-attention families.

## 10. ComPO — Zeroth-Order Preference Alignment

**Authors:** Peter Chen, Xi Chen, Wotao Yin, Tianyi Lin — *Columbia / Alibaba DAMO*
**Links:** [arXiv:2609.19144](https://arxiv.org/abs/2609.19144) · [HF](https://huggingface.co/papers/2609.19144) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.19144)
**Topics:** `post-training`, `preference`, `DPO`

### TL;DR

DPO-family methods struggle with **likelihood displacement** on preference pairs with small margins — the loss can push the preferred completion's likelihood *down*. ComPO (Comparison-based Preference Optimization) sidesteps this: use only a **comparison oracle** (which of two is preferred) and extract *directional* update information via zeroth-order optimization, without differentiating a preference loss on the pair. Also introduces an online variant that uses unlabeled policy generations for reverse-KL control.

### Key idea

If the preference loss is misspecified for small-margin pairs, don't try to fit a differentiable loss — treat preference as a comparison oracle and estimate directions with zeroth-order (finite-difference) updates. Convergence guaranteed under smoothness, gradient sparsity, and oracle-compatibility.

### Main finding

Experiments on Mistral, Llama, Gemma-2, Qwen3, Gemma-3: improved length-controlled win rates over DPO and other direct alignment methods. Pair-level diagnostics show evidence consistent with mitigating likelihood displacement.

### Why it matters

Likelihood displacement is DPO's most documented pathology, and existing fixes (SimPO, KTO, DPO-Positive) modify the loss shape. ComPO argues the loss itself is the wrong tool for pairs where a first-order signal doesn't exist, and provides a principled zeroth-order path with convergence theory. If it holds up, this reframes what "preference optimization" should look like at all.

## 12. MoE Memory Peaks

**Authors:** Shrey Pandit, Xuan-Phi Nguyen, Yiran Zhao, Shafiq Joty — *Salesforce Research*
**Links:** [arXiv:2609.14306](https://arxiv.org/abs/2609.14306) · [HF](https://huggingface.co/papers/2609.14306) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.14306)
**Topics:** `systems`, `MoE`, `long-context`

### TL;DR

Long-context MoE training hits OOM on *whichever* peak spikes first — average memory is a distractor. Identifies four peaks left unbounded by standard parallelism plans: expert dispatch, vocabulary projection, activation-checkpoint boundaries, optimizer state. Each grows differently. Introduces four surgical fixes:

- **PipelinedLLEP** caps tokens per source per dispatch chunk (expert dispatch).
- **Ring-DTP** shards the vocabulary projection around a ring with an online log-sum-exp.
- **Selective Checkpoint Offload (SCO)** keeps each checkpoint boundary's one long-lived tensor on CPU.
- **OffloadStreamAdamW** turns the serial CPU Adam update into a bucket pipeline.

All four preserve exact gradients — only order and granularity change.

### Key idea

Memory optimization on MoE is a *multi-peak* game. Address every peak in-place with a launch-time-bounded working set; never trade correctness for space.

### Main finding

Component tests: MoE dispatch peak −59.3% (no throughput loss), vocab projection peak −86.6%, offloaded optimizer step 2.05× faster. Composed on 120B–667B MoEs: trains at **1M-token context**, 8–32× the reach of a tuned FSDP2 baseline, up to 10.4× throughput.

### Why it matters

Long-context MoE training has been the bottleneck for frontier open-source models (DeepSeek-V3, Llama 4). This paper is the first to systematically enumerate the peaks and give an exact-gradient fix for each. Should become a standard reference for how MoE training is scaled.

## 13. Edge0

**Authors:** Yu Lin, Yiming Wang, Runyuan Cai, Hanze Liu, Xiaodong Zeng — *Affiliation not disclosed on HF page*
**Links:** [arXiv:2609.18063](https://arxiv.org/abs/2609.18063) · [HF](https://huggingface.co/papers/2609.18063) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.18063)
**Topics:** `inference`, `MoE`, `systems`

### TL;DR

Streaming MoE inference from SSD on consumer hardware. Naive offload fails because layer N+1's expert set can only be chosen *after* layer N's output — you can't start reading experts early enough to hide behind compute. Edge0 adds a **prerouter**: a per-layer head predicts the next layer's routing one token ahead, and its prediction *is* the routing, so the staged expert set equals the routed set. A small unmerged recovery LoRA (trained on the student path) restores int4 quantization and routing-replacement quality.

### Key idea

The dependency chain "routing → expert reads" prevents overlap. Break it: predict routing one layer ahead, so reads and compute can overlap. Pay for the prediction error with a tiny LoRA that patches accuracy back.

### Main finding

On a single 24GB machine: 35B MoE at **20 tok/s** with **3 GiB peak active memory**, within a few points of the fp16 teacher across 5 public benchmarks. 8B tier runs on the same framework. Framework and adapters open-source.

### Why it matters

MoE inference has been "GPU-only" for anything above ~14B active parameters. Edge0 is a proof that trained *routing prediction* can move MoEs onto consumer hardware without a giant quality tax — the missing systems piece for on-device MoE serving.

## 14. CERA-MoA

**Authors:** Jiaxuan Jiang, Liyuan He, Zhixuan Fang — *Tsinghua*
**Links:** [arXiv:2609.18779](https://arxiv.org/abs/2609.18779) · [HF](https://huggingface.co/papers/2609.18779) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.18779)
**Topics:** `agents`, `MoE`, `routing`

### TL;DR

Mixture-of-Agents systems typically freeze the router while fine-tuning agents (or vice versa), so routing can't track agent-capability drift. CERA-MoA co-evolves the two in an iterative RL loop. A **predictive familiarity estimator** uses mid-layer hidden states to score which agent is competent for a query without full rollouts; a **cumulative-threshold adaptive routing** activates the minimal agent subset that clears the confidence threshold. Training samples are proactively steered to agents by their evolving competence.

### Key idea

Router and agents are one system, not two. Co-training breaks the static-router bottleneck; using hidden states as a cheap competence proxy avoids the rollout tax normally paid by MoA routers.

### Main finding

Outperforms static-router and fixed-workflow MoA baselines across domains.

### Why it matters

MoA is the LLM analogue of MoE — many models, sparse routing. CERA-MoA is the first co-training recipe of that flavor to appear at LLM scale, and its hidden-state competence estimator is a nice reusable primitive.

## 15. Fathom

**Authors:** Vivek Kalyanarangan — *Independent*
**Links:** [arXiv:2609.17652](https://arxiv.org/abs/2609.17652) · [HF](https://huggingface.co/papers/2609.17652) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.17652)
**Topics:** `inference`, `KV-cache`, `long-context`

### TL;DR

For long-context agentic decoding with offloaded KV, the top-k key scan (used to select which cached keys to attend to) dominates host↔GPU bandwidth. Fathom stores the 4-bit K cache **channel-major as bit planes**, so a prefix of t planes is exactly the t-bit quantizer of that channel. Each query decides *per-channel* how many bit planes to read via reverse water-filling over variance-weighted channel importance.

### Key idea

Bit-plane layout makes the K cache a *variable-precision* store where a query can dial in exactly how many bits per channel it needs, subject to a byte budget. Different queries want different precisions on different channels — Fathom is the first sparse-decoder to expose that knob.

### Main finding

On Qwen3-8B at 1M tokens: 1.67× faster decode step in GPU time than Double Sparsity, Loki, and SparQ (r=32) at 136-bit scans. At matched GPU time as SparQ-68-bit (r=16), Fathom reads 18% fewer bytes with lower attention error on 6/7 model+context settings. On RULER-style tasks, exactly matches full top-k; on real coding-agent sessions, hits the accuracy of the best 136-bit scan at only 92 bits. Reuses the 4-bit K copy a quantized stack already holds.

### Why it matters

Long-context KV offload is the next serving wall: 1M-token sessions blow past HBM budgets. Fathom is a rare instance of a technique that is *both* cheaper *and* more accurate than the incumbents, and it does so by turning the K cache into a variable-precision store — a design pattern that will likely generalize (V cache, activation offload).
