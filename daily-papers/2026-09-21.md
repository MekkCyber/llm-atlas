## 1. CodeMidas: Scaling Agentic Coding RL Environments from Code Itself

**Authors:** Bowen Ye, Lei Li, Shicheng Li, Zihao Yue, Linghao Zhang, Hanglong Lv, Yuanxin Liu, Wenhan Ma, Hao Tian, Rang Li, Jinhao Dong, Yikai Zhao, Xiangwei Deng, Hailin Zhang, Liang Zhao, Qi Liu, Lingpeng Kong, Tong Yang, Fuli Luo — *Xiaomi (MiMo team) with academic collaborators*
**Links:** [arXiv:2609.22068](https://arxiv.org/abs/2609.22068) · [HF](https://huggingface.co/papers/2609.22068) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.22068)
**Topics:** `agents`, `RL`, `code`, `RLVR`

### TL;DR

A pipeline that mines any open-source repository — not just its issues or commits — for RL-ready coding tasks. CodeMidas has an agent read implemented functionality, invent behavioral specs, generate execution-grounded tests, then filter through rollouts. The result is 5,545 verifiable tasks across 23 languages that lift MiMo-V2.5 substantially on issue repair, whole-program construction, and terminal work when trained with GRPO.

### Key idea

Treat *source code itself* as the RL substrate. An agentic pipeline is spent up front to turn plain source into (task prompt, tests, gold solution) triples: agents explore the codebase to formulate specs, write tests grounded in executing the original code, and filter tasks by whether repeated solution rollouts pass the tests. This decouples RL-environment scale from PR/issue availability.

### Main finding

5,545 tasks from 3,185 codebases, spanning 23 languages and 15 domains. GRPO training on this set gives MiMo-V2.5 +11.7% on DeepSWE (issue repair), +17% on ProgramBench (whole-program construction), and +8.5% on Terminal-Bench v2.1. Trajectory analysis shows the trained agent explores more of the codebase and self-verifies more diversely.

### Why it matters

Coding-agent RL has been bottlenecked by verifiable tasks — issue/commit mining runs out of coverage. Sourcing tasks directly from arbitrary code turns "any GitHub repo" into an RL environment, and matches how frontier labs are scaling agent training without hitting the SWE-Bench-style ceiling.

## 2. Grounded Skill Synthesis from Code at Scale (Code2Skill)

**Authors:** Yongqi Tong, Pan Wang, Hang Wang, Jianshe Li, Xin Zhang, Jiang-Ming Yang, Wei Wu — *(multi-institution collaboration)*
**Links:** [arXiv:2609.05571](https://arxiv.org/abs/2609.05571) · [HF](https://huggingface.co/papers/2609.05571) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.05571)
**Topics:** `agents`, `skills`, `data`

### TL;DR

Code2Skill converts GitHub repositories into a bank of *executable-grounded* atomic operations, composite workflows, and recurring patterns, then verifies every record by reconstructing the source body from the record and comparing. Retrieval-augmenting eight benchmarks with the resulting bank (CodeSkillBank, ~1M records from ~20k repos) beats trajectory-derived skill banks on all shared benchmarks.

### Key idea

Two-stage verification: (1) *source-body-blind reconstruction* — regenerate the code from the record without seeing the original, (2) *source-aware comparison* — check equivalence against the original. Only records that survive both are kept. This is a document-derived skill bank whose grounding comes from executable code rather than prose.

### Main finding

CodeSkillBank contains 1,006,822 records from 19,769 repos. Across 72 protocol-matched evaluations (9 models × 8 benchmarks), retrieval augmentation gives +11.7% average lift over matched baselines. Skills mined from AI-generated code pass at 93.50% vs 93.00% for human-written code — the pipeline is essentially indifferent to author origin.

### Why it matters

Prior skill banks either need agent rollouts (expensive, environment-bound) or are text-only (ungrounded). Grounding on repository code is cheap, scalable, and provides executable evidence per skill. As AI-authored code accumulates in public repos, this pipeline mines it too, closing a self-improvement loop.

## 3. EvoOntology: A Self-Evolving Ontology Layer for Data Agents

**Authors:** Meiduo Chong, Shaolei Zhang, Ju Fan, Xiaoyong Du — *Renmin University of China*
**Links:** [arXiv:2609.15779](https://arxiv.org/abs/2609.15779) · [HF](https://huggingface.co/papers/2609.15779) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.15779)
**Topics:** `agents`, `MCP`, `data`

### TL;DR

Data agents (agents that answer natural-language questions over heterogeneous tables/files/DBs) usually see raw column names through generic tools, or a hand-built prompt-injected semantic layer. EvoOntology reifies the semantic layer as an MCP server with schema/content/tool sublayers, and lets the agent query it at runtime. A separate builder agent authors the ontology, and a self-evolution loop refines it via attribution-guided typed edits gated by paired evaluation.

### Key idea

Move the ontology from *prompt* to *tool surface*: expose schema, content, and helper tools through MCP so the agent can call ontology lookups on demand. Refinement is *attribution-guided*: track which ontology entries contributed to failed vs. successful runs, and propose typed edits that are only accepted if a backbone-conditional paired evaluation shows they help.

### Main finding

Consistently beats strong baselines and prior semantic-layer approaches on three data-agent benchmarks with four LLM backbones. The self-evolution loop monotonically improves the ontology across cycles.

### Why it matters

Data-agent quality lives or dies by how much semantic context the model has at query time. Prompt-injection scales badly; runtime queryable ontologies scale far better and give a natural place to attribute failures. MCP-native design also means the same ontology serves multiple agents.

## 4. RecreationWorld: Verifiable Environments for Hybrid Computer-Use Agents

**Authors:** Shuai Bai, Jiayong Deng, Sicheng Fan, Yikun Fu, Chang Gao, Xuhao Hu, Mianqiu Huang, Yizhen Jiang, Yuheng Jing, Dehui Kong, Keliang Li, Ning Li, Wanli Li, Dayiheng Liu, Dunjie Lu, Changwei Luo, Que Shen, Zheyuan Wang, Zijian Wang, Jie Wu, Gao Wu, Zhihui Xie, Rui Xie, Haiyang Xu, An Yang, Jiakang Yuan, Yanming Zhang, Jiajun Zhang, Xi Zhang, Zhenru Zhang, Zhuo Zhen, Mingkang Zhu, Bowen Zhou — *Qwen / Alibaba*

**Topics:** `agents`, `RL`, `eval`, `multimodal`

### TL;DR

Real computer-use work interleaves GUI interaction, code, and command line — but existing agents/benchmarks specialize in one. RecreationWorld defines *hybrid CUAs* and introduces the "recreation task" as a self-verifying environment: the agent produces an artifact, and its behavior is compared against a reference. Five platforms, 250 tasks (RecreationBench), and OOD gains on downstream benchmarks.

### Key idea

Use recreation — asking an agent to reproduce a known-good artifact — as the verifier for hybrid computer-use trajectories. Because the target artifact is available, the environment can be scaled without human labels for each new task, and running/visually verifying the artifact closes the RL reward loop.

### Main finding

RecreationBench spans 250 tasks across 5 platforms. Models trained on the environment improve on out-of-distribution CUA benchmarks; full-featured application generation remains an open frontier.

### Why it matters

GUI-only and code-only CUAs both hit ceilings when real jobs mix the two. Recreation tasks are a clever way to make hybrid environments *verifiable at scale* — reference artifacts double as reward signals — which is what RL post-training needs.

## 5. IntBMoE: Block-Level Conditioning for Full-Participation MoE

**Authors:** Ran Cheng, Longfei Xu, Zheng Liu, Kaikui Liu, Xiangxiang Chu — *AMap / Alibaba*
**Links:** [arXiv:2609.21346](https://arxiv.org/abs/2609.21346) · [HF](https://huggingface.co/papers/2609.21346) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.21346)
**Topics:** `MoE`, `architectures`, `sparse`

### TL;DR

Standard MoE couples three quantities — how many experts contribute knowledge (participation), how many are computed (execution FLOPs), and how many parameter sets exist (materialization memory). IntBMoE decouples all three via block-conditioned expert composition with Dual-Path Residual Gating, achieving *full participation* while keeping execution sparse and memory bounded. Deployed in AMap recommendation.

### Key idea

Introduce a block-level conditioning layer that composes expert-blocks into per-token effective experts, so *every* materialized expert contributes to every token (full participation) but only a sparse subset is actually executed. A residual "dual-path" gate keeps the effective mixture stable when only some experts fire.

### Main finding

+2.4% relative UVCTR in AMap online A/B testing. Ablations show the decoupling of participation from execution is the key lever — full participation without full execution is what buys the quality-cost tradeoff.

### Why it matters

Current MoE routing has an unavoidable *participation = execution* coupling: to have K experts contribute, you must compute K experts. IntBMoE reframes MoE as three axes (participation / execution / materialization), a distinction that suggests new design points beyond top-K.

## 6. OmniVChat: Native Audio-Visual Dialogue

**Topics:** `multimodal`, `audio`, `RL`, `eval`

### TL;DR

Defines the "OmniVChat" task — a user speaks and shows video simultaneously, and an omni model returns text — then supplies the three pieces needed to work on it: a data synthesizer (OmniVChat-Studio), a benchmark (OmniVChat-Bench), and an RL training recipe (OmniVChat-RL). Models trained on OmniVChat-Studio-synthesized dialogues match or beat baselines when evaluated on human-recorded audio-visual dialogues via OmniVChat-Bench, indicating the synthetic distribution is close enough to the real one to be useful for RL.

### Why it matters

Omni models still struggle to *natively* consume speech + video together in a conversation. A synthesis + bench + RL trio is the practical recipe for closing that gap, and matches how the field bootstrapped code and reasoning RL data.

## 7. Paint-Anything: Unified Any-Color Control for Image Generation and Editing

**Authors:** Ji Xie, Dewei Zhou, Xinyu Huang, Zhennan Chen, Xun Wang — *(affiliation not disclosed on abstract)*
**Links:** [arXiv:2609.20816](https://arxiv.org/abs/2609.20816) · [HF](https://huggingface.co/papers/2609.20816) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.20816)
**Topics:** `diffusion`, `multimodal`, `eval`

### TL;DR

Adds precise 24-bit hex color control to diffusion image generation and editing by (1) mining Paint-500K, an object-color-labeled dataset, (2) adding pure-color "anchor" samples only at high-noise timesteps to counteract shadow-induced label noise, and (3) unifying the interface across text-to-image and editing. On FLUX.2-4B, hex-color-fidelity scores jump +85.3% (T2I) and +28.3% (edit).

### Key idea

Two data tricks: (a) label real-image objects with perceptual colors + hex, tolerating shadow-induced approximation; (b) inject pure-color anchor tiles whose pixels *exactly* equal their hex label, but only at high-noise diffusion timesteps where global color is decided. The model learns hex semantics from anchors and photographic realism from natural images.

### Main finding

On FLUX.2-4B: ACBench-T2I +85.3%, ACBench-Edit +28.3% relative to the base model, and best average CompColor among compared methods. Ablations validate the timestep-gated anchor recipe.

### Why it matters

Designers already work in hex; making a T2I / edit model take hex directly cuts the "prompt → color-picker → prompt" loop. The timestep-gated data trick is a general recipe for injecting precise supervision without breaking natural-image aesthetics.

## 8. Designer-RSI: Evolving Procedural Memory for Graphic Design Agents

**Authors:** Hongyang Du, Lan Yan, Christian Flores, Asim Kadav — *(affiliation not disclosed on abstract)*
**Links:** [arXiv:2609.22086](https://arxiv.org/abs/2609.22086) · [HF](https://huggingface.co/papers/2609.22086) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.22086)
**Topics:** `agents`, `skills`

### TL;DR

For long-horizon graphic-design agent work (200+ tools, no programmatic oracle), Designer-RSI keeps the base model frozen and grows an external procedural memory of natural-language skills from user traffic. Across five rounds and 1,406 real briefs the skill bank goes from 76 to 139 procedures, and performance rises without any weight updates or human labels.

### Key idea

Treat "how to do X in the design tool" as a natural-language skill entry, extract these from live user sessions, and let the frontier model retrieve them at inference. Refinement is round-based: successful executions promote skills, failed ones trigger edits. Self-improvement without gradients.

### Main finding

76 → 139 skills over five rounds on 1,406 user briefs, with monotonically improving task outcomes. No labels, no fine-tuning. This is a concrete existence proof that procedural-memory RSI (recursive self-improvement) is a viable RL-free path for professional tool use.

### Why it matters

Two schools of agent improvement — SFT/RL on the model, and external memory around a frozen model — both scale, but the memory path avoids catastrophic-forgetting risk and works with closed-weights frontier models. Designer-RSI is one of the cleaner demonstrations at real product scale.

## 11. MoME: Mixture-of-Memory Embeddings for Context-Aware Sparse Lookup

**Authors:** Muchen Li, Leonid Sigal, Renjie Liao — *University of British Columbia*
**Links:** [arXiv:2609.15126](https://arxiv.org/abs/2609.15126) · [HF](https://huggingface.co/papers/2609.15126) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.15126)
**Topics:** `architectures`, `pre-training`, `sparse`

### TL;DR

Prior memory-embedding methods add a token-indexed lookup table (cheap parametric memory) but map each surface token to a single fixed row, collapsing polysemy. MoME replaces each row with a mixture of M slots and uses a learned gate over the hidden state to select which slots to read *in context*. Beats Value Embedding, Bigram, and STEM baselines iso-parameter and iso-FLOP on multiple backbones.

### Key idea

Take the "cheap parametric memory augmenting a backbone" story from Value Embeddings, but let the router live at the memory layer instead of trusting the surface token as the key. Each token → mixture of M memory rows, gated by hidden state. Same look-up cost per slot, with contextual disambiguation for free.

### Main finding

On nanochat, Llama-3/MobileLLM, and Qwen3 backbones, MoME wins iso-parameter and iso-FLOP comparisons at sub-billion scale, with a favorable memory-size scaling trend. Qualitative routing analyses show polysemous tokens (e.g. "python") dispatch to distinct slots by sense.

### Why it matters

Conditional-memory / value-embedding methods are an emerging class of sparse capacity distinct from MoE — sparser, cheaper, and more amenable to CPU/edge deployment. MoME turns a global limitation (context-agnostic keys) into a routed subsystem, mirroring what MoE did for FFN capacity.

## 12. Calibrated On-Policy Distillation (Cal-OPD)

**Authors:** Qiangqiang He, Jin Li, MingCai Chen — *(affiliation not disclosed on abstract)*
**Links:** [arXiv:2609.21619](https://arxiv.org/abs/2609.21619) · [HF](https://huggingface.co/papers/2609.21619) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.21619)
**Topics:** `post-training`, `distillation`, `reasoning`

### TL;DR

On-policy distillation learns from the token-level *teacher–student discrepancy*, but that discrepancy also picks up the teacher's own idiosyncrasies — not just the capability gap. Cal-OPD estimates the teacher's self-deviation region using positive/negative privileged interventions, then keeps only the discrepancy component outside that region. With just 52–65% of the original signal retained, it beats standard and privileged OPD on math reasoning across scales.

### Key idea

Estimate a "teacher-noise" region: how much does the teacher's next-token distribution shift under privileged vs. non-privileged conditioning? Everything inside that region is the teacher fidgeting; everything outside is real information. Calibrated OPD retains only the outside component as the distillation target.

### Main finding

Cal-OPD outperforms OPD and privileged-OPD variants on math benchmarks at multiple scales, while using only ~52–65% of the raw teacher–student discrepancy as the learning signal.

### Why it matters

OPD has become one of the workhorses for reasoning distillation (compact reasoners from big teachers). Cal-OPD's diagnosis — the signal is contaminated by teacher-specific noise — plus its causal-intervention fix, is the sort of correction that quickly diffuses across every OPD-based training pipeline.

## 13. When AI Reviews Train AI Reviewers: Judgment Collapse & TrustReviewer

**Authors:** Sy-Tuyen Ho, Minghui Liu, Furong Huang — *University of Maryland*
**Links:** [arXiv:2609.20942](https://arxiv.org/abs/2609.20942) · [HF](https://huggingface.co/papers/2609.20942) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.20942)
**Topics:** `safety`, `eval`, `interp`, `data`

### TL;DR

Trains a Llama-3.1-8B ICLR reviewer on 2018–2023 reviews, then fine-tunes successor models on 2024 data with varying mixes of official vs. model-generated reviews. Adding synthetic reviews *compresses rating distributions* and reduces semantic diversity — a scientific-judgment collapse. Mitigations: curated single-stage training + paired activation steering at test time.

### Key idea

Model-collapse-in-the-wild for peer review: as LLM-generated reviews enter training corpora, successor reviewers converge toward flatter, more homogeneous judgments. Two-stage fix: (1) *training-time* — curate a single-stage corpus that filters low-quality/degenerate supervision, (2) *test-time* — paired activation steering to counteract residual collapse without more data or labels.

### Main finding

Even a modest fraction of synthetic reviews measurably compresses same-paper and corpus-level review diversity. TrustReviewer's curated-training-plus-steering combination recovers diversity without sacrificing rating calibration.

### Why it matters

The "AI-in-the-loop of AI training" concern is usually discussed abstractly. This paper measures it on a real, high-stakes benchmark (peer review of ML papers) and shows both the failure mode and a practical mitigation stack. Activation steering as a *post-hoc* corrective for training-corpus contamination is worth watching.

## 14. HEAL: Head-Level Disentanglement for MLLM Hallucination

**Authors:** Meng'en Qin, Junye Chen, Jucheng Liu, Youlu Xing, Song Wang, Ruize Han — *(multi-institution)*
**Links:** [arXiv:2609.09206](https://arxiv.org/abs/2609.09206) · [HF](https://huggingface.co/papers/2609.09206) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.09206)
**Topics:** `interp`, `multimodal`, `safety`

### TL;DR

Attention-based hallucination mitigations look at attention *weights*, which don't cleanly reflect the information flowing through a head. HEAL instead disentangles per-head information via causal noise intervention and counterfactual Difference-in-Differences, discovering *synergy heads* whose information drift correlates with hallucination. It calibrates value vectors in those heads and reduces hallucinations across multiple MLLMs.

### Key idea

Two mechanistic moves: (1) *causal noise intervention* on multi-head outputs to filter out heads that don't causally matter; (2) *difference-in-differences* on the survivors to classify each head by information-flow type, revealing "synergy heads" — the ones that jointly consume visual and text streams. Hallucinations correlate with information-distribution drift in these heads, not with modality-specific ones. HEAL injects dynamic calibration factors into their value vectors.

### Main finding

Consistent hallucination reduction across multiple MLLMs, with a simple and interpretable intervention (edit value vectors of a specific head class) and no retraining.

### Why it matters

Most MLLM hallucination-mitigation work is empirical patchwork on attention weights. Grounding the fix in a causal per-head analysis gives a cleaner mechanistic story and a reusable diagnostic (synergy-head identification) that likely transfers to non-MLLM interp questions.

## 15. Geometry of Values: Task-Vector Composition for Ethical Alignment

**Authors:** Utkarsh Agarwal, Monojit Choudhury — *MBZUAI (inferred)*
**Links:** [arXiv:2609.21094](https://arxiv.org/abs/2609.21094) · [HF](https://huggingface.co/papers/2609.21094) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.21094)
**Topics:** `safety`, `interp`, `alignment`

### TL;DR

Builds a multilingual dataset of moral dilemmas that pit values against each other (Honesty vs. Justice, Justice vs. Autonomy, Autonomy vs. Honesty) in five languages, measures baseline biases, and shows that (1) SFT drives accuracy above 98% and (2) *orthogonalized task vectors* can steer models toward a specific value orientation at inference.

### Key idea

Compute task vectors for each value orientation, then *orthogonalize* pairs so that steering by one axis (e.g. push toward Honesty) doesn't accidentally push along another (Justice). The orthogonalized basis lets you compose value axes in vector space for controllable alignment.

### Main finding

Fine-tuning removes cross-lingual bias, taking accuracy on the value-conflict dilemmas to >98%. The task-vector orthogonalization steers models toward specific ethical orientations without retraining, offering a *geometric* handle on value alignment.

### Why it matters

Alignment work often treats "values" as a monolithic scalar (helpful/harmless). This paper makes the axes explicit, geometric, and *composable* — a step toward controllable, auditable value alignment rather than a single fine-tune.
