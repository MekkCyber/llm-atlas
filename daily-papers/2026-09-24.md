## 1. Hunyuan-A13B

**Authors:** Tencent Hunyuan Team (Ao Liu, Botong Zhou, Can Xu, Chayse Zhou, ChenChen Zhang, et al.) — *Tencent*
**Links:** [arXiv:2609.27284](https://arxiv.org/abs/2609.27284) · [HF](https://huggingface.co/papers/2609.27284) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.27284)
**Topics:** `LLM`, `MoE`, `RL`, `reasoning`

### TL;DR

Tencent's open-source A13B model: 80B total / 13B active MoE trained on 20T rigorously-filtered tokens with STEM-heavy curation. The novel deployment lever is a **dual-mode chain-of-thought**: the model dispatches routine queries through a "fast thinking" path and complex ones through a "slow thinking" long-CoT path, letting a single set of weights trade latency against depth without a router model.

### Key idea

A single MoE model exposes two reasoning regimes chosen at prompt time (or by internal difficulty estimation): fast for short chatty answers, slow for multi-step problems. This is trained via SFT + large-scale RL over both mode-labeled trajectories. Combined with 13B activation for high inference throughput, the model targets the "one model, two latency budgets" niche.

### Main finding

Competitive with much larger dense models across math, science, code, general language, and agent benchmarks while keeping active parameters at 13B. Tencent emphasizes throughput as the deployment story — dual-mode CoT is the mechanism to save tokens without giving up reasoning ceiling.

### Why it matters

Adds a serious open-weights entry to the "MoE + reasoning RL" cluster next to DeepSeek-V3 and Qwen3-A22B. The dual-mode CoT is a training-time answer to the "adaptive reasoning depth" problem that most systems currently solve with a separate router or a hard length cap.

## 2. SpeakerMem-R1

**Authors:** Haobo Zheng, Tan Tang, Yan Chen, Weijie Wang, Yingcai Wu — *State Key Lab of CAD&CG, Zhejiang University*
**Links:** [arXiv:2609.26780](https://arxiv.org/abs/2609.26780) · [HF](https://huggingface.co/papers/2609.26780) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.26780)
**Topics:** `agents`, `memory`, `RL`, `GRPO`

### TL;DR

An agent memory system designed for **multi-party dialogue** — chats with more than two speakers where "who said what about whom" matters. Stores each utterance twice: as speaker-labeled verbatim text and as person- and group-level derived state, then merges them at query time by entity/event/time. Trains the memory writer with a speaker-conditioned GRPO variant.

### Key idea

**Dual-track memory:** one track keeps raw speaker-attributed messages; the other track keeps LLM-derived state organized into person-level and group-level views. At query time both tracks are combined by matching entities, events, and timestamps. The state extractor is trained with **SpeakerLevenshtein** (an edit-distance reward that penalizes attribution errors) plus speaker-conditioned GRPO — variant reward and rollout structure tailored to who is being tracked.

### Main finding

47.9 / 69.2 / 61.9 binary accuracy on GroupMemBench / SocialMemBench / EverMemBench (+3.3, +12.4, +9.4 pts over the best mainstream agent-memory framework). 62.33 on the EverMemBench leaderboard (SOTA) and 70.85 on LoCoMo. RL raises the writer's mean accuracy from 57.4 → 68.2 under a frozen query pipeline.

### Why it matters

Most agent-memory work assumes a two-party chatbot. Multi-party is where relational state (A's model of B in the presence of C) becomes structurally different and where flat retrieval breaks. The paper shows that the fix is data-model + reward-shaping, not just bigger context.

## 3. Past Frames Future

**Authors:** Harold Haodong Chen, Rongjin Guo, Disen Lan, et al. — *HKUST-GZ / MBZUAI / multi-lab consortium*
**Links:** [arXiv:2609.28466](https://arxiv.org/abs/2609.28466) · [HF](https://huggingface.co/papers/2609.28466) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.28466)
**Topics:** `diffusion`, `video`, `memory`, `survey`

### TL;DR

A survey unifying memory mechanisms in **autoregressive video generation**. Formalizes memory as "persistent historical information that survives across outer AR steps and still affects future frames after the originating tokens leave the active context." Organizes the field along five axes: Forms (representation), Functions (what to keep), Operations (write/read/update lifecycle), Learning (training under rollouts), Evaluation.

### Key idea

Treat memory in video generation not as a monolithic buffer but as a lifecycle: **write → read → update → manage → integrate**, each with distinct failure modes. The framework lets the reader classify any memory-aware AR video system (Chris–Cross, Genie 3, world-model DiTs, etc.) by which lifecycle stages it addresses and which it punts on.

### Main finding

Not a benchmark paper; the contribution is the five-axis taxonomy plus an audit of open problems: composable memory architectures, trustworthy state updating, self-rollout learning, standardized evaluation. Positions video-generation memory as the same underlying problem as agent memory in LLM stacks.

### Why it matters

Autoregressive video and world-modeling papers were until recently one-off engineering. This survey is the first to give the community shared vocabulary that treats memory as a first-class subsystem — a prerequisite for the "long-horizon consistent world model" agenda everyone is chasing.

## 4. JitMem

**Authors:** Yefan Zhou, Yang Li, Zeyu Leo Liu, Semih Yavuz, Shafiq Joty — *Salesforce AI Research*
**Links:** [arXiv:2609.27334](https://arxiv.org/abs/2609.27334) · [HF](https://huggingface.co/papers/2609.27334) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.27334)
**Topics:** `agents`, `memory`, `RL`

### TL;DR

Instead of distilling completed trajectories into fixed memory artifacts at write time (workflows, reflections, skills), **JitMem retains raw trajectories and defers curation until read time**, when the current query is known. A learned curator synthesizes a compact task-adaptive payload on demand and is trained directly from the immediate task's success signal.

### Key idea

Moving memory curation from write time to read time inverts the credit-assignment problem. Write-time curators must guess what future queries will need, and their reward is delayed by many tasks. Read-time curators see the current query and are trained by a short-horizon success reward, sidestepping long-horizon credit assignment entirely.

### Main finding

Across **ALFWorld / WebShop / τ²-bench**, JitMem improves over the strongest write-time-memory baseline by **+16.2 / +16.3 / +3.9 absolute success-rate points**. Beats both no-memory agents and heuristic write-time systems.

### Why it matters

Reframes a core question in agent memory. If read-time curation reliably wins, the interesting design question is retrieval + on-demand summarization, not "what should we store." Bridges naturally to RAG-style architectures for agents.

## 5. RewardVerse

**Authors:** Zhenchen Tang, Yang Li, Songlin Yang, Bo Peng, Xiaotong Zhao, Shuai Li, Haotian Fan, Alan Zhao, Jing Dong — *Alibaba / CASIA*
**Links:** [arXiv:2609.22947](https://arxiv.org/abs/2609.22947) · [HF](https://huggingface.co/papers/2609.22947) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.22947)
**Topics:** `RL`, `reward-model`, `diffusion`, `video`

### TL;DR

Video generation RL needs a stable reward, but current video reward models produce a raw scalar that drifts across prompts. RewardVerse inserts an explicit **rubric** step: the reward model first generates evaluation criteria for the current prompt, then scores against them. A two-stage **Rubric-Guided Policy Optimization (RGPO)** algorithm co-trains rubric generator and scorer.

### Key idea

Turn scalar reward into a two-stage pipeline (`prompt → dynamic rubric → rubric-guided score`). The rubric acts as a semantic anchor that mitigates scalar drift — the collapse or shift of scoring scale across prompts. RGPO warms up the scorer with self-evolving seed rubrics, then jointly optimizes the rubric generator while keeping the scorer aligned to human ratings.

### Main finding

SOTA on both pointwise and pairwise evaluation on the 16-dimensional EvalVerse benchmark and external datasets. Directly attacks scalar drift, which they show empirically breaks other video RMs when used as an RL signal.

### Why it matters

Reward-model design for generative video was stuck at scalar regression from human ratings, which does not compose well with RL rollouts. Making the rubric explicit is the same move that helped text RMs (constitution → judge). Now video has a working recipe.

## 6. Schrödinger Repo

**Authors:** Silin Chen, Yufei Yang, Xiaodong Gu, Yuling Shi, Chengcheng Wan, Haibing Guan — *Shanghai Jiao Tong U. / Xi'an Jiaotong U. / East China Normal U.*
**Links:** [arXiv:2609.27891](https://arxiv.org/abs/2609.27891) · [HF](https://huggingface.co/papers/2609.27891) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.27891)
**Topics:** `eval`, `contamination`, `agents`

### TL;DR

Repository-level coding benchmarks (SWE-bench and cousins) are built from popular open-source repos that leak into pretraining. `SchrodingerRepo` applies four **functionality-preserving transformations** to a benchmark repo — problem-statement reconstruction, namespace remapping, intra-file layout reordering, semantics-preserving code rewriting — so any performance drop must come from lost memorization rather than lost reasoning.

### Key idea

Instead of building a fresh benchmark (expensive) or paraphrasing prompts (weak), transform *the repository itself* while preserving the exact fix required. The paper stacks four levels of transformation; each is designed to remove a distinct memorization surface (docs, names, layout, code style).

### Main finding

Model rankings on SchrodingerRepo shift meaningfully vs the original SWE-bench, revealing that a substantial fraction of "SWE-bench performance" is repository memorization rather than repo-reasoning capability. Provides the mechanism for a fair, refreshable version of any repo benchmark.

### Why it matters

The community treats SWE-bench as a fixed comparison surface, but the transform pipeline suggests it has been *partly* memorized by all frontier models. Refreshable benchmarks may become a norm — a natural next step after LiveCodeBench.

## 7. PACT

**Authors:** Jiayan Fu, Hang Xu, Yong Zhang, Zhaokai Luo, Yao Hu, Dongyan Zhao, Mu Chuan — *Peking U. / Xiaohongshu*
**Links:** [arXiv:2609.26355](https://arxiv.org/abs/2609.26355) · [HF](https://huggingface.co/papers/2609.26355) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.26355)
**Topics:** `RL`, `post-training`, `actor-critic`

### TL;DR

Formalizes **token-level credit assignment** for LLM RL by three regularity axioms (Completeness, Prefix Consistency, Neutrality) that uniquely determine it, then uses that lens to derive **Policy-Aligned Critic Training (PACT)**: an actor-first, critic-after update order that applies importance-sampling correction to critic learning so the critic tracks the updated policy.

### Key idea

Existing PPO/GAE trains the critic under the old policy and uses it to score updates for the new one, so critic error compounds when policies drift. PACT flips the order: update actor → correct critic via IS reweighting → repeat. Shows that on-policy distillation and RLOO signals are, in expectation, aligned with the axiomatic token-level credit. Approximate credit sparsity motivates the correction.

### Main finding

**+8.8 pts over GRPO and +13.2 pts over PPO** on agentic math (72.87% average across four benchmarks). **67.4% on SWE-bench Verified**, beating PPO / GRPO / SAO by 2.4 / 2.0 / 3.8 pts. Suggests critic-based methods are underrated once you fix the alignment problem.

### Why it matters

The community mostly abandoned actor-critic for GRPO because value networks were unreliable. PACT is a principled argument for bringing critics back, with numbers to match. Direct challenge to GRPO's status as the default.

## 8. GeoPair

**Authors:** Ammar Ali, Stamatios Lefkimmiatis — *MTS AI / ITMO University*
**Links:** [arXiv:2609.25963](https://arxiv.org/abs/2609.25963) · [HF](https://huggingface.co/papers/2609.25963) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.25963)
**Topics:** `quantization`, `compression`, `efficient-inference`

### TL;DR

A **training-free** post-hoc transformer compression scheme that pairs weight matrices *across layers* and factorizes each pair through a **shared dictionary** while preserving each layer's activation geometry. Replaces the heuristic "which layers to merge" step with a convergent optimization over pairing + factorization.

### Key idea

Recognize that cross-layer redundancy exists but layer-specific calibration geometries differ. The solution: (1) find structurally compatible projections between pairs of layers, (2) learn a shared basis, and (3) still respect each layer's distinct activation distribution. Coupled with structured sparsity, this compresses without any fine-tuning pass.

### Main finding

SOTA across "diverse architectures, scales, and modalities" — outperforms both independent structured-weight decomposition and heuristic pairwise factorization baselines. All post-training, no gradient updates required.

### Why it matters

Practical training-free compression is one of the few high-leverage inference cost knobs left after strong quantization has been applied. Cross-layer factorization has been a heuristic art; GeoPair puts it on an optimization footing.

## 9. Hidden CoT

**Authors:** Xiaoyu Luo, Tao Ren, Wenrui Yu, Xiao Li, Qiongxiu Li, Johannes Bjerva — *Aalborg U.*
**Links:** [arXiv:2609.26637](https://arxiv.org/abs/2609.26637) · [HF](https://huggingface.co/papers/2609.26637) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.26637)
**Topics:** `interp`, `reasoning`, `eval`

### TL;DR

Closed-source frontier models hide their raw chain-of-thought traces. This paper induces the model to externalize its intermediate reasoning by **registering a custom tool through the standard tool-use API** and treating tool-call arguments as the CoT surface. Validates that these traces are genuine (not post-hoc rationalization) on open models where native CoT is known, then applies the method to GPT-6 Astra and characterizes reasoning shape.

### Key idea

Frontier APIs expose tool calling as a general mechanism. Register a "reasoning" tool with a free-text argument, force it into the response path, and the model uses it as a CoT scratchpad. Cross-validation against open models with visible CoT shows the extracted reasoning matches native reasoning's task performance — evidence it's not fabricated after the fact.

### Main finding

Extracted reasoning matches native CoT and beats no-reasoning baselines on competition math, science, and code generation. Astra is characterized as **token-efficient and directed** — it commits to a correct trajectory earlier and resolves elementary steps internally, externalizing only critical decisions.

### Why it matters

A behavioral lens on frontier-model reasoning without needing internal access. The methodology unlocks empirical studies of "how do closed-source frontier reasoners actually reason" that were previously impossible.

## 10. WhatWorkedBench

**Authors:** Jingjie Ning, Xueqi Li, Yibo Kong, Dongting Li — *(unspecified)*
**Links:** [arXiv:2609.27490](https://arxiv.org/abs/2609.27490) · [HF](https://huggingface.co/papers/2609.27490) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.27490)
**Topics:** `eval`, `agents`

### TL;DR

Evaluates whether AI research agents can **predict** how experimental changes affect outcomes: given a codebase and a budget, the agent runs experiments, then submits a **response surface** — a full table predicting scores for every configuration of component settings. Exhaustive CPU execution provides the ground-truth effect of each component while others are held fixed. 36 tasks × 30 data sources × 8 workflow types × 1248 configurations.

### Key idea

Instead of asking "did the agent get the right final answer," ask "did the agent build the right *causal model* of the experiment." A response surface is a much richer prediction than a single number and exposes whether the agent understands component effects — the core skill for a research assistant.

### Main finding

Introduces the benchmark and the response-surface evaluation format. Baseline comparisons and effect-recovery metrics show current agents produce shallow surrogate models rather than actual causal understanding.

### Why it matters

Puts a concrete number on "experimental understanding" — the piece of the AI-scientist agenda that no other benchmark isolates. Bridges agentic evaluation to the classical DoE literature.

## 11. VHD-Play

**Authors:** Xinjie Shen, Wei Fan, Xudong Guo, Jianhong Tu, Yang Su, Chuqiao Kuang, Yinger Zhang, Dayiheng Liu — *Alibaba / Qwen team*
**Links:** [arXiv:2609.27321](https://arxiv.org/abs/2609.27321) · [HF](https://huggingface.co/papers/2609.27321) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.27321)
**Topics:** `agents`, `RL`, `synthetic-data`

### TL;DR

Existing agentic RL environment generation builds the environment first and defines the reward after; VHD-Play **inverts the pipeline** — sample and *solve* a mathematical model of the target dynamics, then render its decision process as stateful tools. Executable dynamics and the trajectory-scoring reference both come from the same solved model, so reward and environment are aligned by construction.

### Key idea

Solve-then-instantiate: a "setter" LLM samples a mathematical mechanism, closed-form-solves it, and generates the corresponding stateful tools that expose the mechanism to an agent. Trajectory scoring uses the analytic optimum from the same solve step. Produces **3,300 diverse agentic environments at cents each**.

### Main finding

Training Qwen3.6-35B-A3B on three families raises its mean agentic score from **0.204 → 0.815** across a five-family diagnostic. Gains generalize to eight unseen mechanism families and to external benchmarks (E-Commerce Bench, travel planning, function calling). On E-Commerce Bench it beats Qwen3.7-Max.

### Why it matters

Agentic environment supply is a bottleneck for RL training of tool-using agents. VHD-Play makes environment supply near-free while guaranteeing verifiable rewards, closing one of the last practical gaps to end-to-end agentic RL at scale.

## 12. RecCAR

**Authors:** Ohad Rahamim, Dvir Samuel, Idan Schwartz, Gal Chechik — *NVIDIA / Bar-Ilan U.*
**Links:** [arXiv:2609.27901](https://arxiv.org/abs/2609.27901) · [HF](https://huggingface.co/papers/2609.27901) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.27901)
**Topics:** `diffusion`, `video`, `multimodal`

### TL;DR

In joint-modality diffusion transformers (video + motion, video + audio), cross-attention is **asymmetric**: companion modalities attend strongly to video, but the reverse direction (modality → video) is weak. RecCAR defines a **reciprocal correspondence gap** between the two attention distributions and closes it with a KL regularizer that pulls the weaker direction toward the stronger one.

### Key idea

Treat the two cross-attention directions as comparable distributions over video tokens. Use the well-established video-to-modality correspondence as a **fixed reference** and align the weaker modality-to-video correspondence to it via KL. This is loss-only, no architecture change.

### Main finding

On joint video-motion generation, Human Anatomy score improves 0.69 → 0.75. On joint video-audio, audio-video desynchronization drops 0.804 → 0.752. Overall generation quality improves alongside.

### Why it matters

Multi-modal joint diffusion is trending but suffers from unclear cross-modal grounding. RecCAR names the asymmetry and gives a drop-in fix — likely to become a default component of joint-modality DiT training.

## 13. Diffusibility

**Authors:** Chao Feng, Zhiyang Xu, Bowei Chen, Yuanjun Xiong, Xiyao Wang, Jui-Hsien Wang, Richard Zhang, Zhe Lin, Andrew Owens, Yijun Li — *Adobe / University of Michigan*
**Links:** [arXiv:2609.28473](https://arxiv.org/abs/2609.28473) · [HF](https://huggingface.co/papers/2609.28473) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.28473)
**Topics:** `diffusion`, `flow-matching`

### TL;DR

Diffusion models operating in the latent space of pretrained encoders (Representation Autoencoders) suffer when the encoder is finetuned for faithful reconstruction. Reconstruction-finetuning reduces effective dimensionality; standard **velocity-prediction flow matching** then forces the model to fit orthogonal noise outside the signal manifold. Switching to **x₀-prediction** (predict the clean sample) restores focus onto the manifold and consistently improves generation.

### Key idea

Parameterization matters more when latents are high-dimensional but low-effective-dimensional. Velocity prediction implicitly requires modeling the noise geometry; x₀-prediction targets the underlying signal directly, so the model stops wasting capacity on orthogonal noise directions.

### Main finding

Across multiple strong-reconstruction RAE encoders, **x₀-prediction consistently improves text-to-image generation** over velocity-prediction flow matching at equal cost.

### Why it matters

The community has been oscillating between v-prediction, ε-prediction, and x₀-prediction for years. This paper explains geometrically *when* one wins over the other, and identifies a concrete regime (high-dim RAE latents) where x₀ should be the default.

## 14. FLEET

**Authors:** Oleksii Streltsov, Oleksandra Vitko — *(independent)*
**Links:** [arXiv:2609.27657](https://arxiv.org/abs/2609.27657) · [HF](https://huggingface.co/papers/2609.27657) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.27657)
**Topics:** `efficient-inference`, `sampling`, `eval`

### TL;DR

Best-of-N temperature sampling has diminishing returns because the sampler is memoryless — it keeps producing semantically duplicate answers. FLEET tracks each generation as a **sparse trajectory through high-entropy states** and infers per-token utility scores from past trajectories, then adjusts the logits of new generations away from duplicates.

### Key idea

Only tokens where the logit entropy exceeds a threshold are "decision points" — the rest are forced. Represent each generation as the sequence of decision-point tokens (sparse) plus their evaluation. Aggregating across past generations gives per-token utility scores that steer future samples away from repeated trajectories, without any model change.

### Main finding

Matches repeated-sampling accuracy with **3× speedup**. Under a fixed budget, boosts **LiveCodeBench Pass@32 from 59.9% to 66.2%**. Greedy configuration is deterministic; a single calibration pass sets the main hyperparameters.

### Why it matters

Test-time compute scaling relies on drawing many samples. If most samples are near-duplicates, the effective scaling curve is much worse than pass@N suggests. FLEET is a light plug-in that recovers most of the "true" pass@N gain.

## 15. LRH Group

**Authors:** Louie Hong Yao, Yuhao Li, Shengchao Liu — *(unspecified)*
**Links:** [arXiv:2609.27158](https://arxiv.org/abs/2609.27158) · [HF](https://huggingface.co/papers/2609.27158) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.27158)
**Topics:** `interp`

### TL;DR

The **Linear Representation Hypothesis** is not one hypothesis but a family, distinguished by which notion of *representation equivalence* is assumed. The paper formalizes this using **group actions**: pick a representation object, a procedure that produces it, and an asserted property, and account for equivalences imposed by the architecture. Metrics and interventions that look identical can silently correspond to different LRH variants.

### Key idea

Different equivalences preserve different structure. If you probe under an orthogonal-equivalence assumption but intervene under an invertible-linear-equivalence assumption, you're measuring different things — and the resulting empirical claims don't compose. The group-action framing makes this explicit so interpretability results can be compared apples-to-apples.

### Main finding

Position-paper more than a benchmark; provides an audit of common representation quantities (probing accuracy, causal interventions, subspace directions) and re-examines recent interpretability papers under this lens. Argues several results are ambiguous because they don't specify the equivalence class.

### Why it matters

Interpretability is accumulating results at speed but with heterogeneous assumptions. If the field wants to build on itself, it needs a shared language for equivalence — this is a candidate for that language.
