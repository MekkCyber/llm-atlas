## 1. Raven

**Authors:** EverMind AI team — *EverMind AI*
**Links:** [arXiv:2609.33439](https://arxiv.org/abs/2609.33439) · [HF](https://huggingface.co/papers/2609.33439) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.33439)
**Topics:** `agents`

### TL;DR

An open-source multi-agent ecosystem that **auto-constructs specialized agent "harnesses"** (the glue code around a model: prompts, tools, routing, memory) and composes them across domains. Each `(model, harness)` pair becomes a reusable unit; a Host Agent decomposes goals, matches sub-tasks, and persists experience via an `EverOS` + `Skill Forge` so trajectories accumulate as reusable procedures.

### Key idea

Treat the *harness itself* as a first-class object to be synthesized and evolved per domain and per model, rather than hand-engineered once. A theory section states sufficient conditions under which composing many `(model, harness)` units outperforms any single harness at the same compute budget.

### Main finding

Significant gains over the strongest single-agent systems on long-horizon, cross-domain tasks; open-sourced as an "All-Domain Collaboration Network" with 4,990 HF upvotes on launch day — among the highest observed in 2026.

### Why it matters

The current frontier-agent stack is bottlenecked on bespoke harness engineering (ChatGPT Agent, Claude Code, Devin, etc. each ship a different one). If harness synthesis works, the economic unit shifts from "a model" to "a model + its auto-grown procedures" — which changes how open-source labs can compete with closed stacks on complex workflows.

## 2. LongLive-Plug

**Authors:** Shuai Yang, Luozhou Wang, Wei Huang, ZhiFei Chen, Bohan Zhang, Xiao Fu, Qianli Ma, Chen-Hsuan Lin, Weian Mao, Bryan Chu, Song Han, Yukang Chen — *(affiliations not disclosed on HF page)*
**Links:** [arXiv:2609.38154](https://arxiv.org/abs/2609.38154) · [HF](https://huggingface.co/papers/2609.38154) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.38154)
**Topics:** `diffusion`, `distillation`, `efficient-inference`, `multimodal`

### TL;DR

A **once-for-all distillation** framework for video diffusion: three reusable capabilities (single-pass CFG, few-step sampling, long-context error correction for autoregressive generation) are trained as LoRA adapters on a base model and then **plugged, training-free**, into any compatible downstream specialization (world modeling, robotics, editing, multimodal gen).

### Key idea

Decouple *capability distillation* from *task specialization*. Instead of redoing the distillation stage per fine-tuned model, train the capability as a LoRA on the base, and let it ride on any downstream LoRA stack — even when the downstream adds conditioning branches or new output channels. A dedicated CFG LoRA, trained at a fixed guidance scale, still gives inference-time guidance control via its merge weight.

### Main finding

Verified training-free deployment on **54 downstream models** across 3 backbone families and 8 task categories. CFG + few-step LoRAs stack without losing CFG controllability.

### Why it matters

Video-diffusion labs currently pay a distillation tax every time they fine-tune a new specialist (editing, robotics, interactive gen). If one base-level distillation covers an entire backbone family, specialists get few-step inference and long-video correction "for free" — a significant unit-economic shift for open-source video stacks.

## 3. TabFM

**Authors:** Weihao Kong, Erez Louidor Ilan, Shuxin Nie, Taman Narayan, Rajat Sen, Yichen Zhou, Deqing Fu, Samet Oymak, Abhimanyu Das — *Google Research*
**Links:** [arXiv:2609.37959](https://arxiv.org/abs/2609.37959) · [HF](https://huggingface.co/papers/2609.37959) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.37959)
**Topics:** `LLM`, `in-context-learning`, `foundation-model`

### TL;DR

A **400M-parameter foundation model for tabular data** that frames supervised prediction as in-context learning: all rows (train + query) are stuffed into the context and a single forward pass returns calibrated predictions. Trained **only on synthetic tables** sampled from structural causal models — no real-world training data — and transferred zero-shot to real benchmarks.

### Key idea

Push the TabPFN line of work to 400M parameters and extend with (i) multi-view feature expansion + ensembling + post-hoc calibration (TabFM+) and (ii) LLM-guided per-dataset feature engineering (TabFM-Auto), both built on the same frozen weights.

### Main finding

On **TabArena (51 datasets, 38 classification + 13 regression)**, zero-shot TabFM ranks **first among default tabular foundation models and outperforms tuned AutoML pipelines**. Extensions improve further on both tracks.

### Why it matters

Tabular ML has long resisted the "big-model + ICL" recipe that dominates text/vision. A clean win over tuned AutoML without touching the model between tasks reframes tabular ML as another in-context-learning problem — and gives LLM-shaped scaling arguments a new target domain.

## 4. Context Language Models

**Authors:** Rulin Shao, Shannon Zejiang Shen, Junjie Oscar Yin, Yuetai Li, Minheng Wang, Hamish Ivison, Radha Poovendran, Nathan Lambert, Teng Xiao, Mike Lewis, Wen-tau Yih, Luke Zettlemoyer, Pang Wei Koh — *University of Washington / Allen AI / Meta FAIR*
**Links:** [arXiv:2609.37725](https://arxiv.org/abs/2609.37725) · [HF](https://huggingface.co/papers/2609.37725) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.37725)
**Topics:** `LLM`, `agents`, `RL`, `efficient-inference`

### TL;DR

A new class of LLMs that **manage their own context as an editable file**: the model is allowed unrestricted writes to this file, so it learns what to keep, drop, or compress. This generalizes cleanly to multi-agent setups where each agent is a separate file. Online-RL and skill-optimization procedures let CLMs **learn** better context policies, and a co-designed Suffix Cache Reuse scheme cuts server compute at matched quality.

### Key idea

Shift context management from the *harness* ("tool-call to summarize", "evict after N turns") to an *intrinsic model action* — file-level edits. Then wrap the file in a KV-cache-friendly serving layer so the edits don't blow up prefill cost.

### Main finding

Zero-shot CLMs beat SOTA context-management strategies: **+11.4% accuracy with −21.5% FLOPs on BrowseComp-Plus**, **+5% / −59% FLOPs on 12-hour EdgeBench**, and 65% greater improvement at matched compute on a 24-hour multi-repo agent-swarm task. Online RL on Qwen3.5-9B gives +47.6% on BrowseComp-Plus at −12% FLOPs; Suffix Cache Reuse reduces server-side compute by 35% vs. standard SGLang at matched performance.

### Why it matters

Modern agent harnesses are increasingly dominated by context-management heuristics (summaries, retrievals, truncations). If models themselves can learn to maintain context, large swaths of harness complexity collapse into a single learned behavior — and gets cheaper to serve at the same time.

## 5. Grounded Entity Biographies

**Authors:** Hui Ren, Lei Fan, Henry Pao, Han Guo, Zeeshan Zia, Ying Chen, Alexander Schwing, Gang Hua — *UIUC / Microsoft*
**Links:** [arXiv:2609.38155](https://arxiv.org/abs/2609.38155) · [HF](https://huggingface.co/papers/2609.38155) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.38155)
**Topics:** `multimodal`, `agents`, `long-video`

### TL;DR

A **long-video memory framework** that reorganizes memory *by physical entity* instead of by time. Observations of the same physical object across clips are grouped into a retrievable "biography", so a question about one object pulls its history rather than a time slice.

### Key idea

Chronological + text-entity memory confuses visually-identical-looking objects and splits observations of a single object into disjoint events. GEB uses visual grounding to merge observations of the same physical instance into one indexed biography while preserving the per-moment context needed to answer "when did X happen?".

### Main finding

Framework paper; the abstract excerpt the HF page exposes emphasizes the memory structure rather than per-benchmark numbers. (See the paper for retrieval accuracy on long-video QA.)

### Why it matters

Hour-scale and day-scale video assistants (home cams, meeting assistants, long-form reasoning) need entity-persistent memory that current RAG-over-captions can't deliver. GEB is a concrete way to make that memory grounded instead of textual-only.

## 6. EngiWorld

**Authors:** Hongcheng Gao et al. (22-author team) — *(multi-institution)*
**Links:** [arXiv:2609.37686](https://arxiv.org/abs/2609.37686) · [HF](https://huggingface.co/papers/2609.37686) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.37686)
**Topics:** `agents`, `eval`

### TL;DR

A **professional-engineering agent benchmark**: 1,301 expert-curated tasks across CAD, CAE, CAM, BIM, EDA, and 3D visualization, spanning 26 software platforms with both GUI and CLI interfaces. Scoring is **artifact-centric**: a unified domain verifier checks geometric validity, physical feasibility, and rule compliance, and scores quantitative tasks continuously by spec attainment.

### Key idea

Shift evals away from "did the agent click the right thing" to **"is the resulting artifact a valid engineering object?"**. Each domain ships a programmatic verifier; multi-software tasks preserve geometric/physical dependencies across tool handoffs.

### Main finding

The strongest frontier model reaches an **EngiScore of 44.3**, and only **3.6% of multi-software attempts succeed** — a stark capability gap vs. generic computer-use benchmarks.

### Why it matters

Industrial engineering workflows are the next frontier for computer-use agents (CAD → CAM → CAE pipelines are structured, verifiable, high-economic-value, and currently un-automated). EngiWorld gives the field a rigorous, artifact-level evaluation to measure progress against.

## 7. Think Before You Score

**Authors:** Xuehai Bai, Zhenchen Tang, Yang Shi, Dianyi Wang, Tengfei Liu, Wanshun Su, Xuanyu Zhu, Ruohui Wang, Haiwen Diao, Haotian Wang, Xiaoling Gu, Yuanxing Zhang — *(multi-institution)*
**Links:** [arXiv:2609.37372](https://arxiv.org/abs/2609.37372) · [HF](https://huggingface.co/papers/2609.37372) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.37372)
**Topics:** `reward-model`, `diffusion`, `RL`, `multimodal`

### TL;DR

A **Thinking Reward Model (TRM)** for visual generation that first produces a per-case rubric ("what should we judge here?") and then uses that rubric to produce fine-grained pointwise rewards. Pairwise preference optimization is replaced by **Pairwise Dual-Group Relative Policy Optimization (PD-GRPO)** to avoid score polarization while keeping pointwise granularity.

### Key idea

Visual reward models have historically mapped `(prompt, image) → scalar` directly; this paper decomposes it into `(prompt) → rubric` and `(rubric, image) → score`. The explicit rubric step mimics "think before you answer" and gives discrimination between near-tied generations.

### Main finding

TRM + PD-GRPO improves reward discrimination and preserves fine-grained pointwise scoring on the paper's visual-generation reward benchmarks. (Exact numbers in the paper body.)

### Why it matters

Visual reward models drive the entire RLHF-for-image-and-video stack. Explicit case-adaptive rubrics port the "process reward model" ideas from reasoning RL into the visual-generation world — and PD-GRPO is a GRPO variant worth tracking on its own.

## 8. SaveRouter

**Authors:** Guannan Lai, Gelin Bian, Hao-Xuan Ma, Jun-Peng Jiang, Long Chen, Jian-Dong Liu, Zhi-Hao Tan, Han-Jia Ye — *Nanjing University*
**Links:** [arXiv:2609.37402](https://arxiv.org/abs/2609.37402) · [HF](https://huggingface.co/papers/2609.37402) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.37402)
**Topics:** `efficient-inference`, `LLM`, `eval`

### TL;DR

LLM-router training is dominated by **upfront supervision cost**: you have to run every candidate model on historical queries to collect quality labels. SaveRouter sparsifies that: it selectively acquires informative labels and shares capability info across related queries, saturating router quality before all labels are collected.

### Key idea

Routing quality saturates well before dense labelling is complete — so treat supervision acquisition itself as a sparse budget-allocation problem. Share capability signals across similar queries, and keep query-level refinement for fine-grained routing.

### Main finding

Across **4 routing benchmarks**, uses only **33–41%** of the available training feedback at competitive-or-better quality, and reduces **break-even deployment volume by ~1.9×–9.5×** vs. the fastest conventional router. More supervision is not always economic: the minimum-serving-cost supervision level can differ from the fastest-payback one.

### Why it matters

Model-routing is central to the economics of modern LLM serving (route cheap queries to cheap models). Prior routing work ignored its own upfront cost; SaveRouter makes the training-vs-serving tradeoff explicit, so routing becomes a *provably-profitable* layer instead of a hopeful heuristic.

## 9. LongCat-DeepResearch

**Authors:** Meituan LongCat Team (He Zhu, Yue Xu, Wanli Wu, Haolin Ren, et al., 30 authors) — *Meituan*
**Links:** [arXiv:2609.36071](https://arxiv.org/abs/2609.36071) · [HF](https://huggingface.co/papers/2609.36071) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.36071)
**Topics:** `agents`, `reasoning`, `tech-report`

### TL;DR

Meituan's **deep-research system**: an enhanced LongCat base model + a multi-agent workflow that separates global planning from per-section investigation and coordinates revision at section-level. Planners produce a `ResearchSpec`, parallel researchers draft sections against it, and a global reviewer triggers *targeted local revisions* instead of full-report rewrites. The same workflow doubles as a data engine for mid- and post-training.

### Key idea

Rather than a single monolithic chain-of-thought, decompose a report into (1) a plan, (2) parallel investigations, (3) section-local revisions driven by a global reviewer. Reuse the trajectories as supervision for training the base model, closing a self-improving loop.

### Main finding

**55.25 on DeepResearchBench, 51.35 on DeepResearchBench II, 79.83 on ResearchRubrics.** On an in-house benchmark, 76.04 (2nd of 4 systems). Dev-set analyses show that **combining multiple planning perspectives helps**, while *further* planning refinement has mixed effects.

### Why it matters

Deep-research is the first large-scale agentic benchmark that cleanly reflects knowledge-worker productivity. The paper is also notable for publishing both the system *and* its training-data pipeline — a style of release that is becoming a standard for 2026 open agent reports.

## 11. HybridCUA

**Authors:** Tongbo Chen, Junbo Niu, Zhengxi Lu, Niu Lian, Fei Tang, Yuchen Yan, Yike Hong, Yong Du, Yizhou Liu, Bofan Chen, Yongliang Shen — *Zhejiang University / Alibaba*
**Links:** [arXiv:2609.38008](https://arxiv.org/abs/2609.38008) · [HF](https://huggingface.co/papers/2609.38008) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.38008)
**Topics:** `agents`, `RL`, `RLVR`

### TL;DR

Computer-use agents are stuck between pure-GUI (slow, error-prone) and per-app APIs (unscalable). HybridCUA teaches an agent to **mix GUI and shell CLI** on the same task. A data pipeline produces GUI-only, CLI-only, and interleaved trajectories (**HybridCUA-8K**: 5K hybrid traces + 3K RLVR-verifiable tasks). Training = SFT on trajectories + RL with a **CLI-aware reward** that pushes the agent to use the shell *selectively and reliably*.

### Key idea

Treat CLI as a first-class action vocabulary alongside GUI, and shape rewards to encourage CLI only when it is clearly better (short, verifiable commands) rather than everywhere.

### Main finding

**HybridCUA-9B: 53.6% on OSWorld (+14.8 pt over base), +4.0 pt on WindowsAgentArena.** Cross-platform generalization confirmed on both Linux-flavored and Windows benchmarks.

### Why it matters

The GUI-only CUA line (Claude Computer Use, GPT-5 CUA, OSWorld top agents) has been plateauing on long tasks where a single CLI command would replace dozens of clicks. A learned CLI/GUI arbiter is a concrete way to break that plateau, and the CLI-aware RLVR reward is a general recipe other tool-mix RL work can borrow.

## 12. General Asynchronous Agents

**Authors:** George Yakushev, Denis Mazur, Vladimir Bartenev, Vyacheslav Zhdanovskiy, Timofey Byzov, Vladimir Kaurkin, Vadim Pastushenko — *Nebius / Yandex*
**Links:** [arXiv:2609.35427](https://arxiv.org/abs/2609.35427) · [HF](https://huggingface.co/papers/2609.35427) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.35427)
**Topics:** `agents`, `multimodal`

### TL;DR

Existing LLM agent loops are strictly sequential (read → think → reply/tool → repeat), while most real deployments (voice assistants, embodied agents, monitors) receive inputs **while the model is still thinking**. This paper proposes a general asynchronous-LLM framework where users (or agents) declare inference **coroutines** with overlapping memory states, and shows that Qwen 3.x handles asynchronous streaming video, videogames, and monitoring **without task-specific training**.

### Key idea

Instead of specialized architectures per use case (voice stacks, VLAs, async tool-calling APIs), expose a general coroutine abstraction over the model's KV state and let the application interleave inference traces. The paper argues this is the common shape behind "async" use cases that today each ship a bespoke stack.

### Main finding

Zero-shot asynchronous operation of **Qwen 3.x** on streaming video, videogames, and monitoring — no fine-tuning. Framework-first paper, with case-study benchmarks per domain.

### Why it matters

If general asynchronous agents can be run on off-the-shelf LLMs, a lot of today's bespoke "voice agent" and "embodied agent" architectures collapse into harness configurations. This is also a prerequisite for real-time multi-sensor agents at the edge.

## 13. EasyPPO

**Authors:** Xuanyi Zhou, Qiuyang Mang, Huanzhi Mao, Dacheng Li, Wenhao Chai, Mayank Mishra, Yichuan Wang, Karthik Narasimhan, Alvin Cheung, Joseph E. Gonzalez — *Berkeley / IBM*
**Links:** [arXiv:2609.36802](https://arxiv.org/abs/2609.36802) · [HF](https://huggingface.co/papers/2609.36802) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.36802)
**Topics:** `RL`, `PPO`, `reasoning`

### TL;DR

Diagnoses PPO's long-standing LLM instability as **two concrete critic failure modes** and fixes them with (i) actor-only overlong filtering (train the critic on returns from both completed *and* truncated rollouts, filter only the actor), and (ii) **noise-normalized critic regression** that weighs each prompt's critic loss by the inverse std of its sampled returns. Smaller critic mini-batches further confine outlier influence.

### Key idea

The critic — not the actor — is where modern PPO-for-LLMs quietly collapses. Filtering truncated rollouts from the *critic* shifts the policy objective to a conditional-on-completion reward and lets truncation grow unbounded; and finite-batch critic updates get dominated by high-variance prompts. Fixing both yields a drop-in replacement for vanilla PPO.

### Main finding

Across **continuous-reward coding (FrontierCS), binary-reward math (AIME24), and multi-turn search (Search-R1)**, EasyPPO stays stable the full horizon and beats PPO / VAPO / HL-Gauss PPO with best-validation relative gains of **+14.89% / +2.28% / +9.47%**.

### Why it matters

PPO is still the horse at the top of many RL stacks (RLHF, agent RL, RLVR). GRPO got the attention in 2025–2026 partly *because* vanilla PPO's critic was unstable at LLM scale. If EasyPPO's two surgical fixes make PPO stable, PPO regains ground as a default — and the diagnostic lens (critic as the actual culprit) is portable to any actor-critic LLM method.

## 14. SAKI

**Authors:** Miteto Wei, Xiaohan Wang, Zehao Chen, Jiajun Chai, Sichao Liu, Li Wang, Haoyuan Xu, Zhaoyu Hu, Wei Lin, Guojun Yin — *Meituan*
**Links:** [arXiv:2609.36601](https://arxiv.org/abs/2609.36601) · [HF](https://huggingface.co/papers/2609.36601) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.36601)
**Topics:** `RL`, `distillation`, `reasoning`

### TL;DR

On-policy distillation (OPD) trains a student on *its own* generated trajectories. The weakness: at teacher-misaligned prefixes, the usual supervision is unrepresentative. SAKI runs a **KL-constrained teacher-guided rollout under maximal coupling** and routes supervision at the token level: accepted positions keep sampled-token reverse-KL supervision; **correction positions receive direct supervision on the teacher's top token**. Under maximal coupling, the correction rate is exactly `TV(p_t, q_t)`, so one trust-region radius controls both drift and intervention rate.

### Key idea

Make the supervision signal *routed by whether student and teacher agree at a given token*, not by position-in-sequence or static weight. The maximal-coupling identity gives a clean handle to bound how often the teacher intervenes.

### Main finding

Across **7 math-reasoning benchmarks**, SAKI improves the matched teacher-guided baseline on **Mean@8 and Pass@8** for both 1.7B and 0.6B students. An engine-resident speculative verifier preserves the exact-q trajectory distribution while delivering a **4.22× rollout throughput speedup**.

### Why it matters

On-policy distillation is becoming the default for compressing reasoning-RL models (R1-style distillation, Qwen distillations, Kimi long2short). SAKI's token-level routing and the TV-correction identity provide a principled, speed-friendly recipe other OPD pipelines can slot in.

## 15. Periodic Weak Spots

**Authors:** Xingyu Zhu, Pu (Luke) Yi, Ziheng Cheng, Ang Lv, Jing Liu, Lexing Ying, Yiyuan Ma, Xin Dong — *Tsinghua / ByteDance*
**Links:** [arXiv:2609.36322](https://arxiv.org/abs/2609.36322) · [HF](https://huggingface.co/papers/2609.36322) · [AlphaXiv](https://www.alphaxiv.org/abs/2609.36322)
**Topics:** `efficient-inference`, `KV-cache`, `interp`

### TL;DR

Chunked KV-cache compression (compress fixed windows of consecutive tokens into fewer entries) silently introduces **phase-dependent retrieval**: the exact same fact is easy to recover at one source-phase and hard at another, with up to a **40-percentage-point** retrieval-accuracy gap across phases. The authors trace this to attention-component **phase specialization**.

### Key idea

Treat chunked-KV compression as a periodic operator over the sequence. Pretrain transformers under controlled chunking and probe which attention components contribute to retrieval at which phase. The resulting "weak spots" are structural, not statistical — meaning naive long-context benchmarks miss them if their probes don't vary the source phase.

### Main finding

Up to **40 pp retrieval-accuracy variation** across source phases under identical chunked compression. Mechanistic analysis reveals which heads/positions "own" each phase.

### Why it matters

Chunked / sink / recurrent KV compression schemes (StreamingLLM-style, YOCO-style, sliding-window + sink hybrids) are the default for long-context serving in 2026. If phase sensitivity is routinely under-measured, long-context benchmarks are over-estimating serving systems. The paper reframes long-context eval around phase-aware probes.
