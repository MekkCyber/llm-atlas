# ExplorationBench
*Depth — one specific technique, grounded in its source paper(s).*

**TL;DR:** A 141-task benchmark that measures whether LLM agents can *explore* — form hypotheses, run experiments, and iterate — in fully executable "Alien World" sandboxes with rules the model has never seen. Every task has a machine-checkable answer, so exploration and exploitation can be scored exactly and separately.

## What it is

A benchmark suite built around two sandbox families ("Alien Worlds") whose rules are (a) fully executable and (b) unfamiliar — combinations of physics, arithmetic, and symbol-manipulation invariants that don't appear in typical pretraining data. Tasks are grouped into 141 items split across two axes:

- **Exploration tasks** — the agent is given interaction budget with the world and asked to infer a rule or property. The rule is verified exactly by running it against the world's executable oracle.
- **Exploitation tasks** — the agent is *given* a rule and must solve a downstream problem in the world. This isolates whether the failure was in discovering the rule vs. using it.

Every answer is checked by the world's executable engine, so contamination-by-lookup is impossible: the rules were generated for this benchmark and don't live in text elsewhere.

## How it works

Each task instance provides:

- A world description (types of objects, allowed actions, observable feedback).
- A budget of interactions with the world (e.g. 50 experiments).
- A verifiable question (predict this outcome, state this rule in a canonical grammar, name the value of this invariant).

The agent loop is standard tool-use: propose an action → observe outcome → repeat → submit an answer. Scoring is exact match to the oracle's answer, with a separate per-task exploration score based on whether the agent's inferred rule (if it emits one) matches the ground-truth rule.

Metrics reported: overall exact-match accuracy, exploration accuracy, exploitation accuracy, and the **exploration gap** = exploitation − exploration.

## Why it matters

- **Isolates a mode most benchmarks conflate.** MMLU / GPQA / MATH all reward *recall* of known rules; ExplorationBench requires *discovery* of unknown ones. Frontier models are close on exploitation and far behind on exploration.
- **Verifiable but out-of-distribution.** Verifiable-reward benchmarks (RLVR-friendly) usually use math or code, both heavily represented in pretraining. Executable Alien Worlds keep verifiability while eliminating memorisation.
- **Correlates weakly with reasoning benchmarks.** The paper reports that ExplorationBench performance is not predicted by AIME / MATH-500 scores — it's measuring a separable capability.

## Gotchas & tricks

- **Interaction budgets are the main axis.** With unlimited interactions, exploration collapses to brute force; the benchmark's difficulty comes from the budget, so re-runs at different budgets tell a richer story.
- **Rule-generating LLM matters.** The rules are procedurally generated by an auxiliary LLM; ensure the generator LLM is *not* in the eval set, or you get an unfair advantage for one family.
- **Not an agent-tooling benchmark.** ExplorationBench evaluates cognition, not tool orchestration; agents that spend tokens on planner/executor scaffolding without querying the world do poorly.
