# FinanceComplexQA
*Depth — a bilingual benchmark for agentic reasoning over industrial-grade financial documents, with dual-context and cross-layout requirements.*

**TL;DR:** 2,026 expert-level questions over 1,009 layout-preserved financial documents (Chinese + English) spanning nine task categories and eight financial domains (commercial banking, corporate reports, investment banking, stock analysis, customer service, compliance, insurance, fiscal bulletins). Generated by **Finance-LaTeX**, a multi-agent pipeline that plans evidence, drafts LaTeX documents, and runs LLM / MCP / human verification. Scored with an **Agent-as-a-Judge** protocol across accuracy, numerical correctness, evidence coverage, faithfulness, completeness, and cost/latency.

## What it is

An agentic financial-QA benchmark whose signature choice is to require *both* explicit document evidence and implicit domain knowledge for every answer, and to force cross-layout reasoning across prose, tables, charts, and forms preserved as layout rather than flattened text.

Nine task categories: comparison, implicit reasoning, knowledge query, multi-hop reasoning, summarization, planning, numerical comparison, multi-hop judgment, explicit reasoning. Average document length ≈16,500 words per language.

## How it works

**Dataset generation — Finance-LaTeX.** A multi-agent pipeline:

1. **Domain planning.** Choose subdomain (e.g. investment banking) and question intent.
2. **Evidence planning.** Decide which spans, tables, and figures the answer depends on.
3. **Layout drafting.** Emit the document in LaTeX so layout structure survives evaluation.
4. **Verification.** LLM checks, MCP checks (external services for numeric or regulatory grounding), and a human sign-off.

**Two design axes make it hard:**

- **Dual-context reasoning.** Every question needs *explicit* evidence (document spans, tables, chart values) and *implicit* domain knowledge (margin interpretation, debt-pressure heuristics, accounting relations, regulatory background).
- **Cross-layout reasoning.** Answers require joint reading of heterogeneous elements — a tabular value cross-checked against a chart, or a footnote qualifying a prose claim.

**Scoring — Agent-as-a-Judge.** Multi-dimensional: accuracy (ACC), numerical correctness, evidence coverage (Cov), faithfulness (FS), completeness, plus cost/latency measurements. First-class cost annotation is unusual for agent benchmarks and enables cost-aware routing analysis.

## Why it matters

- **Exposes agent-vs-RAG trade-offs at cost.** Claude Code with Sonnet 5 tops the leaderboard (76.01% Chinese, 69.39% English) but at 22–50s / 31–46k tokens per question. Layout-preserving retrieval (PageIndex) beats lightweight RAG (LightRAG) by ~7–10 points but is well below the agents.
- **Documents dominant failure modes.** Numeric drift, evidence omission, layout confusion, over-synthesis, and incomplete coverage recur across systems.
- **Real-domain, real-layout, real-language.** Bilingual industrial documents force the model to handle actual enterprise data, not toy tables.

## Gotchas & tricks

- **Agent-as-a-Judge carries evaluator bias.** Improved over template-based metrics but still not free of it — cross-check with human samples for high-stakes conclusions.
- **Cost is a metric, not overhead.** Reporting only accuracy hides the 3–5× gap in tokens between retrieval and agent configurations.
- **Synthetic data is for development only.** Finance-LaTeX outputs are reserved for dev/train; evaluation splits are human-verified real-derived documents.
- **Chinese and English aren't symmetric.** Model families differ in Chinese performance; splitting the leaderboard by language exposes the gap.
