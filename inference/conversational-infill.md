# Conversational Infill (ConvFill)
*Depth — small/large model collaboration where a local model streams in knowledge from a cloud backend mid-turn.*

**TL;DR:** Voice-agent serving has a fundamental tension: cloud-LLM round-trips break the <200 ms latency budget for natural turn-taking, but on-device models lack depth. Conversational infill splits the work: a small local model commits to the conversational *frame* immediately and infills knowledge **as it streams in** from the powerful backend. Latency is decoupled from backend capability without falling back to a cascade.

## What it is

A serving pattern (and an associated 360M-parameter model) for conversational voice agents. The local model owns the conversational surface — it starts speaking immediately — while the cloud model contributes knowledge and reasoning that the local model integrates as tokens arrive.

## How it works

**Local frame, streamed fill.** The local model emits the next utterance with conversational placeholders for knowledge-heavy spans. When the backend's tokens for those spans arrive, the local model smoothly integrates them without restarting the utterance.

**Training data.** Synthetic multi-domain conversations where the "ground truth" turn is split into a frame and an infill — the local model is trained to predict both the frame and how to incorporate the infill on the fly.

**Backend-agnostic.** A single ConvFill checkpoint works with multiple backend LLMs, since the training data was generated by/for several backends.

## Why it matters

- **Latency budget is hard.** Sub-200 ms is the threshold below which turn-taking feels natural; cloud round-trips routinely exceed this even on warm paths.
- **Beats same-size standalones by 36–42%** on accuracy while staying under 200 ms — i.e. the infill mechanism does work, not just the model.
- **Pattern generalizes.** Any real-time agent (live-caption assistance, in-game NPCs, AR helpers) faces the same constraint and can adopt infill instead of cascade.

## Gotchas & tricks

- "Frame" design (where to put the placeholders) is policy: too many placeholders and the local model is just a sentence template; too few and the local model has to fake knowledge it doesn't have. The paper's synthetic data quietly encodes a reasonable default.
- Backend latency spikes still bite — when the infill is *very* late, the local model has to bail to a graceful fallback. Treat infill as best-effort, not guaranteed.
- Distinct from speculative decoding: speculative decoding has the small model speculate *for* the large model; infill has the small model commit and let the large model contribute.
