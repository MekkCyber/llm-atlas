# Streaming Video LLMs
*Depth — multimodal LLMs that consume live video and must respond without re-watching.*

**TL;DR:** A **streaming video LLM** processes a video frame-by-frame as it arrives, maintains a bounded-size memory, and answers questions when they come in — unlike offline video QA, where the model sees the whole clip up front. The central tension is between *perception now* (keep the frame processor fast and small) and *memory for later* (record enough to answer unseen future questions). **OneStreamer** (Zeng et al., 2026) addresses this by writing a *query-independent evidence memory* — hierarchical captions + rolling event summaries — using the same proactive-generation head that produces task responses, trained with a 1M-sample pipeline and a learned wait/speak state transition.

## What it is

Offline video QA: full clip in, question in, answer out — all at inference time. Streaming video QA: frames arrive continuously, questions arrive at arbitrary times, the model must respond with low latency and remember what mattered before the question was asked.

The design axes are:

- **Memory substrate** — raw frames, pooled embeddings, generated captions, event summaries.
- **Memory writer** — query-conditioned (write when a question demands it) vs query-independent (write continuously, before relevance is known).
- **Response policy** — wait-until-question vs proactive speaking when evidence suffices.

OneStreamer is query-independent (writes evidence as it perceives) and proactive (same head emits memory updates and task responses, with learned state transitions).

## How it works

Two components bolted onto a 4B VLM backbone:

### Proactive Hierarchical Caption Memory (PHCM)

- **Short captions** — one per video chunk, time-grounded.
- **Event summaries** — rolling summaries that aggregate recent short captions into higher-level events.

Both are generated by the same model that produces task responses; the memory is written in natural language, so it is readable, debuggable, and directly consumable by the model's own context.

### Proactive State Transition Learning (PSTL)

A streaming VLM naturally learns to *always wait* (output the "waiting" token at every step is a locally safe policy that minimizes mistakes). PSTL rebalances the training distribution of wait vs speak tokens so the model actually transitions to active response when evidence warrants it. Prevents mode collapse into perpetual silence — a known failure mode of naive streaming training.

### Data

OneStreamer-1M: >1M interaction records across streaming video tasks, synthesized through a dedicated pipeline. The 4B OneStreamer reaches best scores on 8 streaming-video understanding benchmarks.

## Why it matters

- **Natural substrate for computer-use and robot agents** that watch a screen or camera; the perception + evidence memory + response triad is the architecture these agents need.
- **Caption-based memory is scalable and inspectable.** A memory of generated captions scales with task complexity (not raw video length), and a human (or a downstream LLM) can read it.
- **Separates evidence recording from task response.** This structural split rhymes with belief-state agents (see [belief-states](../agents/belief-states.md)) — the two threads will likely converge.

## Gotchas & tricks

- **Caption quality dominates memory quality.** A fast-but-weak captioner leaves the model with no handle on the past; a strong captioner slows real-time perception. Hierarchical structure (short + rolling event) is the paper's compromise.
- **Wait/speak balance is fragile.** The PSTL weighting is the key hyperparameter; too much "speak" ⇒ noisy proactive outputs; too much "wait" ⇒ model never responds.
- **Not a long-context fix.** The memory is bounded by what the captioner compresses the stream to; truly long-horizon tasks may still need external retrieval over past captions.
- **Latency floor.** Captioning per chunk sets the inherent frame-rate ceiling for perception; a smaller captioner is a direct speed-up.
- **Not trained for closed-world tool use.** Streaming VLMs are perception-first; wiring them to tool-calling agents is an open integration problem.
