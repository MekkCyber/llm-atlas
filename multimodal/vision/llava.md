# LLaVA

*Depth — the simplest production VLM recipe: vision encoder → projector → LLM, trained via visual instruction tuning.*

**TL;DR:** LLaVA-1 (Liu 2023): pretrained CLIP ViT-L/14 → **single linear projection** → LLM (Vicuna / LLaMA). Two stages: (1) align the projector with vision features by training only it on caption data; (2) instruction-tune projector + LLM together on **158K GPT-4-generated visual instructions** (conversations, detailed descriptions, complex reasoning). LLaVA-1.5 (Liu 2023): swap linear → 2-layer MLP; use CLIP ViT-L/14@336px; expand data mix. **Single 8×A100 machine, <1 day of training, competitive with 30B+ models.** The recipe that made VLMs accessible — the entire open-VLM ecosystem is "LLaVA plus improvements."

## What it is

Liu et al., *Visual Instruction Tuning* (LLaVA-1), NeurIPS 2023, arXiv 2304.08485.
Liu et al., *Improved Baselines with Visual Instruction Tuning* (LLaVA-1.5), arXiv 2310.03744.

The minimum-complexity VLM: no cross-attention, no Q-Former, no gated adapters. Just a projector between a frozen vision encoder and an LLM, with **instruction-tuning data generated by GPT-4**.

Three design choices distinguish LLaVA:
1. **Vision features become LLM tokens.** The projector output is treated as a sequence of "visual tokens" slotted into the LLM's normal token stream. No architectural changes to the LLM.
2. **The LLM unfreezes during fine-tuning.** Unlike Flamingo (frozen LLM), LLaVA fine-tunes the LLM on instruction data. Higher visual-reasoning ceiling; some risk of forgetting.
3. **GPT-4 generates the instruction data.** No human-labeled instructions; instead, prompt text-only GPT-4 with image captions + bounding boxes (no images) to generate Q&A pairs, detailed descriptions, and reasoning chains. Cheap, scalable.

## How it works

### Architecture

```
Image (224×224 or 336×336)
    ↓
CLIP ViT-L/14 [FROZEN in stage 1; in 1.5, also frozen in stage 2]
    ↓
Grid features Z_v ∈ ℝ^(N × d_vit)   (e.g., 256 × 1024 for L/14 @ 336)
    ↓
[Linear projection W (LLaVA-1) or 2-layer MLP (LLaVA-1.5)]
    ↓
H_v ∈ ℝ^(N × d_llm)   ("visual tokens")
    ↓
Insert into LLM token stream:
    [text_before_image_tokens, H_v, text_after_image_tokens]
    ↓
LLM (Vicuna 7B/13B in 1.0; Vicuna v1.5 7B/13B in 1.5) → generation
```

### Token layout (Sec. 4.2)

```
[X_q (user question), X_v (visual tokens), X_a (assistant answer)]
```

or (training-time augmentation, 50/50):

```
[X_v (visual tokens), X_q (user question), X_a (assistant answer)]
```

— randomly swap the image/question order so the model doesn't learn a positional dependency.

### Loss (LLaVA-1 Eq. 4)

Autoregressive next-token prediction, loss computed **only over assistant-answer tokens** (not over prompt or visual tokens):

```
p(X_a | X_v, X_instruct) = ∏_{i=1..L} p_θ(x_i | X_v, X_instruct_<i, X_a_<i)
```

### Two-stage training

#### Stage 1: Feature alignment

- **Only projector W (or MLP) is trainable.** ViT and LLM both frozen.
- **Data**: 595K subset of CC3M, filtered for image-text alignment quality.
- **Objective**: next-token on simple caption tasks — teach the projector to map vision features to LLM-compatible representations.
- **Training**: 1 epoch, LR 2e-3, batch 128, ~4 hours on 8×A100 for 13B.

Why stage 1: the projector starts untrained (random init). Without this stage, stage 2's joint training would be dominated by projector noise, damaging the LLM.

#### Stage 2: Visual instruction tuning

- **Trainable**: projector AND LLM. Vision encoder stays frozen.
- **Data**: LLaVA-Instruct-158K (see below).
- **Training**: 3 epochs, LR 2e-5, batch 32, ~10 hours on 8×A100 for 13B.

### LLaVA-Instruct-158K (the data)

Generated with text-only GPT-4 (no vision input to GPT-4), prompted with:
- **COCO image captions** (describe what's in the image).
- **COCO bounding-box annotations** (what's where).

GPT-4 generates three kinds of data per image:

- **Conversation (58K multi-turn Q&A)**: multi-turn back-and-forth about the image's content.
- **Detailed description (23K)**: long descriptions of the image.
- **Complex reasoning (77K)**: Q&A requiring multi-step reasoning about the image contents.

Total: **158K image-instruction samples** (sometimes called "150K" in the early repo name).

Key insight: **GPT-4 never sees the image** — it only sees the caption + bounding boxes. But the generated questions and answers are still aligned with the image because they're grounded in the caption. A clever use of text-only teachers for multimodal student models.

### LLaVA-1.5 changes (Sec. 3)

Three targeted improvements:

1. **Projector: linear → 2-layer MLP with GELU.** Small capacity bump, minor param cost.
2. **Vision encoder: CLIP ViT-L/14 → CLIP ViT-L/14 @ 336×336.** Higher resolution, finer spatial detail. Sequence length grows ~2.3×.
3. **Expanded data mixture (665K samples)**: LLaVA-Instruct-158K + ShareGPT text-only + academic VQA datasets (VQAv2, GQA, OKVQA, A-OKVQA, OCRVQA, TextCaps) + region-level (RefCOCO, Visual Genome).

**LLaVA-1.5-HD**: tiles higher-res images into 336×336 crops, concatenates the grid outputs. Lets the model handle arbitrary-resolution images.

### Response-formatting trick

LLaVA-1.5 appends a prompt hint to short-form VQA prompts:

> *"Answer the question using a single word or phrase."*

This keeps the model from rambling on benchmarks that expect one-word answers (VQAv2, GQA) while allowing long-form responses when the user asks for them. A small but important robustness fix.

### Results

LLaVA-1.5 claims **state of the art on 11 benchmarks using only public data**, matching or beating 30B-class VLMs despite being 13B. MM-Vet, MME, ScienceQA, VQAv2, GQA — all at frontier-competitive levels.

## Why it matters

- **Simplest VLM recipe that works.** If you're building a VLM, LLaVA's two-stage pattern is the default starting point.
- **Trainable on one node.** 8×A100 = ~$2-5K in cloud costs. Unlike Flamingo-80B or BLIP-2 (many GPUs, frozen LLM), LLaVA runs on an off-the-shelf workstation.
- **Teacher-free instruction data.** GPT-4 (or Claude, or any strong text LLM) can generate visual instructions at scale given captions. Removes the human-labeling bottleneck.
- **Open ecosystem foundation.** LLaVA, LLaVA-Med, LLaVA-Interactive, Video-LLaVA, LLaVA-Plus — a huge open-source family built on the original recipe.
- **Established the "direct projection, full fine-tune" pattern.** Many 2024+ VLMs (InternVL, MiniGPT-4, Bunny, Yi-VL) follow the same template.

## Gotchas & tricks

- **Vision-encoder resolution matters.** 224 vs 336 makes a real difference on VQA. 336 is the LLaVA-1.5 default.
- **2-layer MLP projector beats linear.** LLaVA-1's single linear projector was a capacity bottleneck; 1.5's MLP fixes it at negligible cost.
- **Stage 1 is mandatory.** Skipping stage 1 and going straight to joint training degrades results substantially — the projector is too noisy.
- **Frozen ViT + trainable LLM.** Opposite of Flamingo. Trade-off: vision features are limited by the pretrained CLIP encoder; LLM can re-learn to interpret them. Works well in practice.
- **Response-formatting hint is subtle.** Without it, short-form benchmarks look worse than the model actually is. Always include the format hint for short-answer tasks.
- **The data is the hard part.** The architecture is 30 lines of PyTorch; the data curation (LLaVA-Instruct-158K + the 1.5 expansion) is months of iteration.
- **Catastrophic forgetting is possible.** Full LLM fine-tune risks damaging text-only capability. LLaVA mitigates by mixing text-only ShareGPT in stage 2.
- **Multi-image handling requires care.** LLaVA concatenates visual tokens from multiple images; there's no intra-image-isolation mask like Flamingo's. Works adequately but not exceptionally.
- **Position embeddings interact.** Visual tokens get positions based on their slot in the LLM's token stream — they don't reset. Fine for most models; can interact weirdly with RoPE at very long context.
- **LLaVA-1.5-HD's tiling is simple but effective.** 336×336 tiles + a global resized view → concatenated grids. Handles 1344×1344 inputs as effectively a 4×4 grid of 336 crops.
- **Training throughput dominated by the LLM.** ViT forward is relatively cheap; the LLM's training steps dominate compute. Batch size and sequence length are the main cost knobs.
- **Data contamination is hard to avoid.** Benchmark images (e.g., VQAv2 test set) overlap with CC3M. Reported numbers likely reflect some memorization.
