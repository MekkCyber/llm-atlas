# Visual Token Compression (Region-Level Policies)
*Depth — one specific technique, grounded in its source paper(s).*

**TL;DR:** Multimodal LLM inference is dominated by the visual token count — a single image can produce hundreds to thousands of tokens once the vision encoder projects it into the language backbone. **Region-level policy optimization** learns a policy that treats image regions as actions and prunes them adaptively, hitting the baseline model's accuracy with roughly **75% fewer visual tokens**. Key insight: **localization tolerates 3–4× stronger token compression than recognition**, so uniform pruning wastes the localization budget.

## What it is

MLLMs feed visual tokens (patch embeddings, sometimes 576 or 1024 per image, more per video frame) into the language backbone. Naïve strategies cap the token budget globally — top-K by attention score, cluster-and-merge, resizing — which sacrifices accuracy uniformly across tasks.

Region-level policies instead formulate token selection as a **reinforcement learning problem** over image regions:

- **Action space** — a set of candidate regions (grid patches, superpixels, or hierarchical proposals).
- **Reward** — a score from a frozen MLLM: does the selected subset preserve task performance?
- **Policy** — a small RL-trained module that proposes which regions to keep or drop.

The reward provides supervision without requiring per-image region annotations — the frozen MLLM is a self-generated critic.

## How it works

**Vision-RL2** (representative recipe):

1. **Region proposals.** Given an image, produce candidate regions at multiple scales.
2. **Subtractive rollouts.** Start from the full token set and iteratively drop regions; the reward for a rollout is the frozen MLLM's answer probability on the target task.
3. **Additive rollouts.** Start from the empty set and grow toward a budget; same reward.
4. **Policy update.** GRPO-style optimization mixes subtractive and additive objectives — subtractive teaches which regions are safe to remove, additive teaches which are load-bearing.
5. **Deployment.** At inference, the policy runs once per image, selecting a compressed region subset before the MLLM ingests it.

Because the reward is generated by the *same* MLLM being served, no external labeler or annotation set is needed — the compression is self-supervised.

## Why it matters

- **Input-side compression** complements KV-cache tricks (paged attention, quantized KV): both reduce inference cost, but at different points in the pipeline.
- **Task-adaptive.** Localization tasks retain more low-level detail; recognition tasks accept much heavier pruning. Global thresholds cannot express that gap.
- Reported numbers: **~75% fewer visual tokens** at baseline accuracy across multiple benchmarks and MLLM backbones — a straight compute/cost win.

## Gotchas & tricks

- **Frozen-MLLM reward is biased toward the MLLM's own strengths.** If the policy overfits to it, transfer to different downstream tasks weakens. Regularize with entropy or diversity terms.
- **Subtractive alone under-explores.** The additive objective prevents collapse to trivial small subsets.
- Compression at input is orthogonal to KV-cache compression at inference — you can stack both, but their combined savings are not additive because KV cost scales with tokens the policy already dropped.
