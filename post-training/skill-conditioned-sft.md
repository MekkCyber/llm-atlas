# Skill-Conditioned SFT
*Depth — use the same model as a better teacher by conditioning its rollouts on natural-language "skills", then SFT the student on the resulting traces.*

**TL;DR:** A post-training recipe that boosts a model without a stronger teacher. Prompt the *same* model with explicit skills (e.g. "plan before acting", "verify output"), collect its improved rollouts, then SFT a student copy on those traces with the skills still in the input. An outer agent (AutoMaster) proposes new skills and curates the training data. Beats vanilla SFT on successful unguided rollouts by 1.42–8.99 points on terminal/search/SWE agent tasks.

## What it is

"Skill-FT" — fine-tuning on *skill-conditioned* teacher rollouts generated by the student's own base model. The outer system **AutoMaster** closes the loop by proposing skills, running rollouts, scoring their lift, and curating the SFT set.

Three parts:

1. **Skills.** Natural-language micro-strategies ("plan before acting", "check output before returning", "retry on tool-call failure"). Each skill is a prompt fragment.
2. **Teacher-mode rollouts.** Prompt the base model *with* a skill. The skill primes it to act more carefully; its rollouts outperform the un-primed student on the same task.
3. **Student SFT.** Fine-tune a student copy on (prompt + skill + teacher trace). Skills stay in the input at training time; at evaluation they are removed.

The outer AutoMaster loop treats the skill library as search space, proposing new skills and keeping the ones that produce the biggest lift.

## How it works

```
AutoMaster loop:
  1. Propose skill s via LLM
  2. For a sample of prompts q, roll out o_s = base(q | s) and o_0 = base(q)
  3. Score o_s vs o_0 with task-specific evaluator
  4. If skill helps, keep it; add (q, s, o_s) to SFT set
  5. Refine the skill set: drop dominated skills, merge overlapping ones

Skill-FT:
  student = SFT(student, dataset = { (q, s, o_s) })
  evaluate student on q (no skill at inference)
```

Key empirical finding: **keeping the skill text in the training input helps even though it is absent at evaluation**. The model internalizes "what the skill was asking for" and acts on it unconditionally at inference.

## Why it matters

- **No stronger teacher required.** Many post-training recipes bottom out on "we distill from a stronger model." Skill-FT shows the same model can be its own teacher if given the right prompts — a cheaper, more reproducible pipeline.
- **Explicit search over post-training objectives.** Instead of hoping SFT on raw success traces teaches the right thing, AutoMaster explicitly searches over *what to teach*. Task success alone doesn't say which behaviors to reinforce; skills name them.
- **Composes with RL.** The curated dataset feeds the SFT stage upstream of RL. Nothing in the recipe conflicts with GRPO/PPO downstream.
- **Agent-task specific gains.** The reported gains are measured on terminal, search, and SWE-style tasks — exactly where "plan then act" dominates.

## Gotchas & tricks

- **Skill quality bounds the gain.** A bad skill library produces no lift; the outer AutoMaster loop is the critical component, not Skill-FT alone.
- **Generalization risk.** Skills are task-specific; a library tuned for SWE agents will not transfer to math reasoning without refresh.
- **Dependence on evaluator.** The AutoMaster proposal/accept loop needs a reliable scorer. On unverifiable tasks this is the usual LLM-judge weak point.
- **"Keep skills in training input" is a surprise.** The intuition is that explicit conditioning teaches the model to represent the skill as part of its policy; removing skills at training might work but is reported to be worse.
- **Model-size sensitivity.** Validated at 4B and 9B students. Behavior at larger scale where the base is already strong is open.
