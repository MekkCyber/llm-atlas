# Rainbow Teaming

*Depth — MAP-Elites-based open-ended generation of diverse adversarial prompts.*

**TL;DR:** An algorithm for **automatically generating diverse adversarial prompts** to attack LLMs, using **Quality-Diversity** (MAP-Elites) optimization. Maintains an archive with **feature cells** defined by attack style × risk category; iteratively mutates existing archive entries (via an LLM) and keeps the highest-fitness prompt per cell. Reports **>90% attack success rate** across Llama 2 and Llama 3. Used by Llama 3 to generate **synthetic adversarial training data** for safety tuning — adversarial prompts + responses fine-tune the target model to be robust. Samvelyan et al. (Meta, 2024).

## What it is

Samvelyan et al., *Rainbow Teaming: Open-Ended Generation of Diverse Adversarial Prompts*, arXiv 2402.16822, 2024.

Instead of hand-crafting jailbreaks or running gradient-based attacks (GCG, Zou 2023), use **evolutionary search** to discover adversarial prompts automatically. Specifically: Quality-Diversity (QD) optimization via MAP-Elites (Mouret & Clune 2015).

Goal: a **diverse set** of successful attacks — not just the single best attack, but one per "attack style × risk category" combination. Diversity prevents the classical "defend against one attack, expose 10 others" failure mode.

---

## How it works

### Quality-Diversity via MAP-Elites

MAP-Elites is an evolutionary algorithm that maintains an **archive** (grid) of the fittest solution in each cell defined by a **feature descriptor**. For each candidate solution:

1. Compute features → which cell.
2. Compute fitness.
3. If the cell is empty OR the new solution's fitness > the cell's current occupant: **replace**.

Over iterations, each cell converges to its best solution. The result: a **diverse set of high-fitness solutions** spanning the feature space.

### Rainbow Teaming's three components (Sec. 3)

1. **Feature descriptor** — defines the diversity axes:
   - Example axes: **Risk Category** (violence, CSE, self-harm, ...) × **Attack Style** (roleplay, obfuscation, hypothetical, ...).
   - Example: Llama 2-chat 7B archive in Figure 1 uses Risk × Style axes.
2. **Mutation operator** — an LLM is prompted to take an existing archive prompt and **mutate** it into a new adversarial prompt. The LLM is told to preserve the attack's essence but change wording/style.
3. **Preference/fitness judge** — a judge LLM (e.g., Llama Guard, GPT-4, another LLM) **ranks two responses** to decide which is "more unsafe." Alternatively, uses Llama Guard's direct safety scores.

### The iteration

```
initialize archive with seed prompts (one per cell)

for iteration in 1..N:
    parent = sample a random (non-empty) archive cell
    candidate = mutate(parent)                       # LLM mutation
    target_response = run_target_LLM(candidate)
    if judge(target_response) = UNSAFE:
        cell = feature_descriptor(candidate)
        fitness = judge_score(target_response)
        if archive[cell].fitness < fitness OR archive[cell] empty:
            archive[cell] = candidate

# After N iterations, archive contains one best adversarial prompt per cell
```

### Diversity is the point

A single highly-successful adversarial prompt gives limited information — defending against it only shuts down that exact attack. A **diverse set** across risk × style cells reveals the attack surface. Training a target model to be robust across all cells generalizes better than defending against one.

### Results

**Attack-success rate >90%** across Llama 2 and Llama 3 targets (Abstract).

Attacks generated by Rainbow Teaming are also reported as **highly transferable across models** — a Rainbow-discovered attack on Llama 2 often works on Llama 3, Claude, GPT-4. This is both useful (transfer is efficient for red-teaming) and concerning (publishing the archive enables attacks).

### The synthetic-data use (Llama 3)

The Llama 3 paper cites Rainbow Teaming as one source of **synthetic adversarial data for safety training** (Sec. 5.4.3, "Safety Fine-Tuning"):

- Generate adversarial prompts via Rainbow Teaming.
- Produce safe refusal responses (via hand-crafted or Llama 3).
- Add to safety-SFT mix.
- Fine-tune the target model.

Result: the model becomes more robust to the kinds of attacks Rainbow discovered, without sacrificing helpfulness.

## Why it matters

- **Automated red-teaming at scale.** Human-crafted jailbreaks are expensive; Rainbow generates thousands automatically.
- **Diversity by construction.** MAP-Elites' cell-based archive forces the algorithm to find attacks across the entire feature space, not just in one mode.
- **Transferable attacks.** Attacks generalize across LLM families, making Rainbow useful for evaluating new models quickly.
- **Closes a training loop.** Rainbow → synthetic data → fine-tune → re-run Rainbow on the updated model. Iterative safety improvement.
- **Applies beyond safety.** The paper also shows QA robustness and cybersecurity applications. The method is generic.

## Gotchas & tricks

- **Feature descriptor choice is load-bearing.** Pick axes that span attack surface; axes that are correlated (e.g., "length" × "token count") waste cell budget.
- **Mutator LLM quality matters.** A weak mutator produces weak candidates. Strong LLMs (GPT-4, Claude) make stronger attack generators.
- **Judge reliability is a ceiling.** If the judge can't detect harmful responses reliably, fitness scores are noisy and the archive fills with false-positives.
- **Transfer ≠ perfect.** Attacks generated against model A and re-run on model B succeed ~60-80% of the time, not 100%. Some model-specific defenses.
- **Publishing the archive enables attacks.** There's a tension between advancing the science and enabling adversaries. Meta publishes the methodology but not specific archives.
- **The archive itself can be used to train a stronger detector.** Prompt Guard's training data includes Rainbow-generated prompts as negatives.
- **Compute cost is nontrivial.** Each iteration: one mutator forward, one target forward, one judge forward. Thousands of iterations → millions of LLM calls. Cheap vs human red-teaming; expensive vs gradient-free attacks.
- **Differentiates from GCG/Zou-style gradient attacks.** GCG produces a single highly-adversarial string; Rainbow produces diverse natural-language attacks. Complementary.
- **Applies to any LLM output.** Not just text safety — Rainbow could produce diverse adversarial inputs for vision, code, math. Paper focuses on text safety.
